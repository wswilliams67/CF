    Nimbus ships six ready-to-use page templates that establish the correct header, footer, navigation, and content regions for each supported layout type. Starting from a template rather than from scratch ensures that the structural conventions — sticky headers, sidenav wiring, skip-navigation links, theme tokens, and mobile breakpoints — are all set up correctly from the first line of markup.

    Templates are divided into two sets: Generic templates for internal applications and portals, and Support templates for customer-facing support products. Within each set, three layout variants are available: a standard site page with top navigation, an application page with a full-width main content area, and an application page with a collapsible sidenav. The template files are contained in the Nimbus 9.x distribution package.

    Generic Templates

    Site Page Templates

    The Site Page template is designed for pages where the main navigation is at the top, in the header. It is coded to be responsive down to a mobile phone. The layout is vertical and linear. We suggest dividing content in to sections and segementing them to allow for easier management.

    View the Site Page Template

    Application Page Template

    The Application Page template is designed for applications where the full screen width is utilitzed. It is coded to be responsive down to a large format phone. The layout is a traditional three pane design. A header, footer, and main content area. We recommend this template for applications with little to no informationn architecture where the navigation can be contained within the page content.

    View the Application Page Template

    Application with SideNav Page Template

    The Application SideNav Page template is designed for applications where the collapsible main navigation is on the side. It is coded to be responsive down to a 10" tablet. The layout is a traditional four pane design. A header, footer, side navigation, and main content area. We suggest that a simple information architecture be used to keep the side navigation simple and performance snappy. The side navigation must be duplicated on each page of the application unless the developers adjust their code to use a single frame page and target all content to the main content area. This template is recommended for applications with complex navigation where the primary users will be utilizing a desktop or large format tablet.

    API Documentation

    Introduction

    Nimbus templates are pre-built HTML starting points that wire up the correct structural skeleton — sticky header, footer, skip-navigation link, theme token imports, and (where applicable) sidenav scaffolding — so teams can focus on feature content rather than layout boilerplate. Each template targets a specific layout pattern and product family. Select the template that matches the target layout, copy it into your project, and replace the placeholder content.

    CSS classes

    Class Applied to Description
    cnds-product-casefusion <body> Applies the CaseFusion product color theme.
    cnds-product-hyperlize <body> Applies the Hyperlize product color theme.
    cnds-product-expireon <body> Applies the Expireon product color theme.
    cf-main-app <main> Application main content area. Offsets for the sticky header and optional sidenav.
    cf-footer-app Footer wrapper <div> Footer container styled for application-layout pages.
    sticky-top Header wrapper <div> Keeps the header fixed at the top of the viewport on scroll.
    visually-hidden-focusable Skip-navigation <a> Renders the skip link visually hidden until focused, satisfying WCAG 2.4.1.

    Accessibility

    Every Nimbus template includes a skip-navigation link targeting #main-content that satisfies WCAG 2.4.1 (Bypass Blocks). The skip link uses class="visually-hidden-focusable", which renders it off-screen until a keyboard user tabs into it, at which point it becomes visible and allows focus to jump past repetitive navigation. Ensure that the id="main-content" attribute remains on the <main> element and is not removed or renamed.
