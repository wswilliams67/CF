    v1 Toasts
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The CNDS Toast component delivers lightweight, non-disruptive notifications that appear briefly in the interface and disappear automatically. Toasts are ideal for confirming actions, surfacing status updates, and communicating errors without interrupting the user's workflow.

    CNDS Toasts support nine semantic color variants — primary, secondary, success, danger, warning, caution, info, light, and dark — applied via the data-cnds-color attribute. Each variant uses a distinct background, border, and text color drawn from the CNDS design token system, with all combinations verified WCAG AA compliant.

    Note: Read the API Documentation to find all available options and advanced customization

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Colors

    Header icon size. Toast header icons are cnds-icon-xl (24px), matching Nimbus/Icon/xl in the Figma Nimbus/Toast component: a 24×24 box around an 18×18 glyph. Pair it with lh-1 so the line box is 24px too.

    mdi-18px is not the equivalent, even though the Figma glyph measures 18. MDI sizes the em box, and the glyph draws inside it with padding — mdi-18px yields 14×14 of ink, while cnds-icon-xl yields exactly the 18×18 the design draws. Match the frame, not the vector.
    Caution is not warning. They are separate color families and are routinely swapped by mistake — warning is the yellow ramp (#fff3cc / #f3bc00), caution is the orange one (#ffd7ad / #ff9933). Use warning when something is wrong; use caution when something is outstanding — an action recorded but not yet executed, a record under a hold, a step that succeeded but left work behind it. Neither is danger, which is reserved for an operation that failed.

    Apply a semantic color variant by adding data-cnds-color="variant" to the toast element. The nine available values — primary, secondary, success, danger, warning, caution, info, light, and dark — each set a distinct background, border color, and text color using CNDS design tokens. The header and body share a unified background with no separator border.

    Placement

    Control where toasts appear on screen using the data-cnds-position attribute or the update() method. Six positions are supported: top-left, top-center, top-right, bottom-left, bottom-center, and bottom-right. The default is top-right with a 24px gap from the screen edge.

    Container

    By default, toasts are appended to the <body> and positioned relative to the viewport. To scope a toast inside a specific element instead, set data-cnds-container to a CSS selector targeting the parent element, and add position: relative to that element (via the .parent-toast-relative utility class). Use data-cnds-container with the update() method to reassign the container dynamically.

    Stacking

    When data-cnds-stacking="true", each new toast is queued below the previous one at the configured position, so multiple notifications remain visible simultaneously. Set data-cnds-stacking="false" to replace the current toast with the new one instead of stacking. Stacking state can also be changed at runtime via the update() method.

    HTML
                                                
<button type="button" class="btn btn-primary me-3" id="stacking-trigger">Show toast notification</button>
    JAVASCRIPT
                                                
let stackCount = 0;

document.getElementById('stacking-trigger').addEventListener('click', () => {
  stackCount++;

  const toast = document.createElement('div');
  toast.innerHTML = `
    <div class="toast-header">
      <strong class="me-auto lh-1">${stackCount}</strong>
      <small>11 mins ago</small>
      <button type="button" class="btn-close" data-cnds-dismiss="toast" aria-label="Close"></button>
    </div>
    <div class="toast-body">
      Stacking element
    </div>
  `;

  toast.classList.add('toast', 'fade');
  toast.setAttribute('role', 'status');
  toast.setAttribute('aria-live', 'polite');
  toast.setAttribute('aria-atomic', 'true');

  const toastInstance = new Nimbus.Toast(toast, {
    appendToBody: true,
    stacking: true,
    width: '450px',
    position: 'top-right',
    autohide: true,
    delay: 5000,
    color: 'dark',
  });

  toastInstance.show();
});

    API Documentation

    Introduction

    The CNDS Toast component requires JavaScript initialisation. Toasts can be initialised automatically via the data-cnds-toast-init attribute, or programmatically using new Nimbus.Toast(element, options). Both paths support the full option set including positioning, auto-hide, stacking, and color variants.

    When appendToBody is true or data-cnds-position is set on the element, the toast is positioned fixed to the viewport at the configured position with the configured offset. Multiple toasts at the same position stack automatically when stacking is enabled. Container-scoped toasts are positioned absolutely inside the target element, which must have position: relative (use the .parent-toast-relative utility class).

    Usage

    Via data attributes

    Add data-cnds-toast-init to any .toast element to initialise it automatically on page load. All options can be set via data-cnds-* attributes — no additional JavaScript required.

    HTML
    <div class="toast fade" data-cnds-toast-init
     role="status" aria-live="polite" aria-atomic="true"
     data-cnds-autohide="true" data-cnds-delay="5000"
     data-cnds-position="top-right" data-cnds-append-to-body="true"
     data-cnds-stacking="true" data-cnds-color="info">
    <div class="toast-header">
        <strong class="me-auto lh-1">Nimbus</strong>
        <small>just now</small>
        <button type="button" class="btn-close" data-cnds-dismiss="toast" aria-label="Close"></button>
    </div>
    <div class="toast-body">Example toast</div>
</div>
    Via JavaScript

    Initialise a toast programmatically and call show() to display it. Useful for dynamically created toasts or when options must be set at runtime.

    JAVASCRIPT
    const toastEl = document.getElementById('example-toast');
const instance = new Nimbus.Toast(toastEl, {
  autohide: true,
  delay: 5000,
  position: 'top-right',
  appendToBody: true,
  stacking: true,
  color: 'info',
});
instance.show();
    Dismiss

    Add data-cnds-dismiss="toast" to a button inside the toast to wire up automatic dismissal on click:

    HTML
    <button type="button" class="btn-close" data-cnds-dismiss="toast" aria-label="Close"></button>

    Or trigger a toast from a button outside it using data-cnds-toggle and data-cnds-target:

    HTML
    <button type="button" class="btn btn-primary" data-cnds-toggle="toast" data-cnds-target="#my-toast">Show toast</button>

    Options

    Options can be passed via data attributes or JavaScript. For data attributes, append the option name to data-cnds-. camelCase options are kebab-cased — appendToBody becomes data-cnds-append-to-body.

    Name Type Default Description
    animation Boolean true Apply a CSS fade transition when showing and hiding the toast.
    autohide Boolean true Automatically dismiss the toast after delay milliseconds. The timer pauses while the cursor or focus is inside the toast.
    delay Number 5000 Milliseconds before the toast auto-hides. Only applies when autohide is true.
    position String 'top-right' Viewport position. Accepts: top-left, top-center, top-right, bottom-left, bottom-center, bottom-right. Positioning CSS is only applied when data-cnds-position is set on the element, appendToBody is true, or container is configured.
    offset Number 24 Distance in pixels between the toast and the nearest viewport or container edge. Applies when position is active.
    color String / null null Sets the data-cnds-color attribute on the element. Accepts: primary, secondary, success, danger, warning, caution, info, light, or dark.
    width String / null null Sets an explicit inline width on the toast element, e.g. '350px'. When null, width is controlled by --cnds-toast-max-width.
    appendToBody Boolean false Moves the toast element to <body> when shown. Enables position: fixed viewport placement and resolves stacking context issues caused by transformed ancestors.
    container String / null null CSS selector of a parent element to scope the toast inside. The container receives position: relative automatically. Use with the .parent-toast-relative utility class.
    stacking Boolean true When true, each new toast at the same position queues below (or above) the previous one. When false, toasts replace each other in the same slot.

    Methods

    Name Description Example
    show() Shows the toast. Fires show.cnds.toast immediately and shown.cnds.toast after the transition completes. instance.show()
    hide() Hides the toast. Fires hide.cnds.toast immediately and hidden.cnds.toast after the transition completes. instance.hide()
    update(options) Merges new options into the instance config. If position is included, positional styles are updated immediately. instance.update({ position: 'bottom-right' })
    dispose() Destroys the instance, removes event listeners, and unregisters the toast from the stacking registry. instance.dispose()
    getInstance(el) Static. Returns the Toast instance associated with a DOM element, or null if none exists. Nimbus.Toast.getInstance(el)
    getOrCreateInstance(el) Static. Returns the existing instance or creates a new one with default options. Nimbus.Toast.getOrCreateInstance(el)
    JAVASCRIPT
    const toastEl = document.getElementById('my-toast');
const instance = new Nimbus.Toast(toastEl, { autohide: true, delay: 3000 });
instance.show();

// Update position at runtime
instance.update({ position: 'bottom-center' });

// Listen for hidden event, then clean up
toastEl.addEventListener('hidden.cnds.toast', () => instance.dispose());

    Events

    All toast events fire on the toast element and bubble. Attach listeners before calling show() to capture the opening events.

    Event Trigger
    show.cnds.toast Fires immediately when show() is called. Calling event.preventDefault() cancels the show.
    shown.cnds.toast Fires after the toast becomes fully visible and the CSS transition has completed.
    hide.cnds.toast Fires immediately when hide() is called (by auto-hide timer, dismiss button, or direct call). Calling event.preventDefault() cancels the hide.
    hidden.cnds.toast Fires after the toast is fully hidden and the CSS transition has completed.
    JAVASCRIPT
    const toastEl = document.getElementById('my-toast');

toastEl.addEventListener('show.cnds.toast', event => {
  // cancel the show if a condition is not met
  if (!canShow) event.preventDefault();
});

toastEl.addEventListener('hidden.cnds.toast', () => {
  // toast has finished hiding — clean up or update UI
});

    CSS classes

    The following classes control toast structure and appearance. Color variants are applied via the data-cnds-color attribute rather than additional class names.

    Class Element Description
    .toast <div> Main toast container. Hosts all CSS custom properties. Hidden via display: none until shown; receives .show and .showing during transitions.
    .toast-header <div> Optional header area. Renders as a flex row for icon, title, timestamp, and close button. Separated from the body by a bottom border (suppressed for color variants).
    .toast-body <div> Content area of the toast. Accepts arbitrary HTML including links and formatted text.
    .toast-container <div> Optional wrapper for a group of static inline toasts. Sets pointer-events: none on the container with pointer-events: auto restored on each toast. Applies --cnds-toast-spacing between items.
    .toast-absolute <div> Sets position: absolute on the toast. Use with a position: relative parent when scoping via the container option.
    .parent-toast-relative any Utility that sets position: relative on a container element. Required when scoping a toast inside a parent via data-cnds-container.

    Accessibility

    Toasts are transient notifications that must be announced to assistive technologies without interrupting the user's current task. The following requirements apply to all CNDS Toast implementations and are aligned with Section 508 of the Rehabilitation Act and WCAG 2.1 success criteria 1.4.3, 2.2.1, 2.4.1, and 4.1.3.

    Live region role

    Choose the correct ARIA role based on urgency. Using role="alert" on a non-urgent toast is a Section 508 violation because it interrupts the screen reader mid-sentence.

    Role aria-live Use for
    role="alert" assertive Errors, destructive action confirmations, security warnings — messages that require immediate attention.
    role="status" polite Success confirmations, informational notices, progress updates — messages that can wait for a natural pause.
    Required attributes
    • aria-atomic="true" — ensures the entire toast content is announced as a single unit, not as individual node changes.
    • aria-label="Close" on the .btn-close element — provides an accessible name for the dismiss button (required by WCAG 4.1.2).
    • Decorative icons inside the toast header must have aria-hidden="true" to prevent duplicate announcements.
    Timing (WCAG 2.2.1 / Section 508 §1194.31)
    • Set autohide: true with a minimum delay of 5 000 ms. Screen readers need time to finish their current speech queue before announcing the new live region.
    • Use autohide: false for errors and destructive-action confirmations so the user can read and act before the toast disappears.
    • Mouse hover and keyboard focus both pause the auto-hide timer automatically.
    Color contrast (WCAG 1.4.3)

    All nine color variants — primary, secondary, success, danger, warning, caution, info, light, and dark — have been verified to meet WCAG AA contrast ratios (minimum 4.5:1 for normal text, 3:1 for large text) using CNDS design tokens. Do not override the variant colors with custom values without re-verifying contrast.

    caution pairs Caution/900 #3d1e00 on Caution/200 #ffd7ad for 11.25:1. It deliberately does not use --cnds-caution-text-emphasis (#b35900), which is the correct caution text color on a page ground but reaches only 3.58:1 on this surface and fails AA for body text.

    Skip navigation (WCAG 2.4.1)

    The page-level skip link (<a class="visually-hidden-focusable" href="#main-content">) ensures keyboard users can bypass repeated navigation blocks. This is required for any page that hosts toasts alongside a persistent header or sidenav.
