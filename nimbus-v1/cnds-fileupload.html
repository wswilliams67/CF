    v1File upload
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The File Upload plugin wraps a standard <input type="file"> element with a styled, accessible drag-and-drop drop zone. It handles file selection, image previewing, file-type and size validation, multi-file queuing, and optional XHR upload — all without external dependencies. Initialization requires only a single data attribute; every configurable behavior is exposed through data-cnds-* attributes or a plain JavaScript config object.

    The plugin is registered globally as window.Nimbus.FileUpload and requires css/plugins/file-upload.css (styling) and js/plugins/file-upload.js (behaviour). Both files must be loaded before the DOM is ready.

    Note: Read the API Documentation for the full options, methods, events, and CSS custom-property reference.

    Note: css/plugins/file-upload.css and js/plugins/file-upload.js must be included for the plugin to function.

    Note: To preview the component in different themes, click the theme toggle / in the header navigation bar.

    Basic example

    Place data-cnds-file-upload-init on a wrapper <div>, not on the <input>. The plugin reads the wrapper as its root element, finds (or creates) the <input type="file"> child, hides the native input, and builds the drop zone UI inside the wrapper. Default settings allow up to 10 files, 10 MB each, any file type.

    HTML

    <!-- data-cnds-file-upload-init is on the wrapper, not the input -->
<div data-cnds-file-upload-init>
  <input type="file" aria-label="Choose a file to upload" />
</div>

    Dropzone text

    The dropzoneText option controls the HTML displayed inside the drop zone when no file has been selected. The value accepts an HTML string, so inline markup is valid — wrapping a word in <strong> renders it in the same text color with an underline, making it look like a call-to-action without introducing a separate accent color. Pass the option via the data-cnds-dropzone-text attribute on the wrapper, or as a property in the JavaScript config object.

    HTML

    <div
  data-cnds-file-upload-init
  data-cnds-dropzone-text="Drop your report here or <strong>browse</strong>"
>
  <input type="file" aria-label="Choose a file to upload" />
</div>

    Custom height

    The plugin has no built-in height option; override the min-height of .file-upload-dropzone with an inline style attribute on the wrapper or a CSS rule scoped to a selector of your choice. Use the CSS custom property --cnds-fu-radius if you also need to adjust the border radius.

    HTML

    <div id="my-upload" data-cnds-file-upload-init>
  <input type="file" aria-label="Choose a file to upload" />
</div>

    CSS

    /* Scope the override to a specific instance */
#my-upload .file-upload-dropzone {
  min-height: 300px;
}

/* Or apply globally */
.file-upload-dropzone {
  min-height: 300px;
}

    Max file size

    The maxSize option accepts a size in bytes. Files that exceed the limit are rejected and an error.cnds.fileupload event fires with the reason. The example below restricts uploads to 5 MB (5 × 1024 × 1024 = 5 242 880 bytes). The drop zone hint updates automatically to reflect the configured limit.

    HTML

    <!-- maxSize is in bytes: 5242880 = 5 MB (5 × 1024 × 1024) -->
<div data-cnds-file-upload-init data-cnds-max-size="5242880">
  <input type="file" aria-label="Choose a file to upload (5 MB max)" />
</div>

    Dropzone hint

    By default the drop zone renders a hint line beneath the main message that summarises the active maxSize and maxFiles constraints (e.g., "Max 10 MB · up to 10 files"). The dropzoneHint option replaces this auto-generated text with a custom string, letting you add context-specific instructions or file-format guidance.

    HTML

    <div
  data-cnds-file-upload-init
  data-cnds-dropzone-hint="Accepted: PDF, DOCX, XLSX · Max 10 MB each"
>
  <input type="file" aria-label="Choose a file to upload" />
</div>

    Disable

    Setting data-cnds-disabled="true" renders the drop zone in a non-interactive state: cursor changes to not-allowed, opacity is reduced, and both drag-and-drop and click interactions are blocked. The state can be toggled at runtime using the disable() and enable() instance methods.

    HTML

    <div data-cnds-file-upload-init data-cnds-disabled="true">
  <input type="file" aria-label="File upload (disabled)" disabled />
</div>

    JAVASCRIPT

    const wrapper = document.getElementById('my-upload');
const upload  = Nimbus.FileUpload.getInstance(wrapper);

upload.disable(); // prevents all interaction
upload.enable();  // restores interaction

    Accept file types

    The acceptedTypes option restricts which file types the drop zone accepts. Values follow the same comma-separated format as the HTML accept attribute: MIME types (image/*), file extensions (.pdf), or a mix of both. Files that do not match trigger an error.cnds.fileupload event and are shown in an error state in the file list.

    HTML

    <!-- acceptedTypes mirrors the HTML accept attribute format -->
<div
  data-cnds-file-upload-init
  data-cnds-accepted-types="image/*,.pdf"
>
  <input
    type="file"
    accept="image/*,.pdf"
    aria-label="Choose an image or PDF file"
  />
</div>

    File list visibility

    The plugin renders a file list beneath the drop zone after files are selected. Each entry shows a thumbnail (for images), the filename, file size, any validation error, and a remove button that uses the Nimbus mdi-close icon at 16 px. Set showFileList to false to suppress the entire list — for example, when the surrounding form manages its own file summary UI.

    HTML

    <!-- showFileList="false" hides the rendered list;
     files are still accessible via getFiles() or the change event -->
<div data-cnds-file-upload-init data-cnds-show-file-list="false">
  <input type="file" aria-label="Choose a file to upload" />
</div>

    Multiple files

    The multiple option is true by default. The plugin accepts multiple files per drag-and-drop action or browse dialog and lists each file independently. Set data-cnds-multiple="false" to restrict the component to a single file; adding a second file will replace the first.

    HTML

    <!-- multiple is the default; set data-cnds-multiple="false" for single-file mode -->
<div data-cnds-file-upload-init data-cnds-multiple="true">
  <input type="file" multiple aria-label="Choose one or more files to upload" />
</div>

    Maximum file count

    Combine data-cnds-multiple="true" with data-cnds-max-files to cap the number of files a user can select. Attempting to add files beyond the limit fires an error.cnds.fileupload event with the reason "Maximum number of files (n) reached". The drop zone hint updates automatically to reflect the configured limit.

    HTML

    <!-- maxFiles caps the total files queued; excess triggers an error event -->
<div
  data-cnds-file-upload-init
  data-cnds-multiple="true"
  data-cnds-max-files="3"
>
  <input type="file" multiple aria-label="Choose up to 3 files to upload" />
</div>

    API Documentation

    Introduction

    The File Upload plugin wraps any <input type="file"> element inside a styled, keyboard-accessible drag-and-drop drop zone. It is initialised automatically on page load for every wrapper element that carries data-cnds-file-upload-init, or manually via the FileUpload constructor. All configuration is passed through data-cnds-* attributes on the wrapper or as a plain object to the constructor.

    The plugin dispatches four custom DOM events on the wrapper element so application code can react to user interactions without polling. It is fully theme-aware: all colors reference --cnds-fu-* CSS custom properties that adapt automatically when data-cnds-theme="dark" is active. Interactive states (hover border, drag-over border, progress bar) use a neutral gray derived from --cnds-fu-color rather than a brand accent, keeping the component visually neutral in any context. The plugin is registered globally as window.Nimbus.FileUpload.

    Note: css/plugins/file-upload.css and js/plugins/file-upload.js must both be loaded before the DOM is ready.

    Usage

    Via data attributes

    Add data-cnds-file-upload-init to the wrapper <div> and use additional data-cnds-* attributes to configure the plugin. No JavaScript is required.

    HTML
    <div
  data-cnds-file-upload-init
  data-cnds-max-size="5242880"
  data-cnds-accepted-types="image/*,.pdf"
  data-cnds-dropzone-text="Drop files here or <strong>browse</strong>"
>
  <input type="file" multiple aria-label="Choose files to upload" />
</div>

    Via JavaScript

    Pass a config object as the second argument to the FileUpload constructor. The constructor merges the provided config with the plugin defaults.

    JAVASCRIPT
    const wrapper = document.getElementById('my-upload');

const upload = new Nimbus.FileUpload(wrapper, {
  maxSize:       5 * 1024 * 1024, // 5 MB in bytes
  acceptedTypes: 'image/*,.pdf',
  maxFiles:      5,
  dropzoneText:  'Drop files here or <strong>browse</strong>',
  showPreview:   true,
});

    Options

    All options can be set via data-cnds-* attributes on the wrapper (kebab-cased option name) or passed as a JavaScript config object to the constructor. Attribute values are automatically coerced to the expected type (boolean strings "true"/"false" and numeric strings are converted).

    Name Type Default Description
    multiple boolean true Allow more than one file per selection. Set to false for single-file mode; adding a second file replaces the first.
    maxFiles number 10 Maximum number of files that can be queued at once. Attempting to add more fires error.cnds.fileupload.
    maxSize number 10485760 Maximum allowed file size in bytes (default: 10 MB). Files exceeding this limit fire error.cnds.fileupload.
    acceptedTypes string | null null Comma-separated list of accepted MIME types (image/*) and/or extensions (.pdf). Matches the HTML accept attribute format. null accepts all types.
    showPreview boolean true Show a thumbnail preview for image files (jpg, jpeg, png, gif, webp, svg, bmp, ico) in the file list.
    showFileList boolean true Render the file list beneath the drop zone. When false, files are still tracked internally and accessible via getFiles().
    autoUpload boolean false Automatically POST each file to uploadUrl as soon as it is added. Requires uploadUrl to be set.
    uploadUrl string | null null Endpoint URL for XHR file upload. Required when using autoUpload or the upload() method.
    uploadMethod string 'POST' HTTP method used for the upload request.
    uploadFieldName string 'file' FormData field name used for each uploaded file.
    dropzoneText string 'Drag & drop files here or <strong>browse</strong>' HTML content rendered as the drop zone's primary message. Accepts inline HTML.
    dropzoneHint string '' Secondary hint line rendered below the main message. When empty, the plugin auto-generates a summary from maxSize and maxFiles.
    disabled boolean false Initialise the component in a disabled state. Can be toggled at runtime with disable() / enable().

    Methods

    Retrieve a plugin instance with the static getInstance() method, then call any public method on it. All methods are synchronous unless noted.

    Name Description Returns
    getFiles() Returns an array of the native File objects currently queued. File[]
    getFileData() Returns the full internal file-data array, including status, progress, and error per entry. Object[]
    addFiles(fileListOrArray) Programmatically add files to the queue. Accepts a FileList or any array-like of File objects. Validation rules (type, size, count) still apply. void
    removeFile(id) Remove a single queued file by its generated id string (obtained from getFileData()). void
    clearFiles() Remove all queued files and reset the native input value. void
    upload() Trigger an XHR upload for all queued files. Requires uploadUrl to be configured. void
    disable() Put the component into a disabled state: applies the .disabled modifier class and blocks all interaction. void
    enable() Remove the disabled state and restore interaction. void
    dispose() Destroy the plugin instance: clears the file queue and removes all internal event listeners. void
    FileUpload.getInstance(el) Static. Returns the FileUpload instance attached to the given wrapper element, or null if none exists. FileUpload | null
    JAVASCRIPT
    // Retrieve the instance attached to the wrapper element
const wrapper = document.getElementById('my-upload');
const upload  = Nimbus.FileUpload.getInstance(wrapper);

// Read queued files
const files = upload.getFiles(); // File[]

// Programmatically add files (e.g. from a custom drag target)
upload.addFiles(myFileList);

// Remove a specific file by id (from getFileData())
const [first] = upload.getFileData();
upload.removeFile(first.id);

// Clear the entire queue
upload.clearFiles();

// Trigger upload to uploadUrl
upload.upload();

// Toggle disabled state
upload.disable();
upload.enable();

    Events

    All events fire on the wrapper element (the one that carries data-cnds-file-upload-init), not on the <input>. Event detail is accessed via event.detail.

    Event event.detail shape Description
    add.cnds.fileupload { file: File } Fires immediately after a valid file is added to the queue. detail.file is the native File object.
    remove.cnds.fileupload { file: File } Fires when a file is removed from the queue, either by the user clicking the remove button or by calling removeFile().
    error.cnds.fileupload { file: File, error: string } Fires when a file fails validation (wrong type, exceeds maxSize, exceeds maxFiles). detail.error contains a human-readable reason string.
    change.cnds.fileupload { files: File[] } Fires after any change to the file queue (add, remove, or clear). detail.files is the full current list of queued File objects.
    JAVASCRIPT
    const wrapper = document.getElementById('my-upload');

// React to any queue change (most common use case)
wrapper.addEventListener('change.cnds.fileupload', (e) => {
  console.log('Queued files:', e.detail.files);
});

// Intercept individual additions
wrapper.addEventListener('add.cnds.fileupload', (e) => {
  console.log('Added:', e.detail.file.name);
});

// Handle validation errors
wrapper.addEventListener('error.cnds.fileupload', (e) => {
  console.warn('Rejected:', e.detail.file.name, '—', e.detail.error);
});

// React to removals
wrapper.addEventListener('remove.cnds.fileupload', (e) => {
  console.log('Removed:', e.detail.file.name);
});

    CSS classes

    The plugin generates and manages the following CSS classes. Most are applied programmatically; only .file-upload-compact is a modifier you apply manually to the wrapper.

    Class Element Description
    .file-upload Wrapper <div> Applied automatically by the plugin on init. Sets position: relative; width: 100% and hosts all CSS custom properties.
    .file-upload-compact Wrapper <div> Optional modifier. Renders the drop zone as a compact row (flex-direction: row) rather than a tall column. Add manually alongside data-cnds-file-upload-init.
    .file-upload-dropzone Generated <div> The visible drop-zone area. Receives .dragover during an active drag and .disabled when the component is disabled.
    .file-upload-dropzone.dragover Dropzone Applied during an active drag-over; changes the border from dashed to solid and applies the --cnds-fu-hover-bg neutral tint.
    .file-upload-dropzone.disabled Dropzone Applied by disable(). Reduces opacity and sets pointer-events: none.
    .file-upload-list Generated <ul> Container for the queued-file entries. Only present when showFileList is true.
    .file-upload-item Generated <li> One entry per queued file. Hover applies a neutral background tint in both light and dark themes. Receives .error on validation failure (muted gray border, neutral background) and .success on successful upload (green border). Each item includes a 16 px mdi-close remove button.

    CSS custom properties

    All custom properties are defined on .file-upload in file-upload.css and can be overridden per-instance (inline style on the wrapper) or globally via a CSS rule targeting .file-upload. Dark-mode overrides are in the [data-cnds-theme="dark"] .file-upload block.

    Property Light default Dark default Description
    --cnds-fu-bg var(--cnds-body-bg, #fff) var(--cnds-body-bg, #1e1e1e) Drop zone and file-item background color.
    --cnds-fu-color var(--cnds-body-color, #4f4f4f) var(--cnds-body-color, #ebebeb) Primary text color inside the component.
    --cnds-fu-border var(--cnds-border-color, #dee2e6) var(--cnds-border-color, #6b6b6b) Drop zone and file-item border color.
    --cnds-fu-radius var(--cnds-border-radius, 0.375rem) same Border radius for the drop zone and file items.
    --cnds-fu-primary var(--cnds-fu-color) same Accent color for hover state, active border, and progress bar. Inherits from --cnds-fu-color so it adapts to both themes automatically.
    --cnds-fu-hover-bg rgba(0, 0, 0, 0.04) rgba(255, 255, 255, 0.05) Drop zone background on hover or active drag.
    --cnds-fu-muted #6c757d var(--cnds-text-muted, #d1d1d1) Color for the upload icon, hint text, and file size. Dark value uses --cnds-text-muted for WCAG AA compliance (~10.9:1 on #1e1e1e).
    --cnds-fu-success var(--cnds-success, #00b74a) same Border and progress bar color for successfully uploaded files.
    --cnds-fu-danger var(--cnds-danger, #f93154) same Reserved for downstream use. Error items use --cnds-fu-muted for borders and text to keep the component free of red.
