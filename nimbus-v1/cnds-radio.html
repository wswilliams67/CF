    A radio button is a form control that allows a user to select exactly one option from a group. Use radios when the user must commit to a single choice — use Checkboxes when multiple selections are permitted.

    Nimbus radios replace the browser default with a consistent cross-browser appearance via .form-check and .form-check-input. The checked indicator is a white SVG dot rendered as a CSS background image, keeping the markup clean and the visual fully theme-aware.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Apply .form-check to the wrapper element and .form-check-input to the <input type="radio">. Pair each input with a .form-check-label on the sibling <label>, linked via matching id and for attributes. All inputs in a group must share the same name attribute so the browser enforces mutual exclusivity.

    CNDS uses the sibling selector (~) to style the label in response to the input's state — :checked, :disabled, and :focus — without any JavaScript.

    HTML

    <!-- Unchecked radio -->
<div class="form-check">
    <input class="form-check-input" type="radio" name="flexRadioDefault" id="flexRadioDefault1" />
    <label class="form-check-label" for="flexRadioDefault1">Default radio</label>
</div>

<!-- Pre-checked radio -->
<div class="form-check">
    <input class="form-check-input" type="radio" name="flexRadioDefault" id="flexRadioDefault2" checked />
    <label class="form-check-label" for="flexRadioDefault2">Default checked radio</label>
</div>

    Disabled

    Add the disabled attribute to the <input> to prevent interaction. The sibling .form-check-label is automatically dimmed to 50% opacity via the CSS sibling selector (~), signalling the unavailable state without any JavaScript.

    HTML

    <div class="form-check">
    <input class="form-check-input" type="radio" name="flexRadioDisabled" id="flexRadioDisabled" disabled />
    <label class="form-check-label" for="flexRadioDisabled">Disabled radio</label>
</div>

<div class="form-check">
    <input class="form-check-input" type="radio" name="flexRadioDisabled" id="flexRadioCheckedDisabled" checked disabled />
    <label class="form-check-label" for="flexRadioCheckedDisabled">Disabled checked radio</label>
</div>

    Invalid / Validation

    Add .is-invalid to the radio input to signal a validation error. The .invalid-feedback element switches to --cnds-form-invalid-color. The radio border and label both remain in their default theme styles.

    Prefer server-side or submit-time validation over real-time invalid state to avoid flagging fields the user has not yet interacted with. Associate the feedback message with the input via aria-describedby for screen reader support.

    You must select an option before submitting.

    HTML

    <div class="form-check">
    <input class="form-check-input is-invalid" type="radio" name="flexRadioInvalid" id="invalidRadio"
        aria-describedby="invalidRadio-feedback" />
    <label class="form-check-label" for="invalidRadio">Accept terms and conditions</label>
    <div id="invalidRadio-feedback" class="invalid-feedback">You must select an option before submitting.</div>
</div>

    Inline

    Add .form-check-inline to each .form-check wrapper to place options on a single horizontal row. Each item is rendered as display: inline-block with a right margin between options.

    HTML

    <div class="form-check form-check-inline">
    <input class="form-check-input" type="radio" name="inlineRadioOptions" id="inlineRadio1" value="option1" />
    <label class="form-check-label" for="inlineRadio1">1</label>
</div>

<div class="form-check form-check-inline">
    <input class="form-check-input" type="radio" name="inlineRadioOptions" id="inlineRadio2" value="option2" />
    <label class="form-check-label" for="inlineRadio2">2</label>
</div>

<div class="form-check form-check-inline">
    <input class="form-check-input" type="radio" name="inlineRadioOptions" id="inlineRadio3" value="option3" disabled />
    <label class="form-check-label" for="inlineRadio3">3 (disabled)</label>
</div>

    Without labels

    Omit the .form-check wrapper and the <label> when no visible label text is needed. Always supply an aria-label attribute on the <input> so the option remains accessible to screen readers.


    HTML

    <div>
    <input class="form-check-input" type="radio" name="radioNoLabel" id="radioNoLabel1" value="" aria-label="Option one" />
</div>

<div>
    <input class="form-check-input" type="radio" name="radioNoLabel" id="radioNoLabel2" value="" aria-label="Option two" />
</div>

    Toggle buttons

    Style radio inputs as button-group toggles by pairing .btn-check on the hidden <input> with a .btn class on the sibling <label>. Wrap the group in .btn-group to join the buttons visually. The browser still enforces mutual exclusivity via the shared name attribute; no JavaScript is required.

    HTML

    <div class="btn-group" role="group" aria-label="Toggle button group">
    <input type="radio" class="btn-check" name="options" id="option1" autocomplete="off" checked />
    <label class="btn btn-secondary" for="option1">Checked</label>

    <input type="radio" class="btn-check" name="options" id="option2" autocomplete="off" />
    <label class="btn btn-secondary" for="option2">Radio</label>

    <input type="radio" class="btn-check" name="options" id="option3" autocomplete="off" />
    <label class="btn btn-secondary" for="option3">Radio</label>
</div>

    Accessibility

    Radio buttons are native interactive elements with strong built-in accessibility. Follow these practices to ensure the best experience for assistive technology users:

    • Always associate each <input type="radio"> with a <label> via matching id and for attributes, or use aria-label when no visible label is present.
    • Group related radios by giving them the same name attribute. Screen readers announce the group name as the user navigates between options.
    • Wrap a set of related radios in a <fieldset> with a <legend> to provide context about what the group represents — for example, "Select migration type".
    • For the toggle button pattern, add role="group" and an aria-label to the .btn-group wrapper so the purpose of the control set is announced.
    • Never rely on color alone to convey state — the checked indicator (SVG dot), focus ring, and label opacity change all provide non-color cues.

    For the full specification, see the WAI-ARIA Authoring Practices for the radio group pattern.

    API Documentation

    Introduction

    The Nimbus radio component is CSS-only — no JavaScript initialization is required. Appearance is controlled entirely through CSS custom properties defined on .form-check-input and overridden per-theme in light.css and dark.css. The checked indicator is a white SVG circle rendered via background-image, keeping markup free of extra elements. The toggle button pattern (.btn-check) is also CSS-only — the visually hidden <input> drives the adjacent .btn label via the :checked + .btn sibling selector.

    Usage

    Wrap each radio in .form-check, apply .form-check-input to the <input>, and link a .form-check-label via for/id. All inputs in a group must share the same name value.

    HTML
    <div class="form-check">
    <input class="form-check-input" type="radio" name="group" id="radio1" />
    <label class="form-check-label" for="radio1">Option one</label>
</div>

<div class="form-check">
    <input class="form-check-input" type="radio" name="group" id="radio2" checked />
    <label class="form-check-label" for="radio2">Option two</label>
</div>

    CSS classes

    All classes below are CSS-only and require no JavaScript. Classes sourced from css/components/forms.css and css/components/buttons.css.

    Class Element Description
    .form-check <div> Wrapper that establishes the left-padding gutter for the floating input. Sets min-height: 1.5rem and margin-bottom: 0.125rem.
    .form-check-input <input type="radio"> Replaces the browser default. Renders 18 × 18 px, fully circular (border-radius: 50%). Hosts all --cnds-form-check-* custom properties.
    .form-check-label <label> Label paired with the input. Font size 0.875 rem, weight 600. Opacity is automatically reduced to 0.5 when the sibling input is :disabled.
    .form-check-inline .form-check Modifier that changes the wrapper to display: inline-block with a right margin, placing multiple options on one row.
    .form-check-reverse .form-check Mirrors the layout so the input floats to the right and the label aligns left. Useful for right-to-left or right-aligned form designs.
    .btn-check <input type="radio"> Visually hides the radio while keeping it focusable and interactive. Drives the adjacent .btn label via the :checked + .btn CSS sibling selector.
    .btn-group <div> Wraps a set of .btn-check + .btn pairs into a joined button toolbar. Add role="group" and aria-label for accessibility.

    CSS custom properties

    All custom properties are defined on .form-check-input in css/components/forms.css. Theme-specific values are set in css/themes/light.css and overridden in css/themes/dark.css. Override per-instance with an inline style attribute, or globally by targeting .form-check-input in a custom stylesheet.

    Property Default Description
    --cnds-form-check-bg var(--cnds-input-bg, #fff) Background fill of the unchecked input. Inherits the shared input background token so it adapts to theme automatically.
    --cnds-form-check-bg-image none (unset) SVG background image applied by :checked[type="radio"] — a white circle centered in the input. Set automatically; do not override manually.
    --cnds-form-check-input-width 18px Width and height of the radio input. Both dimensions use this single token.
    --cnds-form-check-input-border-color #787878 (light) Border color of the unchecked input. Overridden in dark mode. Sourced from light.css / dark.css.
    --cnds-form-check-input-checked-bg var(--cnds-surface-blue-500, #355d97) Fill color of the checked input. Overridden in dark mode to var(--cnds-surface-blue-400, #6790ca).
    --cnds-form-check-input-checked-border-color var(--cnds-surface-blue-500, #355d97) Border color of the checked input. Matches --cnds-form-check-input-checked-bg by default so the border disappears visually.
    --cnds-form-check-input-focus-border-color var(--cnds-surface-blue-500, #355d97) Border color applied on :focus. Overridden in dark mode.
    --cnds-form-check-input-focus-box-shadow 0 0 0 0.25rem rgba(53,93,151,0.25) Focus ring applied on :focus. Provides a visible keyboard navigation indicator. Overridden in dark mode with the dark-mode blue.
    --cnds-form-check-input-border-color-invalid #ff97aa Border color applied when .is-invalid or :invalid is present. Overridden in dark mode.
    --cnds-form-check-label-color inherit Text color of .form-check-label. Inherits from the parent by default; overridden to --cnds-body-color in dark mode via dark.css.

    Theme variables

    The radio component adapts to the active theme via tokens set in light.css and overridden in dark.css. The component-level dark overrides are applied on [data-cnds-theme="dark"] .form-check-input selectors. All values below meet WCAG AA contrast requirements against their respective theme backgrounds.

    Token Light value Light contrast Dark value Dark contrast
    --cnds-form-check-input-border-color #787878 4.0:1 on #ffffff — AA (UI) var(--cnds-input-border-color, #6b6b6b) 3.1:1 on #252525 — AA (UI)
    --cnds-form-check-input-checked-bg var(--cnds-surface-blue-500, #355d97) 6.0:1 white dot on #355d97 — AA var(--cnds-surface-blue-400, #6790ca) 3.0:1 white dot on #6790ca — AA (UI)
    --cnds-form-check-label-color inherits --cnds-body-color (#4f4f4f) 11.5:1 on #ffffff — AAA var(--cnds-body-color, #ebebeb) 13.6:1 on #1e1e1e — AAA

    Accessibility

    The following practices ensure an accessible radio implementation:

    • Link every <input type="radio"> to its <label> via matching id and for attributes. When no visible label is used, provide aria-label directly on the input.
    • All radios in a mutually exclusive group must share the same name attribute. This is both a browser requirement for mutual exclusivity and an ARIA grouping signal.
    • Wrap a set of related radios in a <fieldset> with a <legend> to give screen readers the group label alongside each option.
    • For toggle button groups, add role="group" and aria-label to the .btn-group wrapper. The visually hidden .btn-check input retains full keyboard and screen-reader operability.
    • Do not use the disabled attribute to hide irrelevant options — remove them from the DOM instead. Disabled inputs are still discoverable to screen readers and may cause confusion.

    For the full specification, see the WAI-ARIA Authoring Practices for the radio group pattern.
