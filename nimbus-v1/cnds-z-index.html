    While not a part of the grid system, z-indexes play an important part in how components overlay and interact with one another. The Nimbus Design System uses a carefully structured z-index scale to ensure consistent layering across all interactive components.

    The z-index CSS property controls the vertical stacking order of overlapping elements. The Nimbus Design System provides both a component-level z-index scale using CSS custom properties and a set of utility classes for quick layering adjustments in your layouts.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: Z-index utilities are CSS-only and require no JavaScript initialization. They work with any positioned HTML element and are fully theme-compliant.

    Note: Z-index only works on positioned elements (position: relative, position: absolute, position: fixed, or position: sticky). Elements with position: static (the default) ignore z-index.

    Default z-index scale

    The Nimbus Design System defines a default z-index scale using CSS custom properties. This scale is designed to properly layer navigation, tooltips, popovers, modals, and other overlapping components in a predictable order.

    These higher values start at an arbitrary number, high and specific enough to ideally avoid conflicts. A standard set of these values is used across all layered components—tooltips, popovers, navbars, dropdowns, modals—so the system can be reasonably consistent in the behaviors. There is no reason we couldn’t have used 100+ or 500+.

    Customization of these individual values is not encouraged; should you change one, you likely need to change them all.

    CSS Variables 

    /* Nimbus Design System — Component z-index scale */
--cnds-zindex-dropdown:          1000;
--cnds-zindex-sticky:            1020;
--cnds-zindex-fixed:             1030;
--cnds-zindex-offcanvas-backdrop: 1040;
--cnds-zindex-offcanvas:         1045;
--cnds-zindex-modal-backdrop:    1050;
--cnds-zindex-modal:             1055;
--cnds-zindex-popover:           1070;
--cnds-zindex-tooltip:           1080;
--cnds-zindex-toast:             1090;

    Overlapping borders

    To handle overlapping borders within components (e.g., buttons and inputs in input groups), the design system uses low single digit z-index values of 1, 2, and 3 for default, hover, and active states. On hover, focus, or active, a particular element is brought to the forefront with a higher z-index value to show its border over the sibling elements.

    Utility classes

    The Nimbus Design System provides a set of z-index utility classes for quick layering control. These include both numeric utilities (.z-n1 through .z-3) and named layer utilities that map directly to the component z-index scale defined above.

    Numeric utilities

    Use .z-n1, .z-0, .z-1, .z-2, or .z-3 to set explicit z-index values on positioned elements. These low-value utilities are ideal for controlling the stacking of sibling elements within the same component.

    .z-3
    .z-2
    .z-1
    .z-0
    .z-n1

    HTML 

    <div class="position-relative z-3">...</div>
<div class="position-relative z-2">...</div>
<div class="position-relative z-1">...</div>
<div class="position-relative z-0">...</div>
<div class="position-relative z-n1">...</div>

    Named layer utilities

    Named layer utilities map directly to the component z-index scale. Use these when you need to match a specific component’s stacking context, such as placing a custom overlay at the same level as a modal or tooltip.

    HTML 

    <div class="z-dropdown">...</div>           <!-- z-index: 1000 -->
<div class="z-sticky">...</div>             <!-- z-index: 1020 -->
<div class="z-fixed">...</div>              <!-- z-index: 1030 -->
<div class="z-offcanvas-backdrop">...</div> <!-- z-index: 1040 -->
<div class="z-offcanvas">...</div>          <!-- z-index: 1045 -->
<div class="z-modal-backdrop">...</div>     <!-- z-index: 1050 -->
<div class="z-modal">...</div>              <!-- z-index: 1055 -->
<div class="z-popover">...</div>            <!-- z-index: 1070 -->
<div class="z-tooltip">...</div>            <!-- z-index: 1080 -->
<div class="z-toast">...</div>              <!-- z-index: 1090 -->

    API Documentation

    Introduction

    The Nimbus Design System z-index utilities provide a structured set of CSS custom properties and utility classes for controlling the stacking order of positioned elements. These utilities are CSS-only and require no JavaScript initialization. The z-index scale ensures consistent, predictable layering across all interactive components including dropdowns, modals, tooltips, and toast notifications.

    Usage

    Z-index utilities are applied directly as CSS classes on HTML elements. No JavaScript initialization is required. Add the appropriate class to any positioned element (position: relative, absolute, fixed, or sticky) to control its stacking order.

    HTML 
    <!-- Numeric z-index utilities -->
<div class="position-relative z-3">Highest layer</div>
<div class="position-relative z-2">Middle layer</div>
<div class="position-relative z-1">Lower layer</div>

<!-- Named layer utilities -->
<div class="position-fixed z-fixed">Fixed element</div>
<div class="z-tooltip">Tooltip layer</div>

    CSS Variables

    The component z-index scale is defined as CSS custom properties on the :root element. Override these variables to customize the stacking order for your application. Changing one value may require adjusting the others to maintain proper layering.

    Accessibility

    Z-index utilities control visual stacking order only — they have no direct impact on the accessibility tree or keyboard navigation order. However, when z-index is used to create overlapping interactive elements (modals, dropdowns, tooltips), the following accessibility requirements apply to those components:

    • Modal dialogs (.z-modal) must use role="dialog", aria-modal="true", and aria-labelledby pointing to the dialog title.
    • Dropdown menus (.z-dropdown) must use role="menu" or role="listbox" with corresponding aria-haspopup on the trigger.
    • Tooltip elements (.z-tooltip) must be referenced by the triggering element via aria-describedby.
    • When overlaid elements are visually hidden (z-index brings them below others), ensure they are also hidden from the accessibility tree using aria-hidden="true" or display: none.
