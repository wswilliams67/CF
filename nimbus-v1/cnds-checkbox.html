    v1 Checkbox
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Checkboxes allow users to select one or more independent options from a set, or toggle a single boolean preference on or off. Use a checkbox when the selection is independent of other items — if only one option can be active at a time, use a radio button instead.

    Nimbus checkboxes support seven distinct states defined in the Figma component specification: enabled, selected, indeterminate, disabled, disabled-selected, disabled-indeterminate, and invalid. Every state accepts an optional label and helper text.

    Note: All checkbox components use pure HTML5, CSS3, and vanilla JavaScript with zero external dependencies.

    Basic example

    Wrap a <input type="checkbox"> and its <label> in a .form-check container. The .form-check-input class replaces the browser default with the Nimbus-styled 18 × 18 px checkbox. The .form-check-label sits 8 px to the right and is styled at 14 px / semibold per the design tokens.

    The checked state renders a white SVG checkmark over the filled --cnds-form-check-input-checked-bg background. No JavaScript is needed for either the unchecked or checked states.

    HTML

                            <div class="form-check">
  <input class="form-check-input" type="checkbox" value="" id="basicCheckDefault" />
  <label class="form-check-label" for="basicCheckDefault">Default checkbox</label>
</div>
<div class="form-check">
  <input class="form-check-input" type="checkbox" value="" id="basicCheckChecked" checked />
  <label class="form-check-label" for="basicCheckChecked">Checked checkbox</label>
</div>

    Helper text

    Place a .form-text element immediately after the .form-check-label to provide supplementary context below the checkbox. Helper text renders at 12 px (--cnds-form-text-font-size) in a secondary muted color (--cnds-form-text-color). Use it to clarify what selecting the option means — keep it to one short sentence so it doesn't compete with the label.

    Helper text
    Helper text for selected state

    HTML

                            <div class="form-check">
  <input class="form-check-input" type="checkbox" value="" id="helperCheckDefault" />
  <label class="form-check-label" for="helperCheckDefault">Label text</label>
  <div class="form-text">Helper text</div>
</div>
<div class="form-check mt-3">
  <input class="form-check-input" type="checkbox" value="" id="helperCheckChecked" checked />
  <label class="form-check-label" for="helperCheckChecked">Selected label</label>
  <div class="form-text">Helper text for selected state</div>
</div>

    Indeterminate

    The indeterminate state — rendered as a horizontal dash — indicates a mixed or partially selected condition. It is most commonly used in "select all" patterns where a parent checkbox reflects that only some of its children are checked.

    The state is visual only: it does not change the element's .checked property and is not submitted with the form. It must be set and cleared programmatically via element.indeterminate = true / false. The :indeterminate CSS pseudo-class drives the dash icon through --cnds-form-check-bg-image.

    HTML

                            <div class="form-check">
  <input class="form-check-input" type="checkbox" value="" id="indeterminateCheck" />
  <label class="form-check-label" for="indeterminateCheck">Indeterminate checkbox</label>
</div>

    JavaScript

                            // Set the indeterminate state via JavaScript
const indeterminateEl = document.getElementById('indeterminateCheck');
indeterminateEl.indeterminate = true;

    Disabled

    Add the HTML disabled attribute to prevent interaction. The Nimbus checkbox applies opacity: 0.5 and pointer-events: none to both the input and its sibling label, giving a consistent muted appearance across all three disabled sub-states: unchecked, checked, and indeterminate.

    The disabled indeterminate state must still be set via JavaScript — the disabled attribute only controls interaction, not the indeterminate visual. Do not rely on aria-disabled alone; the native disabled attribute is required so the browser excludes the field from form submission and keyboard focus.

    HTML

                            <div class="form-check">
  <input class="form-check-input" type="checkbox" value="" id="disabledCheck" disabled />
  <label class="form-check-label" for="disabledCheck">Disabled checkbox</label>
</div>
<div class="form-check mt-3">
  <input class="form-check-input" type="checkbox" value="" id="disabledCheckedCheck" checked disabled />
  <label class="form-check-label" for="disabledCheckedCheck">Disabled checked</label>
</div>
<div class="form-check mt-3">
  <input class="form-check-input" type="checkbox" value="" id="disabledIndeterminateCheck" disabled />
  <label class="form-check-label" for="disabledIndeterminateCheck">Disabled indeterminate</label>
</div>

    JavaScript

                            // Set disabled-indeterminate state
const disabledIndeterminate = document.getElementById('disabledIndeterminateCheck');
disabledIndeterminate.indeterminate = true;

    Invalid / Validation

    Add .is-invalid to the checkbox input to signal a validation error. The .invalid-feedback element switches to --cnds-form-invalid-color. The checkbox border and label both remain in their default theme styles.

    Prefer server-side or submit-time validation over real-time invalid state to avoid flagging fields the user has not yet interacted with. Associate the feedback message with the input via aria-describedby for screen reader support.

    You must agree before submitting.

    HTML

                            <div class="form-check">
  <input class="form-check-input is-invalid" type="checkbox" value="" id="invalidCheck"
    aria-describedby="invalidCheck-feedback" />
  <label class="form-check-label" for="invalidCheck">Accept terms and conditions</label>
  <div id="invalidCheck-feedback" class="invalid-feedback">You must agree before submitting.</div>
</div>

    Inline

    Add .form-check-inline to each .form-check wrapper to arrange checkboxes horizontally. Inline layout works best for 2–4 short-label options that comfortably fit on one line. For five or more options, or when labels wrap, prefer the default stacked (block) layout to avoid alignment issues and improve scannability.

    Group related inline checkboxes inside a <fieldset> with a <legend> so screen readers announce the group context before reading each label.

    HTML

                            <div class="form-check form-check-inline">
  <input class="form-check-input" type="checkbox" id="inlineCheckbox1" value="option1" />
  <label class="form-check-label" for="inlineCheckbox1">1</label>
</div>
<div class="form-check form-check-inline">
  <input class="form-check-input" type="checkbox" id="inlineCheckbox2" value="option2" />
  <label class="form-check-label" for="inlineCheckbox2">2</label>
</div>
<div class="form-check form-check-inline">
  <input class="form-check-input" type="checkbox" id="inlineCheckbox3" value="option3" disabled />
  <label class="form-check-label" for="inlineCheckbox3">3 (disabled)</label>
</div>

    Without labels

    When a visible label would be redundant — for example, a select-all checkbox at the head of a data table column — omit the .form-check wrapper and .form-check-label. The checkbox still requires an accessible name for screen readers; supply one via aria-label, aria-labelledby pointing to a visible heading, or a visually hidden <label> using the .visually-hidden utility.

    Never leave a checkbox with no accessible name — a blank checkbox is not operable by keyboard or assistive technology users.

    HTML

                            <div>
  <input class="form-check-input" type="checkbox" id="checkboxNoLabel1"
    value="" aria-label="Checkbox without label" />
</div>
<div>
  <input class="form-check-input" type="checkbox" id="checkboxNoLabel2"
    value="" aria-label="Checkbox without label" />
</div>

    Toggle buttons

    Apply any .btn variant to a <label> and pair it with a preceding <input class="btn-check"> to create a button that toggles like a checkbox. The .btn-check input is visually clipped to zero size but remains in the accessibility tree — keyboard and screen reader users interact with it normally.

    The for/id relationship between the label and input is required. The autocomplete="off" attribute prevents the browser from restoring a previously checked state on page reload, which would leave the button visually out of sync with the underlying data.

    HTML

                            <input type="checkbox" class="btn-check" id="btn-check" autocomplete="off" />
<label class="btn btn-primary" for="btn-check">Checkbox button</label>

<input type="checkbox" class="btn-check" id="btn-check2" checked autocomplete="off" />
<label class="btn btn-primary" for="btn-check2">Checkbox button</label>

<input type="checkbox" class="btn-check" id="btn-check3" autocomplete="off" />
<label class="btn btn-primary" for="btn-check3">Checkbox button</label>

    Select all pattern

    A parent checkbox controls the checked state of all its children. The parent reflects three conditions: all checked (checked), none checked (unchecked), and some checked (indeterminate). Clicking the parent while indeterminate should check all children — ensure indeterminate = false is reset in the parent's change handler before the browser reads the new checked value.

    Mark child checkboxes with a shared class (e.g. .select-all-child) so the JavaScript can query and synchronize them. This pattern requires no library or framework — pure vanilla JavaScript with a single change listener on each element.

    HTML

                            <div class="form-check">
  <input class="form-check-input" type="checkbox" value="" id="selectAllCheckbox" />
  <label class="form-check-label fw-bold" for="selectAllCheckbox">Select all</label>
</div>
<hr class="my-2" />
<div class="form-check">
  <input class="form-check-input select-all-child" type="checkbox" value="" id="childCheck1" />
  <label class="form-check-label" for="childCheck1">Option 1</label>
</div>
<div class="form-check">
  <input class="form-check-input select-all-child" type="checkbox" value="" id="childCheck2" />
  <label class="form-check-label" for="childCheck2">Option 2</label>
</div>
<div class="form-check">
  <input class="form-check-input select-all-child" type="checkbox" value="" id="childCheck3" />
  <label class="form-check-label" for="childCheck3">Option 3</label>
</div>

    JavaScript

                            document.addEventListener('DOMContentLoaded', function () {
  const selectAll = document.getElementById('selectAllCheckbox');
  const children = document.querySelectorAll('.select-all-child');

  if (!selectAll || !children.length) return;

  // Parent controls children
  selectAll.addEventListener('change', function () {
    children.forEach(function (child) {
      child.checked = selectAll.checked;
    });
    selectAll.indeterminate = false;
  });

  // Children update parent
  children.forEach(function (child) {
    child.addEventListener('change', function () {
      const checkedCount = document.querySelectorAll('.select-all-child:checked').length;
      selectAll.checked = checkedCount === children.length;
      selectAll.indeterminate = checkedCount > 0 && checkedCount < children.length;
    });
  });
});

    API Documentation

    CSS Classes

    The following CSS classes are used to build and customize checkbox components. All classes follow the Nimbus naming convention and require no JavaScript initialization.

    Class Description
    .form-check Wrapper element for checkbox input and label pairs. Provides proper spacing and alignment.
    .form-check-input Applied to the <input type="checkbox"> element. Replaces the browser default with Nimbus-styled checkbox.
    .form-check-label Applied to the <label> element paired with the checkbox input.
    .form-check-inline Added to .form-check to display checkboxes horizontally in a row.
    .form-text Helper text element placed after the label. Renders at 12px in a secondary color.
    .btn-check Visually hides the checkbox input (position: absolute; clip: rect(0,0,0,0)) and pairs it with a button-styled label for toggle button patterns.
    .is-invalid Applied to the checkbox input to indicate a validation error. Changes border color to the danger token.
    .invalid-feedback Validation error message displayed below the checkbox when .is-invalid is applied.
    .select-all-child Utility class applied to child checkboxes in a select-all pattern. Used by JavaScript to query and synchronize child states.

    JavaScript

    Nimbus checkboxes are pure HTML/CSS components and do not require JavaScript initialization. However, certain states and patterns require JavaScript:

    • The indeterminate state must be set via element.indeterminate = true
    • The select all pattern requires event listeners to synchronize parent/child states
    • Dynamic validation can toggle the .is-invalid class programmatically
    Setting indeterminate state
                              // Set indeterminate state on a checkbox
const checkbox = document.getElementById('myCheckbox');
checkbox.indeterminate = true;

// Clear indeterminate state
checkbox.indeterminate = false;
    Toggling validation state
                              // Add invalid state
const checkbox = document.getElementById('myCheckbox');
checkbox.classList.add('is-invalid');

// Remove invalid state
checkbox.classList.remove('is-invalid');
    Listening for change events
                              const checkbox = document.getElementById('myCheckbox');
checkbox.addEventListener('change', function (event) {
  if (event.target.checked) {
    console.log('Checkbox is checked');
  } else {
    console.log('Checkbox is unchecked');
  }
});

    Accessibility

    Nimbus checkboxes are built with accessibility in mind. Follow these guidelines to ensure your checkbox implementations are accessible to all users:

    • Always pair each <input> with a <label> using matching for/id attributes.
    • When labels are not visible, use aria-label or aria-labelledby to provide an accessible name.
    • Use <fieldset> and <legend> to group related checkboxes.
    • Ensure sufficient color contrast between checkbox states and their background.
    • The indeterminate state is visual only and does not affect the checked property — handle both states in your form logic.
    • Validation messages should be associated with the input using aria-describedby for screen reader support.
    • Toggle buttons (.btn-check) maintain keyboard accessibility — users can toggle with Space or Enter.
