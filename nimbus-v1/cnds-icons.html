    The Nimbus Design System provides two bundled icon libraries for all UI needs. Material Design Icons (MDI) is the primary library for all functional and interactive interface icons — toolbars, navigation, buttons, alerts, status indicators, and form controls. MDI icons use the mdi base class plus an mdi-{icon-name} class on an <i> or <span> element, and can be precisely sized with pixel-based classes (mdi-18px, mdi-20px, mdi-24px, mdi-36px, mdi-48px). Font Awesome 6 Brands (fab) is reserved for social-platform and footer brand logos (X/Twitter, LinkedIn, YouTube). Both libraries are fully embedded in the Nimbus CSS bundle — no external CDN or additional downloads required. Icons inherit the current text color by default and are fully theme-aware, automatically adapting between light and dark modes via CSS custom properties.

    Icons can be used alone or paired with visible text labels. When an icon appears alongside a text label it is purely decorative and must carry aria-hidden="true" so screen readers skip it and read only the label. When an icon is the sole content of an interactive element — such as an icon-only button — the parent element must carry an aria-label. Standalone informational icons (conveying meaning without accompanying text) require role="img" and aria-label directly on the icon element. Consistent use of MDI pixel sizing (mdi-18px for inline, mdi-24px for toolbars) ensures optical alignment across Nimbus components and meets WCAG AA contrast requirements when paired with theme-aware color tokens.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: Icons are CSS-only and require no JavaScript initialization. To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic usage

    Place icons anywhere in your markup using the appropriate CSS prefix and icon name. All UI icons use MDI with the mdi base class and an mdi-{icon-name} modifier. The <i> tag is conventional for brevity, though a <span> is more semantically correct for inline text flow. Font Awesome Brands (fab) are reserved exclusively for social-platform logos.

    mdi-camera (MDI — UI icon)

    fa-github (Font Awesome Brand — social icon)

    HTML

    <!-- MDI icon (all UI/functional icons) -->
<i class="mdi mdi-camera" aria-hidden="true"></i>

<!-- Font Awesome Brand icon (social logos only) -->
<i class="fab fa-github" aria-hidden="true"></i>

    Material Design Icons sizing

    MDI uses pixel-based sizing classes for precise, consistent alignment in toolbars, navigation, and UI components. Use mdi-18px for inline icons within body text and form controls, mdi-20px for compact UI components and navigation, mdi-24px for toolbars and primary actions, and mdi-36px / mdi-48px for hero icons and empty states.

    cnds-icon-sm mdi-18px mdi-20px mdi-24px mdi-36px mdi-48px

    HTML

    <i class="mdi mdi-camera mdi-18px" aria-hidden="true"></i>
<i class="mdi mdi-camera mdi-20px" aria-hidden="true"></i>
<i class="mdi mdi-camera mdi-24px" aria-hidden="true"></i>
<i class="mdi mdi-camera mdi-36px" aria-hidden="true"></i>
<i class="mdi mdi-camera mdi-48px" aria-hidden="true"></i>

    Tip: Prefer MDI pixel-based sizing for all UI icons to ensure optical alignment across components. FA relative sizing (fa-lg, fa-2x) is useful when icons must scale proportionally with surrounding text.

    Note: If icons appear clipped on the top or bottom, ensure the parent element has sufficient line-height.

    Nimbus icon scale

    The .cnds-icon-* classes mirror the size axis of the Figma component Nimbus/Icon, so a size named in a design maps to exactly one class in code. Reach for these when matching a Figma spec; use the MDI pixel classes when you simply need a pixel value.

    Why these exist: MDI ships only 18px, 20px, 24px, 36px and 48px. It has no mdi-16px or mdi-22px, which are the SM and ML steps — the two sizes the input field and its clear button use. A mdi-16px class does not exist and silently falls back to the inherited font size; use .cnds-icon-sm instead.

    Font Awesome icon styles

    Font Awesome 6 provides multiple style variants. The fas (solid) and far (regular) styles are available for the free icon set. The fab (brands) style provides social-platform logos and is the only Font Awesome style used in Nimbus UI components.

    Solid (fas) Regular (far) Brands (fab) — social logos

    HTML

    <!-- Solid style -->
<i class="fas fa-heart" aria-hidden="true"></i>

<!-- Regular style -->
<i class="far fa-heart" aria-hidden="true"></i>

<!-- Brands style (social logos only) -->
<i class="fab fa-github" aria-hidden="true"></i>

    Icons in components

    Icons integrate seamlessly with Nimbus components such as buttons, alerts, input groups, and navigation elements. Use MDI for all functional UI icons. Apply spacing utilities like me-1 or me-2 to add appropriate gaps between icons and adjacent text. Always add aria-hidden="true" to icons that appear alongside visible text labels.

    In buttons

    HTML

    <!-- Icon before text -->
<button type="button" class="btn btn-casefusion">
  <i class="mdi mdi-download mdi-18px me-2" aria-hidden="true"></i> Download
</button>

<!-- MDI icon before text -->
<button type="button" class="btn btn-outline-casefusion">
  <i class="mdi mdi-plus mdi-18px me-2" aria-hidden="true"></i> Add item
</button>

<!-- Icon after text -->
<button type="button" class="btn btn-casefusion">
  Submit <i class="mdi mdi-arrow-right mdi-18px ms-2" aria-hidden="true"></i>
</button>

<!-- Icon-only button — aria-label on button, aria-hidden on icon -->
<button type="button" class="btn btn-casefusion btn-floating" aria-label="Add new item">
  <i class="mdi mdi-plus mdi-18px" aria-hidden="true"></i>
</button>

  <i class="mdi mdi-check-circle mdi-18px me-2" aria-hidden="true"></i>

    Accessibility

    Correct ARIA usage on icons is required for Section 508 and WCAG 2.1 AA compliance. The core rule is simple: if an icon appears next to visible text, it is decorative and must be hidden from assistive technology. If an icon conveys meaning without any visible label, it must be announced to screen readers.

    Decorative icon (alongside visible label)

    Operation completed — icon is decorative, label provides meaning

    Semantic standalone icon (conveys meaning alone)

    Status: — icon has role="img" and aria-label

    Icon button (no visible label)
    aria-label on the button, aria-hidden on the icon

    HTML

    <!-- Decorative icon next to visible text -->
<i class="mdi mdi-check-circle mdi-18px me-2" aria-hidden="true"></i> Operation completed

<!-- Standalone semantic icon -->
<i class="mdi mdi-alert-circle mdi-24px"
   role="img"
   aria-label="Error — action required"></i>

<!-- Icon-only button -->
<button type="button" class="btn btn-outline-secondary" aria-label="Close dialog">
  <i class="mdi mdi-close mdi-18px" aria-hidden="true"></i>
</button>

    API Documentation

    Introduction

    The Nimbus icon system is CSS-only — no JavaScript initialization is required. Both icon sets (MDI and Font Awesome 6) are embedded in nimbus.css and are available immediately on any page that loads it. MDI is the standard library for all interactive and functional UI icons; Font Awesome Brands (fab) is used exclusively for social-platform logos in footers and social link components. Icons inherit the current text color by default and adapt to light and dark themes automatically via CSS custom property resolution.

    Usage

    Icons are purely CSS-driven. Add the appropriate classes to an <i> or <span> element. Always add aria-hidden="true" for decorative icons, or the appropriate role and aria-label for semantic ones.

    Via HTML classes
    HTML
    <!-- MDI icon (decorative, next to label) -->
<i class="mdi mdi-{icon-name}" aria-hidden="true"></i>

<!-- MDI icon with explicit size -->
<i class="mdi mdi-{icon-name} mdi-18px" aria-hidden="true"></i>

<!-- Font Awesome Brands (social logos only) -->
<i class="fab fa-{brand-name}" aria-hidden="true"></i>
    Via JavaScript (dynamic insertion)

    To insert icons dynamically, create an element and set its className property. Always set aria-hidden or an appropriate label on the element.

    JAVASCRIPT
    // Create a decorative MDI icon element
const icon = document.createElement('i');
icon.className = 'mdi mdi-check-circle mdi-18px me-2';
icon.setAttribute('aria-hidden', 'true');

// Append to a container
document.querySelector('.my-container').appendChild(icon);

    Accessibility (Section 508 / WCAG 2.1 AA)

    Icon accessibility depends entirely on whether the icon communicates meaning independently or merely reinforces a visible text label. Apply the correct ARIA pattern for each context — incorrect usage either creates redundant announcements for screen-reader users or silently hides information they need.

    Decorative icons (alongside visible text)

    When an icon appears next to a visible text label — in a button, alert, list item, or navigation link — the icon is purely decorative. Add aria-hidden="true" so assistive technologies skip it entirely and announce only the text label. This is the most common pattern.

    Pattern Attribute Example
    Icon + visible label aria-hidden="true" on <i> <i class="mdi mdi-download mdi-18px" aria-hidden="true"></i> Download
    Icon in alert next to message aria-hidden="true" on <i> <i class="mdi mdi-check-circle mdi-18px" aria-hidden="true"></i> Success
    Semantic standalone icons (meaning without visible text)

    When an icon conveys meaning without any accompanying visible text — for example a status indicator in a table cell with no label — add role="img" and an aria-label that describes what the icon means in context.

    Pattern Attributes Example
    Standalone informational icon role="img" + aria-label on <i> <i class="mdi mdi-alert-circle mdi-24px" role="img" aria-label="Error — action required"></i>
    Icon buttons (interactive, no visible label)

    Icon-only buttons must carry an aria-label on the <button> element describing the action. The icon inside the button must carry aria-hidden="true" to prevent duplication.

    Pattern Attributes Example
    Icon-only button aria-label on <button>, aria-hidden="true" on <i> <button aria-label="Close dialog"><i class="mdi mdi-close mdi-18px" aria-hidden="true"></i></button>
    Icon-only link aria-label on <a>, aria-hidden="true" on <i> <a href="#" aria-label="View case details"><i class="mdi mdi-open-in-new mdi-18px" aria-hidden="true"></i></a>

    Best practices

    • Use MDI (mdi-*) for all functional and interactive UI icons — buttons, navigation, alerts, toolbars, status indicators.
    • Use Font Awesome Brands (fab fa-*) only for social-platform logos (X/Twitter, LinkedIn, YouTube, GitHub) in footers and social link components.
    • Use <i> or <span> elements for icons. Avoid <div> or block-level elements.
    • Always add aria-hidden="true" to decorative icons that appear alongside visible text labels.
    • For icon-only buttons, provide an aria-label on the button, not on the icon.
    • Prefer MDI pixel sizing (mdi-18px inline, mdi-24px toolbars) for consistent optical alignment.
    • Icons inherit the current color CSS property. Use Nimbus text color utilities (text-success, text-danger) or CSS custom properties (var(--cnds-product-casefusion-green-600)) to colorize icons — never hardcode hex values.
    • Avoid mixing FA and MDI sizing classes on the same element.
