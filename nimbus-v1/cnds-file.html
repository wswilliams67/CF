    v1File Input
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The File Input component lets users select one or more files from their local device. It replaces the unstyled browser-native <input type="file"> with a consistent, theme-aware control that matches the Nimbus design language: a labelled button, a visual divider, and a status area that updates with the selected filename once a file is chosen.

    Use the File Input when you need a simple single-field file picker that integrates with other form controls. For drag-and-drop uploads, multi-file queues, progress tracking, or file-type validation, use the Drag & Drop File Upload component instead.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Pair a .form-label with a .cf-file-input wrapper. Add data-cnds-file-input-init to enable auto-initialisation — the page script wires up the button click and updates the status text whenever a file is selected.

    No file chosen

    HTML

    <label class="form-label" for="fileBasic">Upload document</label>
<div class="cf-file-input" data-cnds-file-input-init>
    <button type="button" class="cf-file-input-btn" aria-hidden="true" tabindex="-1">Choose File</button>
    <span class="cf-file-input-divider" aria-hidden="true"></span>
    <span class="cf-file-input-text">No file chosen</span>
    <input type="file" class="cf-file-input-native" id="fileBasic" aria-label="Upload document" />
</div>

    Add the .disabled class to the wrapper and the disabled attribute to the <input> to render the component in its non-interactive state. No data-cnds-file-input-init is needed — the component does not require JavaScript when disabled.

    API Documentation

    Introduction

    The Nimbus File Input is a lightweight custom component built from standard HTML elements — a flex container, a visual button, a divider, and a status text span — with a hidden native <input type="file"> inside. The native input handles all browser file-dialog logic, accessibility semantics, and keyboard interaction; the visible elements provide the consistent Nimbus visual treatment.

    JavaScript initialisation wires up two event listeners: a click handler on the visible button that delegates to input.click(), and a change handler on the native input that updates the status text with the selected filename or a file count for multiple selections. No framework or build step is required.

    Usage

    The minimum required markup is a .cf-file-input wrapper containing the four child elements below. Always associate a visible .form-label with the native input via matching for / id attributes. Supply aria-label on the native input when the label text is not adjacent (see Accessibility).

    HTML
    <label class="form-label" for="myFile">Choose a file</label>
<div class="cf-file-input" data-cnds-file-input-init>
    <button type="button" class="cf-file-input-btn" aria-hidden="true" tabindex="-1">Choose File</button>
    <span class="cf-file-input-divider" aria-hidden="true"></span>
    <span class="cf-file-input-text">No file chosen</span>
    <input type="file" class="cf-file-input-native" id="myFile" aria-label="Choose a file" />
</div>

    JavaScript

    Adding data-cnds-file-input-init to the wrapper element enables auto-initialisation. The page script (or nimbus.js in production) calls CNDSFileInput.autoInit() on DOMContentLoaded, which finds every matching wrapper and attaches the event listeners automatically.

    JS
    // Auto-init — called once on DOMContentLoaded
CNDSFileInput.autoInit();

// Manual init — pass any .cf-file-input element
var wrapper = document.querySelector(".cf-file-input");
CNDSFileInput.init(wrapper);

    The CNDSFileInput.init() function attaches two listeners to the wrapper element passed in:

    • Button click — calls input.click() to open the OS file-picker dialog.
    • Input change — reads input.files and writes either the selected filename or a count string (e.g., 3 files selected) into .cf-file-input-text. Adds the .has-file class to apply the full-contrast text color; removes it when the selection is cleared.

    CSS classes

    Class Element Description
    .cf-file-input <div> Required wrapper. Renders as display: flex with a border, border-radius, and overflow: hidden so all children are clipped to the rounded corners. Hosts all CSS custom properties.
    .cf-file-input-sm <div> Small size modifier. Reduces font size to 13 px, vertical padding to 8 px, and horizontal padding to 12 px. Apply alongside .cf-file-input.
    .cf-file-input-lg <div> Large size modifier. Increases font size to 16 px, vertical padding to 14 px, and horizontal padding to 24 px. Apply alongside .cf-file-input.
    .cf-file-input.disabled <div> Disabled state. Sets opacity: 0.65, pointer-events: none, and applies the disabled background. Also match with disabled on the native input and button.
    .cf-file-input-btn <button> Visual "Choose File" button. Rendered with aria-hidden="true" and tabindex="-1" — it is a visual affordance only. JavaScript delegates its click event to the hidden native input.
    .cf-file-input-divider <span> 1 px vertical rule separating the button from the status text. Color inherits --cnds-file-border-color. Mark with aria-hidden="true".
    .cf-file-input-text <span> Status text area. Shows "No file chosen" by default. Updated by JavaScript to the selected filename or a count string.
    .cf-file-input-text.has-file <span> Added by JavaScript once a file is selected. Changes the text color from the muted placeholder value to --cnds-file-text-selected-color.
    .cf-file-input-native <input type="file"> The hidden native file input. Visually clipped to 1 px × 1 px using the clip technique so it remains in the tab order. All standard <input type="file"> attributes (accept, multiple, disabled, etc.) apply here.
    .cf-file-input-casefusion <div> CaseFusion product modifier. Overrides the :focus-within ring to the CaseFusion green brand color (#2e892a light / #7dd67a dark). Apply alongside .cf-file-input.
    .cf-file-input-expireon <div> ExpireOn product modifier. Overrides the :focus-within ring to the ExpireOn indigo brand color (#4e45d6 light / #b6b4ee dark). Apply alongside .cf-file-input.
    .cf-file-input-hyperlize <div> Hyperlize product modifier. Overrides the :focus-within ring to the Hyperlize amber brand color (#926a08 light / #f6bf37 dark). Apply alongside .cf-file-input.

    Accessibility

    The component is built around the native <input type="file">, which carries all required file-picker semantics for assistive technologies without additional ARIA markup. Follow the guidelines below to ensure the full component remains accessible:

    • Always pair the component with a visible .form-label that references the native input via matching for / id attributes. This gives screen readers an accessible name for the file picker.
    • Supply aria-label on the native input when the label text is not adjacent or when additional context is needed (e.g., aria-label="Case evidence — PDF or DOCX only").
    • The visual button must carry aria-hidden="true" and tabindex="-1". It is a presentation-only element — the native input handles keyboard activation (Tab to focus, Space/Enter to open the dialog).
    • The divider <span> must carry aria-hidden="true" to suppress it from the accessibility tree.
    • The :focus-within rule on .cf-file-input provides a visible focus ring around the entire wrapper when the native input is keyboard-focused, satisfying WCAG 2.1 SC 2.4.7 (Focus Visible).
    • When restricting accepted file types, always communicate the constraint in visible text (e.g., a .form-text hint below the input) in addition to the accept attribute. The accept attribute alone is not announced by all screen readers.
