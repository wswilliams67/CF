    v1 Tables
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Nimbus tables display tabular data clearly and compactly. Add the base class .table to any <table> to opt in to table styles. All modifier classes build on this base — nothing is applied globally, so nested tables and third-party widgets stay unaffected.

    Tables are opt-in by design. Because <table> elements are widely used in calendars, date pickers, and other widgets, Nimbus does not style them globally. Apply .table explicitly where you want Nimbus styles.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: If you need more advanced features such as sorting, pagination, or async data loading, see the DataTables documentation.

    Basic example

    Using the most basic table markup, here’s how .table-based tables look in Nimbus. Apply .table to any <table> element. All cells inherit theme-aware colors via CSS custom properties defined on the .table selector.

    Basic table
    # First Last Handle
    1 Mark Otto @mdo
    2 Jacob Thornton @fat
    3 Larry the Bird @twitter

    HTML

                                                
<table class="table">
    <thead>
        <tr>
            <th scope="col">#</th>
            <th scope="col">First</th>
            <th scope="col">Last</th>
            <th scope="col">Handle</th>
        </tr>
    </thead>
    <tbody>
        <tr>

            <td>Mark</td>

        </tr>
        <tr>
            <th scope="row">3</th>
            <td colspan="2">Larry the Bird</td>
            <td>@twitter</td>
        </tr>
    </tbody>
</table>

    Conveying meaning to assistive technologies:
    Using color to add meaning only provides a visual indication, which will not be conveyed to users of assistive technologies – such as screen readers. Ensure that information denoted by the color is either obvious from the content itself (e.g. the visible text), or is included through alternative means, such as additional text hidden with the .visually-hidden class.

    Nesting

    Style, active state, and variant classes are scoped to direct children using the .table > :not(caption) > * > * child combinator. Nested <table> elements inside a <td> are completely unstyled and can receive their own .table class independently.

    Nesting example
    # First Last Handle
    1 Mark Otto @mdo
    Nested table
    Header Header Header
    A First Last
    B First Last
    C First Last
    3 Larry the Bird @twitter

    HTML

                                                
<table class="table table-striped table-bordered">
    <thead>
        <tr>
            <th scope="col">#</th>
            <th scope="col">First</th>
            <th scope="col">Last</th>
            <th scope="col">Handle</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td colspan="4">
                <!-- Nested table: inherits no styles from the outer table -->
                <table class="table mb-0">
                    <thead><tr><th>Header</th><th>Header</th><th>Header</th></tr></thead>
                    <tbody><tr><th scope="row">A</th><td>First</td><td>Last</td></tr></tbody>
                </table>
            </td>
        </tr>
    </tbody>
</table>

    How nesting works

    To prevent any styles from leaking to nested tables, we use the child combinator (>) selector in our CSS. Since we need to target all the tds and ths in the thead, tbody, and tfoot, our selector would look pretty long without it. As such, we use the rather odd looking .table > :not(caption) > * > * selector to target all tds and ths of the .table, but none of any potential nested tables.

    Note that if you add <tr>s as direct children of a table, those <tr> will be wrapped in a <tbody> by default, thus making our selectors work as intended.

    Responsive tables

    Wrap any .table in a responsive container to enable horizontal scrolling when the table overflows its parent. Choose the container class that matches the viewport breakpoint at which scrolling should activate.

    Vertical clipping/truncation:
    Responsive tables make use of overflow-y: hidden, which clips off any content that goes beyond the bottom or top edges of the table. In particular, this can clip off dropdown menus and other third-party widgets.

    Always responsive

    Across every breakpoint, use .table-responsive for horizontally scrolling tables.

    Always responsive table
    # Heading Heading Heading Heading Heading Heading Heading Heading Heading
    1 Cell Cell Cell Cell Cell Cell Cell Cell Cell
    2 Cell Cell Cell Cell Cell Cell Cell Cell Cell
    3 Cell Cell Cell Cell Cell Cell Cell Cell Cell

    HTML

                                                
<div class="table-responsive">
    <table class="table"></table>
</div>

    Breakpoint specific

    Use .table-responsive{-sm|-md|-lg|-xl|-xxl} as needed to create responsive tables up to a particular breakpoint. From that breakpoint and up, the table will behave normally and not scroll horizontally.

    These tables may appear broken until their responsive styles apply at specific viewport widths.

    API Documentation

    Introduction

    Nimbus tables are a CSS-only component — no JavaScript initialisation is required. The base class .table enables all modifier classes and opts the element in to theme-aware custom properties. All colors, backgrounds, and borders resolve from CSS custom properties defined on .table so every variant automatically adapts in dark mode without additional class changes.

    All custom properties follow the --cnds-table-* namespace and are defined in css/components/tables.css. Theme overrides live in css/themes/light.css and css/themes/dark.css.

    Usage

    Apply .table to any <table> element. Layer modifier classes to add striping, hover, borders, sizing, or color variants. Wrap the table in a .table-responsive container for horizontal scrolling.

    HTML
    <div class="table-responsive">
    <table class="table table-striped table-hover">
        <thead>
            <tr>
                <th scope="col">#</th>
                <th scope="col">Name</th>
                <th scope="col">Status</th>
            </tr>
        </thead>
        <tbody>
            <tr>
                <th scope="row">1</th>
                <td>Mark Otto</td>
                <td>Active</td>
            </tr>
        </tbody>
    </table>
</div>

    CSS classes

    The following classes control table layout, color, sizing, and behaviour. All classes are CSS-only and require no JavaScript.

    CSS classes reference
    Class Applied to Description
    .table <table> Base class. Enables all custom properties and theme-aware colors. Required for all modifier classes to work.
    .table-striped <table> Zebra-stripes odd rows in <tbody> using --cnds-table-striped-bg.
    .table-striped-columns <table> Zebra-stripes even columns instead of rows.
    .table-hover <table> Highlights the hovered row using --cnds-table-hover-bg.
    .table-active <tr>, <td>, <th> Applies an active/selected highlight using --cnds-table-active-bg.
    .table-bordered <table> Adds borders to all four sides of every cell and the table.
    .table-borderless <table> Removes all internal and external borders.
    .table-sm <table> Halves cell padding to 0.25rem for dense layouts.
    .table-group-divider <thead>, <tbody>, <tfoot> Draws a thicker, darker border above the group section.
    .table-responsive wrapper <div> Enables horizontal scrolling on all viewports.
    .table-responsive-{sm|md|lg|xl|xxl} wrapper <div> Enables horizontal scrolling below the specified breakpoint only.
    .table-primary / .table-secondary / .table-success / .table-danger / .table-warning / .table-info / .table-light / .table-dark <table>, <tr>, <td>, <th> Contextual color variants. Each sets its own --cnds-table-bg, --cnds-table-color, and related tokens.
    .caption-top <table> Positions the <caption> above the table header instead of below.
    .align-middle / .align-top / .align-bottom <table>, <tr>, <td>, <th> Vertical alignment utilities. <thead> is always bottom-aligned; <tbody> inherits from the table.

    All custom properties are defined on .table in tables.css. Override them inline or via a CSS rule to customise individual tables or a global variant.

    Property Default (light) Description

    --cnds-table-bg var(--cnds-body-bg, #fff) Default background color of the table.
    --cnds-table-border-color var(--cnds-border-color, #dee2e6) Color of row-separator borders.
    --cnds-table-accent-bg transparent Used by striped and hover states as a base accent layer.
    --cnds-table-striped-color var(--cnds-body-color, #4f4f4f) Text color for striped rows.
    --cnds-table-striped-bg rgba(0, 0, 0, 0.05) Background for odd rows when .table-striped is applied.
    --cnds-table-active-color var(--cnds-body-color, #4f4f4f) Text color when .table-active is applied.

    Accessibility

    Follow these practices to ensure tables are accessible to all users including those using screen readers or keyboard navigation:

    • Use scope="col" on <th> in <thead> to associate header cells with columns.
    • Use scope="row" on <th> in <tbody> to associate header cells with rows.
    • Add a <caption> to give screen readers a summary of the table purpose before they read the data.
    • Icon-only action buttons must carry an aria-label describing the action (e.g., aria-label="Remove item"). Add aria-hidden="true" to the icon element itself.
    • Each checkbox in a selection column must have a unique id and a descriptive aria-label (e.g., aria-label="Select row 1").
    • Use color only as a secondary indicator — never as the sole means of conveying state. Add visually-hidden text or use aria-label where needed.
    • Avoid using overflow: hidden containers around dropdowns nested inside .table-responsive — these will be clipped.

    For tabular data in assistive technology contexts, see the WAI Tables Tutorial.
