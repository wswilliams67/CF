    v1Toggle Switch
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    A toggle switch is a binary control used to activate or deactivate a single setting. It behaves like an on/off physical switch — the action takes effect immediately, without requiring a form submission. Use a switch when the change is instant and self-contained; use a checkbox instead when the option is part of a larger form that is submitted together.

    Nimbus switches are built on the .form-check .form-switch pattern and support four distinct states: default, checked, disabled, and disabled-checked. Every state accepts an optional label and helper text.

    The sections below document core component patterns, followed by a real-world settings panel example that shows grouping, helper text, and disabled states working together.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Wrap an <input type="checkbox" role="switch"> and its <label> in a .form-check.form-switch container. The .form-switch modifier renders the pill-shaped track and animated thumb. Always include role="switch" so assistive technologies announce the control correctly; always pair the input with a <label> using matching for/id attributes. No JavaScript is required.

    HTML

    <!-- Default switch -->
<div class="form-check form-switch">
    <input class="form-check-input" type="checkbox" role="switch" id="basicSwitchDefault" />
    <label class="form-check-label" for="basicSwitchDefault">Default switch</label>
</div>

<!-- Checked switch -->
<div class="form-check form-switch">
    <input class="form-check-input" type="checkbox" role="switch" id="basicSwitchChecked" checked />
    <label class="form-check-label" for="basicSwitchChecked">Checked switch</label>
</div>

<!-- Disabled switch -->
<div class="form-check form-switch">
    <input class="form-check-input" type="checkbox" role="switch" id="basicSwitchDisabled" disabled />
    <label class="form-check-label" for="basicSwitchDisabled">Disabled switch</label>
</div>

<!-- Disabled checked switch -->
<div class="form-check form-switch">
    <input class="form-check-input" type="checkbox" role="switch" id="basicSwitchCheckedDisabled" checked disabled />
    <label class="form-check-label" for="basicSwitchCheckedDisabled">Disabled checked switch</label>
</div>

    Helper text

    Add a .form-text element inside the .form-check.form-switch wrapper to display supplementary context directly below the label. Helper text renders at 12 px in a muted secondary color. Use it to clarify what enabling the option does — one short sentence keeps it scannable.

    Receive a daily digest of your migration activity.
    Apply the dark color theme to all application views.

    HTML

    <div class="form-check form-switch">
    <input class="form-check-input" type="checkbox" role="switch"
        id="helperSwitchDefault" aria-describedby="helperSwitchDefaultDesc" />
    <label class="form-check-label" for="helperSwitchDefault">Email notifications</label>
    <div class="form-text" id="helperSwitchDefaultDesc">Receive a daily digest of your migration activity.</div>
</div>
<div class="form-check form-switch mt-3">
    <input class="form-check-input" type="checkbox" role="switch"
        id="helperSwitchChecked" checked aria-describedby="helperSwitchCheckedDesc" />
    <label class="form-check-label" for="helperSwitchChecked">Dark mode</label>
    <div class="form-text" id="helperSwitchCheckedDesc">Apply the dark color theme to all application views.</div>
</div>

    Error message

    Add an .invalid-feedback element after the .form-text to surface a validation error below the helper text. Apply .is-invalid to the <input> to show the error message and highlight the switch track border in the danger color. Use error messages to explain what went wrong and how to resolve it — for example, when a required setting must be enabled before a workflow can proceed.

    Receive a daily digest of your migration activity.
    Email notifications must be enabled to receive job alerts.
    Apply the dark color theme to all application views.
    This setting conflicts with your organisation's display policy.

    HTML

    <div class="form-check form-switch">
    <input class="form-check-input is-invalid" type="checkbox" role="switch"
        id="errorSwitchDefault" aria-invalid="true"
        aria-describedby="errorSwitchDefaultDesc errorSwitchDefaultFeedback" />
    <label class="form-check-label" for="errorSwitchDefault">Email notifications</label>
    <div class="form-text" id="errorSwitchDefaultDesc">Receive a daily digest of your migration activity.</div>
    <div class="invalid-feedback" id="errorSwitchDefaultFeedback">Email notifications must be enabled to receive job alerts.</div>
</div>

<div class="form-check form-switch mt-3">
    <input class="form-check-input is-invalid" type="checkbox" role="switch"
        id="errorSwitchChecked" checked aria-invalid="true"
        aria-describedby="errorSwitchCheckedDesc errorSwitchCheckedFeedback" />
    <label class="form-check-label" for="errorSwitchChecked">Dark mode</label>
    <div class="form-text" id="errorSwitchCheckedDesc">Apply the dark color theme to all application views.</div>
    <div class="invalid-feedback" id="errorSwitchCheckedFeedback">This setting conflicts with your organisation's display policy.</div>
</div>

    Disabled

    Add the HTML disabled attribute to prevent interaction. The Nimbus switch applies opacity: 0.5 and pointer-events: none to both the input and its sibling label, giving a consistent muted appearance across both disabled sub-states: off and on.

    Do not rely on aria-disabled alone; the native disabled attribute is required so the browser excludes the field from keyboard focus and form submission. Use disabled switches to indicate that a setting is locked by a higher-level permission or system constraint — always pair with explanatory text nearby so users understand why the control is inactive.

    HTML

    <!-- Disabled off -->
<div class="form-check form-switch">
    <input class="form-check-input" type="checkbox" role="switch" id="disabledSwitchOff" disabled />
    <label class="form-check-label" for="disabledSwitchOff">Disabled (off)</label>
</div>

<!-- Disabled on -->
<div class="form-check form-switch">
    <input class="form-check-input" type="checkbox" role="switch" id="disabledSwitchOn" checked disabled />
    <label class="form-check-label" for="disabledSwitchOn">Disabled (on)</label>
</div>

    Inline

    Add .form-check-inline to each .form-check.form-switch wrapper to arrange switches horizontally with a 24 px gap between them. Inline layout works well for 2–3 short options that fit comfortably on a single line. For more options, or when labels are longer, prefer the default stacked layout for better readability.

    HTML

    <div class="form-check form-switch form-check-inline">
    <input class="form-check-input" type="checkbox" role="switch" id="inlineSwitch1" />
    <label class="form-check-label" for="inlineSwitch1">Option A</label>
</div>
<div class="form-check form-switch form-check-inline">
    <input class="form-check-input" type="checkbox" role="switch" id="inlineSwitch2" checked />
    <label class="form-check-label" for="inlineSwitch2">Option B</label>
</div>
<div class="form-check form-switch form-check-inline">
    <input class="form-check-input" type="checkbox" role="switch" id="inlineSwitch3" disabled />
    <label class="form-check-label" for="inlineSwitch3">Option C (disabled)</label>
</div>

    Without labels

    When a visible label would be redundant — for example, a toggle in a dense settings table where the row heading already names the setting — keep the .form-check.form-switch wrapper but omit the .form-check-label. The switch must still have an accessible name; supply one via aria-label or aria-labelledby pointing to a visible heading. Never leave a switch without an accessible name — it cannot be operated by keyboard or assistive technology users.

    HTML

    <div class="mx-auto d-inline-flex flex-column gap-2">
    <div class="form-check form-switch">
        <input class="form-check-input" type="checkbox" role="switch"
            id="switchNoLabel1" aria-label="Enable feature A" />
    </div>
    <div class="form-check form-switch">
        <input class="form-check-input" type="checkbox" role="switch"
            id="switchNoLabel2" aria-label="Enable feature B" checked />
    </div>
</div>

    Settings panel

    Group related switches inside a <fieldset> with a <legend> when they share a common context — for example, a notification preferences panel. Each switch pairs with helper text to explain what enabling the option does, keeping the choice clear without external documentation. Use the disabled attribute for options that are locked by a plan or permission level, and always pair with explanatory helper text so users understand why the control is inactive.

    Introduction

    The Nimbus toggle switch is a CSS-only form component — no JavaScript initialization is required. It extends the native <input type="checkbox"> with a pill-shaped track and animated thumb, using CSS Grid layout internally so the label, helper text, and error message always align cleanly to the right of the switch regardless of content length. All interaction states — checked, disabled, and invalid — are driven by native HTML attributes, keeping the markup minimal and semantically correct. The component is fully theme-aware: track and thumb colors adapt automatically when data-cnds-theme="dark" is present on any ancestor element.

    Usage

    Wrap a <input type="checkbox"> and a <label> inside a <div class="form-check form-switch">. Apply role="switch" to the input so assistive technologies announce it as a toggle switch rather than a generic checkbox. Always pair the input with a visible <label> using matching for/id attributes, or supply an accessible name via aria-label when a visible label is intentionally omitted.

    HTML
    <div class="form-check form-switch">
    <input class="form-check-input" type="checkbox" role="switch" id="mySwitch" />
    <label class="form-check-label" for="mySwitch">Label text</label>
</div>

    CSS classes

    The following CSS classes are used to build and customize toggle switch components. All classes follow the Nimbus naming convention and require no JavaScript initialization.

    Class Description
    .form-check Wrapper element for the switch input and label pair. Provides the CSS Grid layout context (28 px switch column + 1fr label column).
    .form-switch Added to .form-check to render the pill-shaped track and animated thumb instead of a standard checkbox.
    .form-check-input Applied to the <input type="checkbox"> element. Replaces the browser default with the Nimbus switch track; use role="switch" alongside this class.
    .form-check-label Applied to the <label> element paired with the switch input. Pins to the label column of the CSS Grid.
    .form-check-inline Added to .form-check.form-switch to display switches horizontally in a row with a 24 px gap between each item.
    .form-text Helper text element placed after the label inside the wrapper. Pins to the label column and renders at 0.75 rem in a secondary muted color.
    .is-invalid Applied to .form-check-input to show the validation error state. Highlights the track border in the danger color and reveals any sibling .invalid-feedback element.
    .invalid-feedback Error message element placed after .form-text inside the wrapper. Hidden by default; shown when a sibling .form-check-input carries .is-invalid. Pins to the label column and inherits the same 0.75 rem font size as helper text.

    CSS custom properties

    Nimbus switches use CSS custom properties for theming. Override these variables to customize switch appearance across light and dark themes. Dark theme values are set in dark.css using the [data-cnds-theme="dark"] selector. Switch-specific properties are listed first; the switch also inherits all --cnds-form-check-input-* properties for track color and focus ring styling.

    Variable Default (Light) Dark Description
    --cnds-form-switch-bg SVG circle (off: rgba(0,0,0,0.25), focus: #355d97, on: #fff) SVG circle (off: #d1d1d1, on: #355d97) SVG data-URI for the switch thumb. Reassigned per state to change the thumb fill color. Dark theme values sourced from Figma (Surface/Form/Switch/Toggle/*).
    --cnds-form-check-input-border-color #787878 #787878 Track border color in the default (off) state. Dark theme switch uses the same value per Figma (Surface/Form/Switch/Border/Default).
    --cnds-surface-dark-300 — #4a4a4a Dark theme track background in the off state. Applied directly to .form-switch .form-check-input. Figma: Surface/Form/Switch/Background/Default.
    --cnds-surface-blue-300 — #8fadd6 Dark theme track background in the on state. Figma: Surface/Form/Switch/Background/Selected.
    --cnds-form-check-input-checked-bg #355d97 overridden by --cnds-surface-blue-300 Track fill color when the switch is on. Light theme uses blue-500; dark theme switch overrides this with blue-300 (#8fadd6).
    --cnds-surface-blue-400 — #6790ca Dark theme track border when the switch is on. Figma: Surface/Form/Switch/Border/Selected.

    --cnds-form-text-color #6c757d #a3a3a3 Color for helper text and error message text below switches.
    --cnds-form-text-font-size 0.75rem — Font size for helper text and error message text (12 px).

    JavaScript

    Nimbus switches are pure HTML/CSS components and do not require JavaScript initialization. The most common JavaScript interaction patterns are:

    • Reading or setting the checked state programmatically
    • Toggling the disabled state based on application logic
    • Listening for change events to react to user interaction

    Listening for change events

    JavaScript
    const toggle = document.getElementById('mySwitch');
toggle.addEventListener('change', function (event) {
    if (event.target.checked) {
        console.log('Switch is on');
    } else {
        console.log('Switch is off');
    }
});

    Setting state programmatically

    JavaScript
    const toggle = document.getElementById('mySwitch');

// Turn on
toggle.checked = true;

// Turn off
toggle.checked = false;

// Disable
toggle.disabled = true;

// Re-enable
toggle.disabled = false;

    Toggling all switches in a group

    JavaScript
    // Turn off all switches inside a fieldset
const fieldset = document.getElementById('notificationSettings');
fieldset.querySelectorAll('input[role="switch"]').forEach(function (sw) {
    sw.checked = false;
});

    Accessibility

    Nimbus switches are built with accessibility in mind. Follow these guidelines to ensure your switch implementations are accessible to all users:

    • Always add role="switch" to the <input> so assistive technologies announce it as a switch rather than a generic checkbox.
    • Always pair each <input> with a <label> using matching for/id attributes.
    • When a visible label would be redundant, use aria-label or aria-labelledby to provide an accessible name.
    • When helper text is present, add a unique id to the .form-text element and reference it on the input via aria-describedby. This ensures screen readers announce the helper text when the switch receives focus.
    • When an error message is present, add aria-invalid="true" to the input and include both the helper text ID and the .invalid-feedback ID in a space-separated aria-describedby value so screen readers announce both the context and the specific error.
    • Use <fieldset> and <legend> to group related switches so screen readers announce the group context before each option.
    • Use the native disabled attribute — not aria-disabled alone — to prevent keyboard focus and form submission on locked switches.
    • When a switch is disabled due to a plan or permission restriction, always provide visible explanatory text nearby so the reason is apparent without assistive technology.
    • Add aria-hidden="true" to all decorative icon elements (<i>) inside buttons or links that already carry an accessible name, to prevent screen readers from announcing icon class names.
    • Ensure sufficient color contrast between the switch track and page background in both the on and off states. See Theme variables for verified contrast values.
