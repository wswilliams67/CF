    v1 Input fields
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Input fields collect typed data from users. The Nimbus .cf-input-field wrapper component provides a consistent design across all text-based inputs — label, control, trailing icon, helper text, and error message — and adapts automatically to the active product theme and light/dark color scheme.

    Use the size modifiers .cf-input-field-sm and .cf-input-field-lg to match adjacent UI density. Apply .is-invalid to the wrapper to reveal inline error messaging without JavaScript. For multi-line text entry use the Textarea component; for bounded numeric ranges use Range or Multi Range Slider.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    A basic input field uses a static label above the control, wrapped in .cf-input-field. The .cf-input-wrapper positions the trailing icon, and .cf-input-helper holds helper and counter text below the field.

    HTML
                                    
<div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="form12">Example label</label>
    <div class="cf-input-wrapper">
        <input type="text" id="form12" class="cf-input-control" placeholder="Placeholder text" />
    </div>
</div>

    Product themes

    Each Cloudficient product has a designated accent color defined in the design system. Setting a product class on <body> activates that color for all input fields at once:

    Add .cf-input-counter inside .cf-input-helper and set the maxlength attribute. Use a small script to update the counter as the user types.

    Keep it concise. 0/20

    Icons

    Trailing icon

    Add an i element with class .cf-input-icon inside .cf-input-wrapper to render a trailing icon inside the input field. The input gets right padding automatically to avoid overlap.

    HTML
                                        
<div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="form1">Example label</label>
    <div class="cf-input-wrapper">
        <input type="text" id="form1" class="cf-input-control" placeholder="Enter value" />
        <i class="mdi mdi-information cf-input-icon"></i>
    </div>
</div>

    Clear button

    Add a button with class .cf-input-clear inside .cf-input-wrapper to let the operator empty the field. Show it only once the field holds a value. Unlike .cf-input-icon it is interactive, so it takes pointer events and lifts to full opacity on hover and keyboard focus — give it an aria-label. Add data-cnds-input-clear-init to the input and Nimbus wires the behaviour: the control appears only while the field has a value, clicking it empties the field, dispatches a native input event so anything already listening reacts as it does to typing, and returns focus to the field. Use type="text", not type="search" — the search type paints the browser’s own clear control, which differs per browser and is not the design system’s icon.

    It renders at --cnds-icon-sm (16px) at every field size: the clear is a constant affordance rather than part of the field's semantic icon scale, which tracks the field size through MD / SM / ML. When a trailing icon is also present the clear sits to its left with an 8px gap, and the control reserves enough right padding that the value stops 8px short of it and truncates with an ellipsis rather than sliding underneath.

    HTML
                                        
<div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="clear1">Example label</label>
    <div class="cf-input-wrapper">
        <input type="text" id="clear1" class="cf-input-control" value="Byrne-Halloran, Jenny" />
        <button type="button" class="mdi mdi-close-circle cf-input-clear" aria-label="Clear field" hidden></button>
        <i class="mdi mdi-information cf-input-icon"></i>
    </div>
</div>

    API Documentation

    Introduction

    The Nimbus input field component is CSS-only — no JavaScript initialisation is required. Structure, states, and size variants are controlled entirely through HTML classes and attributes applied to the wrapper and control elements. The component is fully theme-aware: background, border, and text colors adapt automatically when data-cnds-theme="dark" is present on any ancestor element.

    Usage

    Wrap the label, input wrapper, and helper row inside .cf-input-field. The focus-ring color is set automatically by the page-level product class on <body>. Add a product modifier class (e.g. .cf-input-field-casefusion) directly on the wrapper only when a field needs an accent independent of the body class. Always associate the label with the control via matching for / id values, and link helper or error text with aria-describedby.

    HTML
    <div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="id">Label</label>
    <div class="cf-input-wrapper">
        <input type="text" id="id" class="cf-input-control"
               placeholder="Placeholder" aria-describedby="id-helper" />
    </div>
    <div class="cf-input-helper">
        <span id="id-helper" class="cf-input-helper-text">Help text</span>
        <span class="cf-input-error">An error has occurred.</span>
    </div>
</div>

    CSS classes

    The following classes control input field structure and appearance. All classes are CSS-only and require no JavaScript.

    Class Element Description
    .cf-input-field <div> Root wrapper. Vertical flex layout with 4px gap between label, field, and helper row.
    .cf-input-field-sm <div> Small size modifier on the wrapper. Label 13px Bold, control 13px, vertical padding 12px, horizontal padding 12px.
    .cf-input-field-lg <div> Large size modifier on the wrapper. Label 16px Bold, control 16px, vertical padding 14px, horizontal padding 24px.
    .cf-input-field-casefusion <div> Sets --cnds-product-accent locally to CaseFusion green, overriding the page-level body class. Focus ring: var(--cnds-product-casefusion-green-700) light / var(--cnds-product-casefusion-green-400) dark.
    .cf-input-field-hyperlize <div> Sets --cnds-product-accent locally to Hyperlize gold, overriding the page-level body class. Focus ring: var(--cnds-product-hyperlize-orange-700) light / var(--cnds-product-hyperlize-orange-400) dark.
    .cf-input-field-expireon <div> Sets --cnds-product-accent locally to Expireon indigo, overriding the page-level body class. Focus ring: var(--cnds-product-expireon-blue-500) light / var(--cnds-product-expireon-blue-200) dark.
    .is-invalid <div> Error state on the wrapper. Makes .cf-input-error visible, stacked below helper text. Does not change the control border or shadow.
    .cf-input-label <label> Static label above the control. 14px ExtraBold, letter-spacing −0.2px (default size).
    .cf-input-wrapper <div> Positions the trailing icon absolutely within the field. Always wraps .cf-input-control.
    .cf-input-control <input> The form control. Applies border, background, padding, and typography tokens. Works with any <input> type.
    .cf-input-icon <i> Trailing icon inside .cf-input-wrapper. Positioned absolutely at the right edge. Automatically adds right padding to the control to prevent overlap.
    .cf-input-clear <button> Interactive clear control inside .cf-input-wrapper. 16px (--cnds-icon-sm) at every field size. Sits left of .cf-input-icon with an 8px gap when both are present; otherwise takes the icon's position. Show only when the field has a value, and give it an aria-label.
    data-cnds-input-clear-init Behaviour hook, placed on the input. Nimbus shows the clear only while the field has a value, empties the field on click, dispatches a native input event, and returns focus to the field. Fires cleared.cnds.input-clear. Without it the button is styled but inert.
    .cf-input-helper <div> Helper row below the field. Grid layout: helper text and error stack vertically in the left column; counter sits in the right column.
    .cf-input-helper-text <span> Guidance text. Always visible — remains shown in the error state, stacked above the error message.
    .cf-input-error <span> Validation error message. Hidden by default; shown when .is-invalid is on the wrapper.
    .cf-input-counter <span> Character counter at the right of the helper row. Update via JavaScript as the user types.
    .cf-input-required <span> Required asterisk inside the label. Renders in the CaseFusion green brand color.

    Accessibility

    The following practices are required for an accessible input field implementation:

    • Always use a visible <label> with a matching for attribute linked to the control's id. Do not rely on placeholder as a label substitute.
    • Add aria-describedby on the control pointing to the id of .cf-input-helper-text and/or .cf-input-error so screen readers announce helper and error text when the field receives focus.
    • When showing a required field, add required (or aria-required="true") to the control in addition to the visual .cf-input-required asterisk in the label.
    • Disabled fields are announced as disabled by the browser — no additional ARIA is needed. Avoid disabling fields that contain information users may need to read.
