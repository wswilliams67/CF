    v1 Shadows
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Nimbus™ shadow utilities provide a complete, layered elevation system for your application's visual hierarchy. The system offers five numbered shadow levels (.shadow-1 through .shadow-5), semantic size aliases (.shadow-sm, .shadow-md, .shadow-lg), strong theme-aware variants (.shadow-*-strong) for dark surfaces and images, an inset inner shadow (.shadow-inner), hover transition classes (.hover-shadow, .shadow-*-hover), and 25 Material Design depth levels (.z-depth-{n}-vcds). All standard numbered shadows reference CSS custom property tokens (--cnds-shadow-*) so they automatically adapt to light and dark themes with zero JavaScript.

    Choosing the right shadow level depends on the perceived elevation of an element. Use no shadow or .shadow-0 for flat surfaces that are part of the page background. Use .shadow-sm / .shadow-1 for subtle lifts on items like table rows or list panels. Use .shadow-2 or .shadow-md for cards and content panels that should clearly float above the page. Reserve .shadow-lg / .shadow-4 and .shadow-5 for high-priority overlays, sticky toolbars, and modal dialogs that need strong visual separation. Inset shadows (.shadow-inner) are ideal for form input wells and pressed-state effects. Strong variants (-strong) use theme-aware color tokens and are recommended whenever the shadowed surface is dark, image-based, or needs to stand out in both light and dark themes.

    Inner shadow

    Use the .shadow-inner utility to apply a subtle inset box shadow to an element. This can be useful for things like form controls, input wells, or pressed-state affordances where you want the element to appear sunken into the page rather than elevated above it.

    HTML

    <div class="shadow-inner"></div>

    Shadow hover effect

    By adding .hover-shadow class to the element you can apply a shadow hover effect with a smooth transition: box-shadow 0.3s ease-in-out. Use numbered variants like .shadow-3-hover to target a specific elevation level on hover.

    HTML

    <img
  src="img/cf/styleguide/card-image.png"
  class="img-fluid hover-shadow"
  alt="..."
  style="width: 24rem"
/>

    Images with shadow

    Theoretically, depending on the brightness of the image you should use standard or strong shadow. However, practical use shows that strong shadows work better in most cases with images because they use theme-aware color tokens that remain legible against both light and dark page backgrounds.

    HTML

    <img src="img/cf/styleguide/card-image.png" class="img-fluid shadow-4-strong" alt="..." />

    Accessibility

    Box shadows are a purely visual technique and carry no semantic meaning for assistive technologies. Follow the guidance below to ensure shadowed elements remain accessible under Section 508 and WCAG 2.1 requirements.

    High-contrast mode

    In Windows High Contrast mode and forced-color environments, box-shadow is suppressed by the browser. Never rely on a shadow as the only visual cue to indicate an element boundary, interactive state, or active selection. Always pair shadows with a visible border or a meaningful foreground-color change so the element remains distinguishable when shadows are absent. Use CSS @media (forced-colors: active) to provide explicit fallback styles if the default border is not sufficient.

    Interactive state indication

    Hover shadow effects (.hover-shadow, .shadow-*-hover) communicate interactive affordance visually. Because shadows disappear in high-contrast mode, interactive elements must also provide a cursor: pointer style and, where appropriate, a :focus-visible outline so keyboard users receive the same affordance as pointer users. Do not use shadow alone to distinguish a focused or selected state.

    Contrast for shadowed content

    The content inside a shadowed element must still meet the WCAG AA minimum contrast ratio of 4.5:1 for normal text or 3:1 for large text against the element's background color. The shadow itself does not affect the contrast calculation between text and its immediate background.

    Shadow as decoration

    When shadows are applied purely for aesthetic layering (e.g., depth in a hero section), no additional ARIA attributes are needed. When a shadow visually groups or separates a distinct region of content, wrap that region in a <section> or add role="region" with an aria-label so assistive technologies can identify the boundary through markup rather than visual styling.

    API Documentation

    Introduction

    The Nimbus shadow utilities are a comprehensive set of CSS-only classes that apply box-shadow styles to any HTML element. No JavaScript initialization is required. Classes cover standard shadows, strong theme-aware shadows for dark elements, semantic size aliases, hover transition effects, an inset inner shadow, and 25 Material Design depth levels specific to the Nimbus™ design language. Standard numbered shadows reference CSS custom property tokens (--cnds-shadow-*) so they automatically adapt to light and dark themes.

    Usage

    Shadow utilities are applied directly as CSS classes on any HTML element. No JavaScript initialization is required. Combine a shadow class with any other utility class to achieve the desired effect.

    HTML
    <!-- Standard shadow -->
<div class="shadow-3">...</div>

<!-- Strong shadow for dark or image elements -->
<div class="shadow-4-strong">...</div>

<!-- Remove shadow -->
<div class="shadow-0">...</div>

<!-- Inner (inset) shadow -->
<div class="shadow-inner">...</div>

<!-- Hover shadow on an image -->
<img src="..." class="img-fluid hover-shadow" alt="..." />

<!-- Targeted hover shadow level -->
<div class="shadow-2-hover">...</div>

<!-- Nimbus depth shadow -->
<div class="z-depth-4-vcds">...</div>

    Accessibility

    The following requirements apply to accessible use of shadow utilities under Section 508 and WCAG 2.1:

    • Supplement, don't replace borders. Always pair a shadow with a visible border on interactive or grouped elements. Shadows are suppressed in Windows High Contrast / forced-colors mode; the border provides the fallback visual boundary.
    • Never use shadow alone for interactive state. A hover or focus shadow must be accompanied by a cursor change and a :focus-visible outline so keyboard users receive an equivalent affordance to pointer users.
    • Content contrast is independent of shadow. The WCAG AA contrast ratio (4.5:1 normal text, 3:1 large text) applies between text and its immediate background color — the surrounding shadow does not factor into this calculation.
    • Region boundaries via markup. When a shadow visually groups a distinct region of content, encode the boundary in HTML using <section> or role="region" with aria-label so the grouping is available to assistive technologies regardless of visual rendering.
    • Forced-colors fallback. Use @media (forced-colors: active) to provide explicit border or outline fallbacks on elements that rely on shadow for visual separation in your component stylesheets.
