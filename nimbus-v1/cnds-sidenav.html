    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The Sidenav provides persistent, structured navigation for the main sections and pages of an application. It supports three display modes — overlay (slides over content), push (shifts content aside), and side (fixed alongside content) — and can be collapsed to a slim icon-only ribbon to reclaim horizontal space. Categories expand and collapse in accordion style so users can focus on the active section without the nav becoming crowded.

    Product themes (CaseFusion, Hyperlize, ExpireOn) supply the active highlight color. The component derives all other colors from CNDS semantic tokens and automatically adapts to light and dark themes without any additional configuration.

    Note: Read the API Documentation to find all available options, data attributes, CSS custom properties, and JavaScript instance methods.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    The demo below shows the Sidenav in its two width states. Click the hamburger button to toggle between the full-width and slim (icon-only) modes. In slim mode the nav collapses to show only icons, with labels appearing as tooltips on hover. Clicking a nav item marks it as active with a product-themed highlight and a left accent bar; when a child item is active, its parent category inherits a lighter highlight without the accent bar. Use the product switcher to preview the active-state color scheme for each Cloudficient product.

    The Nimbus application template ships with a working Sidenav implementation. Add your navigation structure following the naming conventions in the next section, then set the two initialization variables described in the Initialization section to automatically mark the correct page and category on load.

    Naming Navigation Items

    Correct naming of Sidenav elements is required for the component's JavaScript to automatically mark the active page and expand the correct category on load. The structure is a nested unordered list: top-level items are either direct navigation links or expandable category toggles that contain a child list.

    Three attributes on each element must follow a strict naming convention: the title, data-original-title, and id attributes must all share the same unique identifier value. This is how the initialization script knows which item and category to highlight when the page loads.

    Main Nav Container

    The nav element is pre-configured with the id, class, and data-cnds-* attributes the component requires. Copy it as-is from the application template. The id (sidebar-cf), the mode and accordion settings, and the content target (data-cnds-content) must not be changed — the initialization script and the slim-toggler depend on them.

    Top Level Items

    The navigation menu is a ul with the class sidenav-menu. Each direct child li represents one top-level navigation item and carries the class sidenav-item.

    Each li must have both a title and a data-original-title attribute set to the same unique value — this value is the item's identifier and is used by the slim-mode tooltip and the initialization script.

    Inside each li is an anchor (a) with an id prefixed with navlink_. This prefix must not be changed. The portion after the prefix must exactly match the identifier used in that item's title and data-original-title attributes. Each identifier must be unique across the entire navigation.

    Category Items

    Categories group related navigation links under a collapsible heading. A category is not itself a navigation link — it is an accordion toggle that expands or collapses its child list. By default the Sidenav operates in accordion mode: opening one category automatically closes any other that is open.

    The li and its title / data-original-title attributes follow the same naming convention as top-level items. The key difference is the id prefix on the anchor: category toggles use tog_submenu_ instead of navlink_. The anchor also requires data-cnds-toggle="sidenav-collapse" and an initial aria-expanded value. The sibling ul must carry the class sidenav-collapse.

    Child items inside the sidenav-collapse list follow exactly the same naming pattern as top-level items — each li has matching title and data-original-title values, and each anchor uses the navlink_ prefix with the same identifier. All identifiers across the entire navigation must remain unique.

    Initialization

    The Sidenav initializes after the full page load. The application template is pre-configured to handle this — no additional setup is required beyond setting two page-level JavaScript variables. These variables tell the initialization script which category to expand and which item to mark as active when the page loads. This is where the naming convention pays off.

    In the JavaScript section at the bottom of the application template, set the following two variables before the page loads:

    JAVASCRIPT

    var sidenavSection = "";
var sidenavTopic = "";

    sidenavSection is the identifier of the category the current page belongs to — the portion of the tog_submenu_ anchor's id after the prefix. sidenavTopic is the identifier of the current page's nav link — the portion of the navlink_ anchor's id after the prefix. Both values must exactly match their corresponding identifiers in the navigation markup.

    Note: If the variables are left blank the application will assume this is the home screen and mark the Sidenav accordingly.

    Using the list example from earlier, we set the variables to their corresponding values.

    HTML

    <li class="sidenav-item" title="CategoryName1" data-original-title="CategoryName1">
    <a id="tog_submenu_CategoryName1" class="sidenav-link ps-4"
       data-cnds-toggle="sidenav-collapse" aria-expanded="false">
        <i class="mdi mdi-view-grid mdi-18px me-2"></i>
        <span>Category 1</span>
        <span class="mdi mdi-chevron-down sidenav-chevron" aria-hidden="true"></span>
    </a>
    <ul class="sidenav-collapse">
        <li class="sidenav-item" title="Link1" data-original-title="Link1">
            <a id="navlink_Link1" class="sidenav-link ps-4" href="#">
                <i class="mdi mdi-grid mdi-18px me-2"></i>
                <span>Link 1</span>
            </a>
        </li>
    </ul>
</li>

    JAVASCRIPT

    var sidenavSection = "CategoryName1";
var sidenavTopic = "Link1";

    Keep the navigation structure as simple as possible. One level of nesting — a category with its child links — is the recommended maximum. Deeper nesting makes the Sidenav harder to scan and is not supported by the slim-mode tooltip behavior.

    API Documentation

    Introduction

    The Nimbus Sidenav is a JavaScript-driven component registered as Nimbus.Sidenav. It is initialized automatically by nimbus.js for any <nav> element that carries data-cnds-mode. The component manages three display modes (overlay, push, side), slim/icon-only mode, submenu accordion behavior, backdrop, and keyboard dismissal. All behavior is configurable via data-cnds-* attributes on the <nav> element or via options passed to the constructor. The component dispatches lifecycle events and exposes instance methods for programmatic control.

    Usage

    Place the <nav> element as a direct sibling of your main content wrapper. Set data-cnds-mode to choose how the sidenav interacts with surrounding content. The component is initialized automatically on page load; no additional JavaScript is required. Use data-cnds-content to point to the content element that should shift when the nav opens in push or side mode.

    HTML
    <nav id="sidebar-cf" class="sidenav"
     data-cnds-mode="side"
     data-cnds-slim="false"
     data-cnds-slim-collapsed="false"
     data-cnds-content="#slim-content"
     data-cnds-accordion="true"
     aria-label="Application navigation">
    <!-- sidenav content injected by sidenav-loader.js -->
</nav>
<div id="slim-content">
    <!-- page content -->
</div>

    Data attributes

    All options can be set declaratively via data-cnds-* attributes on the <nav> element. Values are read at initialization time and merged with any options passed to the constructor.

    Attribute Type Default Description
    data-cnds-mode string "over" Display mode. "over" — slides over content with backdrop; "push" — shifts content aside; "side" — fixed alongside content.
    data-cnds-accordion boolean true When true, opening one category automatically closes all others.
    data-cnds-slim boolean false Initializes the sidenav in slim (icon-only) mode.
    data-cnds-slim-collapsed boolean false Runtime flag written by the slim toggler. Reflects current slim state; read by the initialization script.
    data-cnds-content string — CSS selector for the content element to push or margin when in "push" mode.
    data-cnds-backdrop boolean true Show a backdrop overlay when the sidenav is open in "over" mode. Clicking the backdrop closes the sidenav.
    data-cnds-keyboard boolean true Close the sidenav when the Escape key is pressed.

    CSS classes

    The following classes control sidenav structure and appearance. All structural classes are required for correct behavior; modifier classes are optional.

    Class Element Description
    .sidenav <nav> Base class. Positions the sidenav fixed to the left edge, sets width, height, background, and transition.
    .sidenav.show <nav> Toggles the sidenav into its visible state (transform: translateX(0)).
    .sidenav-right <nav> Modifier. Anchors the sidenav to the right edge instead of the left.
    .sidenav-slim <nav> Modifier. Collapses width to icon-only mode (70px). Labels are hidden; tooltips activate on hover.
    .sidenav-menu <ul> The navigation list container. Required on the top-level <ul> inside the sidenav.
    .sidenav-item <li> Each navigation list item.
    .sidenav-link <a> Navigation link or category toggle. Provides hover, focus, and active styles.
    .sidenav-link.active <a> Marks the current page item. Applies the product accent bar and highlight background.
    .sidenav-collapse <ul> Collapsible child list inside a category item. Hidden by default; toggled by the parent .sidenav-link.
    .sidenav-collapse.show <ul> Expanded state of a category submenu.
    .sidenav-header <div> Optional header area at the top of the sidenav — typically contains the slim-toggle button or a logo.
    .sidenav-divider <hr> or <li> Horizontal rule separating groups of navigation items.
    .sidenav-subheading <span> Uppercase label that groups related items visually. Not a navigation target.
    .sidenav-backdrop <div> Injected by the component in "over" mode. Clicking it closes the sidenav.
    .sidenav-content <div> Content sibling whose left margin is adjusted in "push" mode.

    CSS custom properties

    All custom properties are defined on .sidenav in sidenav.css and can be overridden per-instance via an inline style attribute or globally via a CSS rule targeting .sidenav.

    Property Default Description
    --cnds-sidenav-width 240px Full-width of the sidenav. Override on .sidenav-slim to change the collapsed width (default slim: 70px).
    --cnds-sidenav-bg #fff Background color. Theme overrides this to --cnds-surface-light-200 in light and --cnds-surface-dark-500 in dark mode.
    --cnds-sidenav-color #4f4f4f Default text and icon color for navigation links.
    --cnds-sidenav-padding-y 0.5rem Top and bottom padding of the sidenav container.
    --cnds-sidenav-padding-x 0 Left and right padding of the sidenav container.
    --cnds-sidenav-transition transform 0.3s ease-in-out, width 0.3s ease-in-out CSS transition applied to open/close and slim/expand animations.
    --cnds-sidenav-zindex var(--cnds-zindex-offcanvas, 1045) Stack order. Ensure this exceeds any fixed headers or modals it should appear above.

    Theme variables

    The sidenav adapts to the active theme via custom properties overridden in dark.css on the [data-cnds-theme="dark"] .sidenav selector. All values meet WCAG AA contrast requirements against their respective theme backgrounds.

    Token Light value Light contrast Dark value Dark contrast

    Instance methods

    Retrieve the component instance with Nimbus.Sidenav.getInstance(element) or create one with Nimbus.Sidenav.getOrCreateInstance(element, options). All methods return the instance for chaining.

    Method Description
    .toggle() Toggles the sidenav between the shown and hidden states.
    .show() Opens the sidenav. Fires show.cnds.sidenav before and shown.cnds.sidenav after the transition.
    .hide() Closes the sidenav. Fires hide.cnds.sidenav before and hidden.cnds.sidenav after the transition.
    .toggleSlim() Toggles the .sidenav-slim class, switching between full-width and icon-only modes.
    .dispose() Destroys the component instance, removes event listeners, and removes the backdrop if present.
    JAVASCRIPT
    var el = document.getElementById('sidebar-cf');

// Get the existing instance (null if not yet initialized)
var sidenav = Nimbus.Sidenav.getInstance(el);

// Or create one programmatically with options
var sidenav = Nimbus.Sidenav.getOrCreateInstance(el, {
    mode: 'side',
    accordion: true,
    backdrop: false
});

// Instance methods
sidenav.show();
sidenav.hide();
sidenav.toggle();
sidenav.toggleSlim();
sidenav.dispose();

    Events

    The component fires four lifecycle events on the <nav> element. All events are cancelable: calling event.preventDefault() in a show or hide handler stops the transition from beginning.

    Event Fires when…
    show.cnds.sidenav The sidenav is about to open (before the CSS transition starts).
    shown.cnds.sidenav The sidenav has fully opened (after the CSS transition ends).
    hide.cnds.sidenav The sidenav is about to close (before the CSS transition starts).
    hidden.cnds.sidenav The sidenav has fully closed (after the CSS transition ends).
    JAVASCRIPT
    var el = document.getElementById('sidebar-cf');

el.addEventListener('show.cnds.sidenav', function (event) {
    // Cancel the open by calling event.preventDefault()
    console.log('Sidenav is about to open');
});

el.addEventListener('shown.cnds.sidenav', function () {
    console.log('Sidenav is now fully visible');
});

el.addEventListener('hide.cnds.sidenav', function () {
    console.log('Sidenav is about to close');
});

el.addEventListener('hidden.cnds.sidenav', function () {
    console.log('Sidenav is fully hidden');
});

    Accessibility & Section 508

    The following requirements apply to all Sidenav implementations. The demos on this page are configured to meet these requirements.

    • The <nav> element creates a navigation landmark automatically. Add aria-label="Application navigation" to distinguish it from other navigation regions on the page (header, breadcrumbs, right sidebar).
    • The current page link must carry aria-current="page". The initialization script applies this attribute automatically based on sidenavTopic.
    • Category toggle anchors must carry aria-expanded="false" initially and aria-expanded="true" when their submenu is open. The component manages this attribute automatically.
    • The slim-toggle button must have aria-label="Toggle slim mode" since its only visible content is an icon. The icon itself must carry aria-hidden="true" to prevent it being announced by screen readers.
    • In "over" mode (drawer), add a focus trap so keyboard users cannot reach content behind the open sidenav. The data-cnds-keyboard="true" attribute enables Escape to dismiss; implement a focus trap in your application shell for full Section 508 compliance.
    • All nav link text must meet WCAG 2.1 AA contrast requirements (minimum 4.5:1 for normal text). See Theme variables for verified contrast ratios.
    • Icons within links must carry aria-hidden="true" — the link's visible text label is the accessible name. Never use icon-only links without a tooltip or visually hidden label.

    For the WAI-ARIA navigation landmark specification, see the WAI-ARIA Authoring Practices — Navigation Landmark.
