    v1 Search
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The Nimbus search component is a composable UI pattern for building search inputs that can be paired with icons, buttons, or clear controls. The base element is a standard <input type="search"> styled through Nimbus form classes. It integrates cleanly with the .input-group wrapper to add prefix icons or suffix buttons, and with the .cf-input-field pattern to produce a Nimbus-branded floating-label field.

    Use the search component anywhere a user needs to filter or find content — in navbars, data table toolbars, sidenav headers, and standalone search pages. Three size modifiers (.cf-input-field-sm, default, .cf-input-field-lg) let you match the input to the surrounding layout density. All variants are fully theme-aware and adapt to light and dark modes automatically via CSS custom properties.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    A basic example with a simple button.

    HTML

                                    
<div class="input-group form-outline-casefusion">
    <input type="search" id="search-input" class="form-control" placeholder="Search" aria-label="Search" />
    <button type="button" class="btn btn-primary">
        <i class="mdi mdi-magnify mdi-18px"></i>
    </button>
</div>

    Autocomplete

    By adding extra JS code you can make your search input autocomplete as well.

    Learn more about Autocomplete in the Autocomplete Docs

    HTML

                                    
<div id="search-autocomplete" class="input-group form-outline-casefusion">
    <input type="search" id="search-autocomplete-input" class="form-control" placeholder="Search" aria-label="Search" />
    <button type="button" class="btn btn-primary">
        <i class="mdi mdi-magnify mdi-18px"></i>
    </button>
</div>

    JAVASCRIPT

                                    
const basicAutocomplete = document.querySelector('#search-autocomplete');
const data = ['One', 'Two', 'Three', 'Four', 'Five'];
const dataFilter = (value) => {
  return data.filter((item) => {
    return item.toLowerCase().startsWith(value.toLowerCase());
  });
};

new Nimbus.Autocomplete(basicAutocomplete, {
  filter: dataFilter
});

    Focus

    You can make your input in search component focusable by pressing ctrl + alt shortcut. You are able to easily change combinations of shortcuts by modifing keys array in JS code. For example to change ControlLeft to e key just swap it to KeyE etc.

    HTML

                                    
<div class="input-group form-outline-casefusion">
    <input id="search-focus" type="search" class="form-control" placeholder="Search" aria-label="Search" />
    <button type="button" class="btn btn-primary">
        <i class="mdi mdi-magnify mdi-18px"></i>
    </button>
</div>

    JAVASCRIPT

                                    
const searchFocus = document.getElementById('search-focus');
const keys = [
  { keyCode: 'AltLeft', isTriggered: false },
  { keyCode: 'ControlLeft', isTriggered: false },
];

window.addEventListener('keydown', (e) => {
  keys.forEach((obj) => {
    if (obj.keyCode === e.code) {
      obj.isTriggered = true;
    }
  });

  const shortcutTriggered = keys.filter((obj) => obj.isTriggered).length === keys.length;

  if (shortcutTriggered) {
    searchFocus.focus();
  }
});

window.addEventListener('keyup', (e) => {
  keys.forEach((obj) => {
    if (obj.keyCode === e.code) {
      obj.isTriggered = false;
    }
  });
});

        <li><a class="dropdown-item" href="#">Action</a></li>
        <li><a class="dropdown-item" href="#">Another action</a></li>
        <li><a class="dropdown-item" href="#">Something else here</a></li>
    </ul>

    JAVASCRIPT

                                    
const searchInputDropdown = document.getElementById('search-input-dropdown');
const dropdownOptions = searchInputDropdown
  .closest('.dropdown-menu')
  .querySelectorAll('.dropdown-item');

searchInputDropdown.addEventListener('input', () => {
  const filter = searchInputDropdown.value.toLowerCase();
  showOptions();
  const valueExist = !!filter.length;

  if (valueExist) {
    dropdownOptions.forEach((el) => {
      const elText = el.textContent.trim().toLowerCase();
      const isIncluded = elText.includes(filter);
      if (!isIncluded) {
        el.style.display = 'none';
      }
    });
  }
});

const showOptions = () => {
  dropdownOptions.forEach((el) => {
    el.style.display = '';
  })
}

    API Documentation

    Introduction

    The Nimbus search component is built on the native HTML <input type="search"> element. For basic use — a standalone input with an icon or button — no JavaScript initialisation is required. Floating-label behaviour is applied automatically by app.js to every .form-outline .form-control on the page; the data-cnds-input-init attribute on the wrapper is a semantic convention used throughout the design system to mark managed inputs. To add autocomplete suggestions, create a Nimbus.Autocomplete instance on the .form-outline wrapper element. The component is fully theme-aware: input borders and focus rings adapt automatically when the data-cnds-theme="dark" attribute is present on the <html> element. Product-specific focus colors are available through the .form-outline-casefusion, .form-outline-hyperlize, and .form-outline-expireon modifier classes.

    Usage

    Wrap a .form-outline element with data-cnds-input-init inside an .input-group. Apply type="search" to the input so the browser exposes a native clear button. Pair every input with a <label> using a matching for attribute. Optionally append a search button or icon inside the .input-group.

    HTML
    <div class="input-group">
    <div class="form-outline" data-cnds-input-init>
        <input id="search-input" type="search" class="form-control" />
        <label class="form-label" for="search-input">Search</label>
    </div>
    <button type="button" class="btn btn-primary">
        <i class="mdi mdi-magnify mdi-18px"></i>
    </button>
</div>

    To activate autocomplete, pass the wrapper to Nimbus.Autocomplete after the DOM has loaded:

    JAVASCRIPT
    const data = ['Result one', 'Result two', 'Result three'];

new Nimbus.Autocomplete(
  document.querySelector('#search-autocomplete'),
  {
    filter: (value) => data.filter(
      (item) => item.toLowerCase().includes(value.toLowerCase())
    )
  }
);

    JavaScript API

    Initialise the component by passing the .form-outline wrapper element and an options object to the constructor. All options except filter are optional.

    JAVASCRIPT
    const ac = new Nimbus.Autocomplete(element, options);

    Options

    Option Type Default Description
    filter Function null Required. Receives the current input value (string) and returns an array of suggestion items or a Promise<array>. The component shows a loading spinner while a Promise is pending.
    displayValue Function identity Maps each suggestion item to the string displayed in the list and written to the input when selected. Defaults to the item value itself.
    threshold number 0 Minimum number of characters the user must type before the filter function is called.
    itemContent Function null Returns an HTML string used as the inner content of each suggestion <li>. Use for rich item rendering (e.g. icons, secondary text). When omitted the displayValue string is used as plain text.
    customContent string "" HTML string appended to the dropdown footer — use for "Show all results" links or other persistent footer content.
    autoSelect boolean false When true, pressing Tab confirms the highlighted suggestion rather than closing the dropdown.
    container string "body" CSS selector for the element that the dropdown is appended to. Change this when the default body append causes z-index or overflow clipping issues.
    listHeight number 190 Maximum height of the suggestion list in pixels. Exceeding items scroll within the panel.

    Data attributes

    Three options can alternatively be set via data-cnds-* attributes on the wrapper element, which is useful when initialising from markup rather than JavaScript.

    Attribute Corresponding option Type
    data-cnds-threshold threshold integer string
    data-cnds-list-height listHeight integer string
    data-cnds-autoselect autoSelect "true"

    Instance methods

    Method Description
    ac.open() Programmatically runs the filter with the current input value and opens the dropdown.
    ac.close() Closes the dropdown and removes it from the DOM. Fires close.cnds.autocomplete.
    ac.dispose() Tears down all event listeners and removes the loader element. Call this before removing the input from the DOM.

    Static methods

    Method Description
    Nimbus.Autocomplete.getInstance(element) Returns the existing Autocomplete instance attached to element, or null if none has been created.
    Nimbus.Autocomplete.getOrCreateInstance(element, options) Returns the existing instance or creates and returns a new one with the provided options.

    Events

    All events bubble and are dispatched on the .form-outline wrapper element.

    Event Detail Description
    update.cnds.autocomplete event.detail.results Fired after the filter runs. results is the array returned by the filter function (empty array on error).
    open.cnds.autocomplete — Fired when the dropdown is rendered and visible.
    close.cnds.autocomplete — Fired when the dropdown is closed, whether by user interaction, ac.close(), or Escape.
    itemSelect.cnds.autocomplete event.detail.value Fired when a suggestion is confirmed. value is the original item from the filter result array.

    Keyboard navigation

    Key Action
    ↓ Arrow Down Move focus to the next suggestion item.
    ↑ Arrow Up Move focus to the previous suggestion item.
    Enter Confirm the currently highlighted item.
    Escape Close the dropdown and return focus to the input.
    Tab Confirm the highlighted item when autoSelect: true; otherwise close the dropdown.

    CSS classes

    The following classes control search input structure and appearance. All classes are CSS-only unless marked JS-managed.

    Class Element Description
    .input-group <div> Flex container that groups the input with an optional prepended icon or appended button.
    .form-outline <div> Required inner wrapper. Add data-cnds-input-init to mark the element for design-system initialisation. Floating-label behaviour is applied automatically by app.js to all .form-outline .form-control elements.
    .form-outline-casefusion <div> Modifier on .form-outline. Applies the CaseFusion green focus ring and border color.
    .form-outline-hyperlize <div> Modifier on .form-outline. Applies the Hyperlize orange focus ring and border color.
    .form-outline-expireon <div> Modifier on .form-outline. Applies the ExpireOn blue focus ring and border color.
    .autocomplete-input <input> Added automatically by Nimbus.Autocomplete to the <input>. Do not add manually.
    .autocomplete-label <label> Added automatically by Nimbus.Autocomplete to the <label>. Do not add manually.
    .autocomplete-dropdown-container <div> Absolutely positioned container injected by Nimbus.Autocomplete to host the dropdown panel. Scopes all autocomplete CSS custom properties.
    .autocomplete-dropdown <div> The visible dropdown panel. Receives .open once rendered to trigger the scale-and-opacity entrance animation.
    .autocomplete-items-list <ul> Scrollable list container inside the dropdown panel. Max-height is controlled by the listHeight option.
    .autocomplete-item <li> Individual suggestion row. Receives .active on keyboard focus.
    .autocomplete-loader <div> Spinner injected inside the input wrapper. Shown while an async filter Promise is pending; hidden otherwise.

    Accessibility

    The following attributes and practices are required for an accessible search implementation:

    • Every <input type="search"> must have a matching <label> via the for/id pair, or an aria-label when a visible label is not suitable (for example, an inline navbar search).
    • When the search field controls a live results region, add role="search" to the enclosing <div> or <form> landmark to expose the region to assistive technologies.
    • If autocomplete suggestions are shown, Nimbus.Autocomplete manages aria-expanded, aria-activedescendant, and role="listbox" / role="option" automatically. Do not add these attributes manually.
    • The loading spinner injected by Nimbus.Autocomplete carries role="status" and aria-hidden="true" — it is intentionally hidden from assistive technologies since the results themselves announce the update.

    For the full specification, see the WAI-ARIA Authoring Practices for the combobox pattern.
