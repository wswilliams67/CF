    v1Utilities for Layout
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The Nimbus Design System includes a comprehensive set of utility classes for faster mobile-friendly and responsive development. These CSS-only utilities cover position (static, relative, absolute, fixed, sticky), top/bottom/start/end placement offsets, translate utilities, overflow control (auto, hidden, scroll, visible), object-fit, display toggling, flexbox options, margin and padding spacing, and visibility management. They work seamlessly across all supported themes and responsive breakpoints without requiring any JavaScript.

    Layout utilities are organized into key categories: position utilities for controlling element stacking and placement, overflow options for clipping and scrolling content, display properties for toggling element rendering, flexbox options for flexible layouts, margin and padding for spacing control, and visibility toggling for hiding elements while preserving their layout space.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Changing display

    Use the display utilities to responsively toggle common values of the display property. Combine them with the grid system, content, or components to show or hide elements across specific viewport sizes. These utilities map directly to the CSS display property and support all standard responsive breakpoints.

    Responsive display utilities follow the format .d-{breakpoint}-{value} where breakpoint is one of sm, md, lg, xl, or xxl. Common display values include:

    • .d-none — hides the element entirely
    • .d-inline — displays as an inline element
    • .d-inline-block — displays as an inline block element
    • .d-block — displays as a block element
    • .d-flex — displays as a flex container
    • .d-inline-flex — displays as an inline flex container
    • .d-grid — displays as a grid container
    • .d-table — displays as a table element

    Hiding elements

    To hide elements at specific breakpoints, combine .d-none with a responsive display class. For example, .d-none .d-md-block hides an element on small screens but shows it from the md breakpoint and up.

    Flexbox options

    The Nimbus Design System is built with flexbox, but not every element's display has been changed to display: flex as this would add many unnecessary overrides and unexpectedly change key browser behaviors. Most of the design system's components are built with flexbox enabled.

    Should you need to add display: flex to an element, do so with .d-flex or one of the responsive variants (e.g., .d-sm-flex). You'll need this class or display value to allow the use of the additional flexbox utilities for sizing, alignment, spacing, and more.

    Margin and padding

    Use the margin and padding spacing utilities to control how elements and components are spaced and sized. The Nimbus Design System includes a six-level scale for spacing utilities, based on a 1rem value default $spacer variable. Choose values for all viewports (e.g., .me-3 for margin-right: 1rem), or pick responsive variants to target specific viewports (e.g., .me-md-3 for margin-right: 1rem starting at the md breakpoint).

    Notation

    Spacing utilities follow the format .{property}{sides}-{size} for xs and .{property}{sides}-{breakpoint}-{size} for sm, md, lg, xl, and xxl.

    Where property is one of:

    • m — sets margin
    • p — sets padding

    Where sides is one of:

    • t — sets margin-top or padding-top
    • b — sets margin-bottom or padding-bottom
    • s — (start) sets margin-left or padding-left in LTR
    • e — (end) sets margin-right or padding-right in LTR
    • x — sets both left and right
    • y — sets both top and bottom
    • blank — sets all 4 sides

    Where size is one of:

    • 0 — eliminates the spacing
    • 1 — sets spacing to $spacer * .25
    • 2 — sets spacing to $spacer * .5
    • 3 — sets spacing to $spacer
    • 4 — sets spacing to $spacer * 1.5
    • 5 — sets spacing to $spacer * 3
    • auto — sets spacing to auto

    Toggle visibility

    When toggling display isn't needed, you can toggle the visibility of an element with the visibility utilities. Invisible elements will still affect the layout of the page, but are visually hidden from visitors. The key difference between display: none and visibility: hidden is that invisible elements still occupy space in the document flow.

    Visible element
    Invisible element (still takes space)
    Visible element

    HTML

    <!-- Visible element -->
<div class="visible">...</div>

<!-- Invisible element (still occupies space) -->
<div class="invisible">...</div>

    The .visible and .invisible classes set the CSS visibility property. These classes do not modify the display value at all and do not affect layout. Elements with .invisible still take up space in the page but are not visible to the user.

    API Documentation

    The Nimbus Design System layout utilities are a comprehensive set of CSS classes that provide control over position, overflow, object-fit, display, flexbox, spacing, and visibility properties. These utilities are CSS-only and require no JavaScript initialization. All classes support responsive breakpoints for adaptive layouts across screen sizes.

    Usage

    Layout utilities are applied directly as CSS classes on HTML elements. No JavaScript initialization is required. Simply add the appropriate class to any element to apply the desired layout behavior.

    HTML
    <!-- Display utility -->
<div class="d-flex">...</div>

<!-- Spacing utility -->
<div class="p-3 mt-2">...</div>

<!-- Visibility utility -->
<div class="invisible">...</div>

<!-- Responsive display utility -->
<div class="d-none d-md-block">...</div>

<!-- Position utility with placement offset -->
<div class="position-relative">
  <span class="position-absolute top-0 end-0">Badge</span>
</div>

<!-- Combined layout utilities -->
<div class="d-flex justify-content-between align-items-center p-3 mt-4">
  <div class="me-auto">Left content</div>
  <div class="ms-3">Right content</div>
</div>

    Responsive breakpoints

    All layout utility classes support responsive breakpoint infixes. The pattern follows .{property}-{breakpoint}-{value} where the breakpoint is optional (omitting it targets all screen sizes).

    Accessibility

    Layout utility classes have direct implications for keyboard navigation, screen reader behavior, and focus management. Follow these guidelines to maintain accessibility compliance when applying layout utilities in CaseFusion and other Nimbus-based applications.

    Position-fixed and focus traps

    Elements using .position-fixed (such as modals, drawers, or sticky toolbars) can create focus trap concerns. When a fixed-position overlay is visible, keyboard focus must be contained within it — users should not be able to tab into content behind the overlay. Use a JavaScript focus trap (or Angular CDK's FocusTrap) to manage this. Fixed headers using .sticky-top should not intercept focus from the main content — always include a .visually-hidden-focusable skip link at the top of the page targeting #main-content (WCAG 2.4.1 Bypass Blocks).

    Overflow-hidden and hidden content

    Applying .overflow-hidden to a container clips its content visually, but clipped content may still be accessible to screen readers and keyboard navigation. If overflowed content should also be inaccessible, use aria-hidden="true" or control visibility with display: none (.d-none) rather than overflow clipping alone. Scrollable regions using .overflow-auto or .overflow-scroll must be keyboard-accessible — add tabindex="0" to non-interactive scrollable containers so keyboard users can reach and scroll them (WCAG 2.1.1 Keyboard).

    Visibility vs. display for accessibility

    Choose the right hiding technique based on intent:

    Technique Occupies space Screen reader accessible Keyboard focusable Use when
    .invisible Yes No No Hide visually while preserving layout space
    .d-none No No No Completely remove from layout and accessibility tree
    .visually-hidden No (clipped) Yes No Provide screen reader context (e.g., icon labels)
    .visually-hidden-focusable No (until focused) Yes Yes Skip navigation links (WCAG 2.4.1)
    aria-hidden="true" Yes No Yes (must also use tabindex="-1") Hide decorative elements from assistive technology

    Note: Always test layout-utility-driven UI patterns with a screen reader (VoiceOver, NVDA) and keyboard-only navigation to verify that focus order, landmark regions, and content visibility behave as expected for all users.
