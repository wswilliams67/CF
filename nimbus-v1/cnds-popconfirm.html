    The CNDS Popconfirm is a compact confirmation overlay that intercepts a button click before an action executes. It renders either inline — positioned relative to the trigger button — or as a centered modal dialog. Use it to guard destructive or irreversible actions such as deleting a record, submitting a form, or ending a session, requiring the user to explicitly confirm or cancel before the operation proceeds.

    Popconfirm initializes automatically when data-cnds-toggle="popconfirm" is present on a .btn element — no JavaScript required for basic usage. All options are configurable through data-cnds-* attributes. For programmatic control, use the Nimbus.Popconfirm JavaScript API.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Add data-cnds-toggle="popconfirm" and the .popconfirm-toggle class to any button to activate the default popconfirm. The message defaults to "Are you sure?" and the dialog opens inline below the trigger. Click OK to confirm or Cancel to dismiss.

    HTML

    <button type="button" class="btn btn-primary popconfirm-toggle" data-cnds-toggle="popconfirm" data-cnds-message="This is example">
    Default
</button>

    Display mode

    Popconfirm supports two display modes controlled by data-cnds-popconfirm-mode. The inline mode (default) positions the dialog relative to the trigger button using the data-cnds-position attribute. The modal mode renders the dialog fixed at the center of the viewport with a semi-transparent backdrop, independent of the trigger's position.

    The .popconfirm-toggle class is required on the trigger in both modes.

    HTML

    <button type="button" data-cnds-popconfirm-mode="modal" data-cnds-toggle="popconfirm" class="btn btn-primary popconfirm-toggle">
    Modal
</button>
<button type="button" data-cnds-popconfirm-mode="inline" data-cnds-toggle="popconfirm" class="btn btn-primary popconfirm-toggle">
    Inline
</button>

    Icon example

    Add an icon to the popconfirm message by setting data-cnds-popconfirm-icon to any MDI class string. The icon is rendered before the message text inside the dialog. For example, data-cnds-popconfirm-icon="mdi mdi-comment" renders the MDI comment icon. Use icons from the Material Design Icons library (mdi prefix) as designated in the CNDS design system.

    HTML

    <button type="button" data-cnds-popconfirm-mode="inline" data-cnds-popconfirm-icon="mdi mdi-comment" data-cnds-message="Icon example" data-cnds-toggle="popconfirm" class="btn btn-primary popconfirm-toggle">
    Icon
</button>

    Inline positions

    When using data-cnds-popconfirm-mode="inline", the dialog is positioned relative to the trigger button. Use data-cnds-position to choose from twelve placements: four cardinal directions each with two edge-aligned variants plus centered versions. The component calculates coordinates using the trigger's bounding rect and the viewport scroll offset.

    Available positions: top left; top; top right; right top; right; right bottom; bottom right; bottom; bottom left; left bottom; left; left top

    HTML

    <button type="button" data-cnds-popconfirm-mode="inline" data-cnds-position="top left" data-cnds-toggle="popconfirm" class="btn btn-primary popconfirm-toggle">
    Top left
</button>
<button type="button" data-cnds-popconfirm-mode="inline" data-cnds-position="bottom" data-cnds-toggle="popconfirm" class="btn btn-primary popconfirm-toggle">
    Bottom
</button>
<button type="button" data-cnds-popconfirm-mode="inline" data-cnds-position="right top" data-cnds-toggle="popconfirm" class="btn btn-primary popconfirm-toggle">
    Right top
</button>

    API Documentation

    Introduction

    The Nimbus Popconfirm is a lightweight confirmation dialog component that intercepts button clicks before an action executes. It renders a small overlay — inline or modal — containing a configurable message, a cancel button, and a confirm button. The component registers automatically when data-cnds-toggle="popconfirm" is detected on a .btn element via the CNDS DataAPI. All configuration is available via data-cnds-* attributes or the JavaScript constructor. The component emits custom DOM events (show, hide, confirm, cancel) on the trigger element, enabling clean separation of UI interaction and business logic.

    Usage

    Via data attributes

    The Popconfirm component requires no JavaScript to initialize. Add data-cnds-toggle="popconfirm" and the .popconfirm-toggle class to any button. Use additional data-cnds-* attributes to configure all options declaratively without writing a single line of JavaScript.

    HTML
    <button type="button" class="btn btn-primary popconfirm-toggle" data-cnds-toggle="popconfirm">Default</button>
    Via JavaScript

    Create a Popconfirm instance programmatically using the Nimbus.Popconfirm constructor. This is useful when the trigger element is rendered dynamically or when you need direct control over show/hide behavior.

    JAVASCRIPT
    const element = document.querySelector('.popconfirm-toggle');
const instance = new Nimbus.Popconfirm(element);

    Options

    Options can be passed via data attributes or the JavaScript constructor. For data attributes, convert the option name from camelCase to kebab-case and prefix with data-cnds-. For example, okText becomes data-cnds-ok-text.

    Name Type Default Description
    backdrop Boolean true Renders a transparent overlay behind the popconfirm; clicking it closes the dialog. In modal mode the overlay is semi-transparent (rgba(0,0,0,0.3)).
    cancelClass String 'btn btn-secondary btn-sm' CSS classes applied to the cancel button.
    cancelText String 'Cancel' Label text for the cancel button. Set to an empty string to suppress the cancel button entirely.
    message String 'Are you sure?' Confirmation message displayed in the popconfirm body.
    okClass String 'btn btn-primary btn-sm' CSS classes applied to the confirm button.
    okText String 'OK' Label text for the confirm button.
    popconfirmIcon String '' MDI class string (e.g. 'mdi mdi-alert') rendered as an icon before the message text. Leave empty to omit the icon.
    popconfirmMode String 'inline' Display mode. 'inline' positions the dialog relative to the trigger; 'modal' centers it in the viewport.
    position String 'bottom' Placement of the inline dialog relative to the trigger. One of twelve position strings. Ignored in modal mode. See Inline positions.

    Methods

    Method Description Example
    show() Opens the popconfirm. No-op if already shown. instance.show()
    hide() Closes the popconfirm and removes it from the DOM. No-op if not shown. instance.hide()
    toggle() Opens the popconfirm if hidden; closes it if shown. instance.toggle()
    dispose() Destroys the popconfirm instance, hides the dialog, and removes all event listeners. instance.dispose()
    getInstance() Static method. Returns the Popconfirm instance associated with a DOM element, or null if none exists. Nimbus.Popconfirm.getInstance(el)
    getOrCreateInstance() Static method. Returns the existing instance for a DOM element or creates and returns a new one. Nimbus.Popconfirm.getOrCreateInstance(el)
    JAVASCRIPT
    const el = document.querySelector('.popconfirm-toggle');
const instance = Nimbus.Popconfirm.getInstance(el);
instance.dispose();

    Events

    All popconfirm events fire on the trigger element — the button with data-cnds-toggle="popconfirm". Attach listeners to the specific trigger rather than document when multiple popconfirms are present on the same page.

    Event Description
    show.cnds.popconfirm Fired immediately when the popconfirm begins to open. Calling event.preventDefault() will prevent the popconfirm from opening.
    hide.cnds.popconfirm Fired immediately when the popconfirm begins to close, regardless of the reason (confirm, cancel, or backdrop click).
    confirm.cnds.popconfirm Fired when the confirm button is clicked. The dialog closes after this event fires.
    cancel.cnds.popconfirm Fired when the dialog is dismissed via the cancel button or a backdrop click. The dialog closes after this event fires.
    JAVASCRIPT
    const triggerEl = document.querySelector('.popconfirm-toggle');

triggerEl.addEventListener('confirm.cnds.popconfirm', () => {
    // Action confirmed — proceed with the operation
});

triggerEl.addEventListener('cancel.cnds.popconfirm', () => {
    // Action cancelled — restore state or do nothing
});

    CSS classes

    The following classes control popconfirm structure and appearance. Classes prefixed with .popconfirm (except .popconfirm-toggle) are generated dynamically by the JavaScript component and are not added to markup manually.

    Class Element Description
    .popconfirm-toggle <button> Required on the trigger element. Combined with data-cnds-toggle="popconfirm", it marks the button as the popconfirm trigger and registers it with the CNDS DataAPI.
    .popconfirm <div> (generated) Root container of the popup. Positioned absolute by default; coordinates are set by the positioning engine based on the trigger's bounding rect.
    .popconfirm-mode-modal <div> (generated) Applied alongside .popconfirm in modal mode. Changes positioning to fixed; top: 50%; left: 50% with a centered transform.
    .popconfirm-message <div> (generated) Contains the confirmation text and optional icon. Text color inherits --cnds-body-color — theme-aware in both light and dark modes.
    .popconfirm-actions <div> (generated) Flex row that holds the cancel and confirm buttons, right-aligned via justify-content: flex-end.
    .popconfirm-backdrop <div> (generated) Transparent fixed overlay that intercepts outside clicks in inline mode. Omitted when the backdrop option is false.
    .popconfirm-backdrop-modal <div> (generated) Applied alongside .popconfirm-backdrop in modal mode. Adds a semi-transparent dark dimmer (rgba(0,0,0,0.3)) behind the dialog.

    Accessibility

    The Nimbus Popconfirm meets the following Section 508 / WCAG 2.1 AA requirements for confirmation dialogs:

    • Operable trigger — The trigger is a native <button>, which is keyboard-focusable and activatable by default (Space or Enter). Do not replace it with a non-interactive element such as <div> or <span>.
    • Visible label — Provide descriptive text on the trigger button (e.g. "Delete record") so users understand the action before interacting. If the button is icon-only, add aria-label with an equivalent text description.
    • Multiple dismissal methods — The Cancel button and backdrop click both dismiss the dialog, satisfying WCAG 2.5.3.
    • Theme-aware contrast — Message text uses --cnds-body-color (#4f4f4f on #ffffff in light mode — 5.7:1 contrast ratio, exceeds the 4.5:1 AA minimum for small text). The token is overridden in dark mode to maintain equivalent contrast.

    For full dialog accessibility (WAI-ARIA dialog pattern and WCAG 4.1.3), consider the following enhancements when implementing in production:

    • Add role="dialog" and aria-modal="true" to the generated .popconfirm element so assistive technologies treat it as a dialog.
    • Add aria-labelledby pointing to the message element so the dialog purpose is announced when it opens.
    • Move focus to the first button (Cancel or OK) when the popconfirm opens, and restore focus to the trigger when it closes.
    • Handle the Escape key to close the dialog — equivalent to clicking Cancel.

    For the full dialog pattern specification, see the WAI-ARIA Authoring Practices Guide: Dialog (Modal) Pattern.
