    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Responsive Buttons built with the Nimbus™ Design System. Multiple predefined button style classes: link, outline, rounded, floating, fixed, toggle & more.

    Use Nimbus™ custom button styles for actions in forms, dialogs, and more with support for multiple sizes, states, and more.

    Note: Read the API documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Use the default .btn-primary button style to indicate an action or link within your website. Add the data-cnds-button-init attribute to initialize the Nimbus Button component.

    HTML

                                                
<button type="button" class="btn btn-primary" data-cnds-button-init>Button</button>

    Disable text wrapping

    If you don't want the button text to wrap, you can add the .text-nowrap class to the button.

    Hierarchy

    Buttons, as one of the key UI elements, must have their own hierarchy. This means that the user should be able to easily identify which button is the most important (primary button), which is less important (secondary button) and which presents completely additional information (tertiary button).

    Elements with strong, filled backgrounds attract attention the most, which is why button primary is built in this way. Note that there should only be one primary call to action per screen or per enclosed sections of a screen.

    A delicate background with outline is less engaging, so it is well suited for button secondary.

    The lack of background and shadow makes the element the least visible. These features characterize the button tertiary.

    Note: Button tertiary may require additional margins. Without extra margins, the button edge will be flush with adjacent elements (which is sometimes the desired result). If you need margin — simply add margin utility classes like mx-1.

    HTML

                                                
<button type="button" class="btn btn-primary mx-1" data-cnds-button-init>Primary</button>
<button type="button" class="btn btn-secondary mx-1" data-cnds-button-init>Secondary</button>
<button type="button" class="btn btn-tertiary mx-1" data-cnds-button-init>Tertiary</button>

    Contextual

    Nimbus includes several predefined contextual button styles, each serving its own semantic purpose, with colors that communicate meaning such as success, danger, warning, and info.

    HTML

                                    
<button type="button" class="btn btn-success mx-1" data-cnds-button-init>Success</button>
<button type="button" class="btn btn-danger mx-1" data-cnds-button-init>Danger</button>
<button type="button" class="btn btn-caution mx-1" data-cnds-button-init>Caution</button>
<button type="button" class="btn btn-warning mx-1" data-cnds-button-init>Warning</button>
<button type="button" class="btn btn-info mx-1" data-cnds-button-init>Info</button>

    Conveying meaning to assistive technologies:
    Using color to add meaning only provides a visual indication, which will not be conveyed to users of assistive technologies – such as screen readers. Ensure that information denoted by the color is either obvious from the content itself (e.g. the visible text), or is included through alternative means, such as additional text hidden with the .visually-hidden class.

    Link

    The .btn-link style makes a button look like a hyperlink while maintaining button padding and sizing. It removes the background and border, with a subtle light-gray hover background. No text-decoration is applied.

    Semantic tertiary

    Tertiary semantic buttons are the outline treatment with the border removed. The colour still carries the semantic meaning; dropping the border is what places them below .btn-outline-* in the hierarchy. Use them where a semantic action must stay available without competing with the primary action on the screen — a destructive action parked at the far left of a toolbar, for example.

    Because a tertiary button draws no border, focus is the one state that does — keyboard users still need to see where they are. Do not remove the focus border to make the control quieter.

    HTML

                                            
<button type="button" class="btn btn-tertiary-success" data-cnds-button-init>Success</button>
<button type="button" class="btn btn-tertiary-danger" data-cnds-button-init>Danger</button>
<button type="button" class="btn btn-tertiary-caution" data-cnds-button-init>Caution</button>

    Tags

    The .btn classes are designed to be used with the <button> element. However, you can also use these classes on <a> or <input> elements (though some browsers may apply a slightly different rendering).

    When using button classes on <a> elements that are used to trigger in-page functionality (like collapsing content), rather than linking to new pages or sections within the current page, these links should be given a role="button" to appropriately convey their purpose to assistive technologies such as screen readers.

    Link

    HTML

                                                                                
                                <a class="btn btn-primary" href="#" role="button" data-cnds-button-init>Link</a>
                                <button class="btn btn-primary" data-cnds-button-init type="submit">Button</button>
                                <input class="btn btn-primary" type="button" value="Input" />
                                <input class="btn btn-primary" type="submit" value="Submit" />
                                <input class="btn btn-primary" type="reset" value="Reset" />

    Disabled state

    Make buttons look inactive by adding the disabled boolean attribute to any <button> element. Disabled buttons have pointer-events: none applied to, preventing hover and active states from triggering.

    HTML

                                                                                
                                <button type="button" class="btn btn-primary btn-lg" disabled data-cnds-button-init>Primary button</button>
                                <button type="button" class="btn btn-secondary btn-lg" disabled data-cnds-button-init>Button</button>

    Disabled buttons using the <a> element behave a bit different:

    • <a>s don’t support the disabled attribute, so you must add the .disabled class to make it visually appear disabled.
    • Some future-friendly styles are included to disable all pointer-events on anchor buttons. In browsers which support that property, you won’t see the disabled cursor at all.
    • Disabled buttons using <a> should include the aria-disabled="true" attribute to indicate the state of the element to assistive technologies.
    • Disabled buttons using <a> should not include the href attribute.
    Primary link Link

    HTML

                                                                                
                                <a class="btn btn-primary btn-lg disabled" role="button" aria-disabled="true" data-cnds-button-init>Primary link</a>
                                <a class="btn btn-secondary btn-lg disabled" role="button" aria-disabled="true" data-cnds-button-init>Link</a>

    Link functionality caveat:
    To cover cases where you have to keep the href attribute on a disabled link, the .disabled class uses pointer-events: none to try to disable the link functionality of <a>s. Note that this CSS property is not yet standardized for HTML, but all modern browsers support it. In addition, even in browsers that do support pointer-events: none, keyboard navigation remains unaffected, meaning that sighted keyboard users and users of assistive technologies will still be able to activate these links. So to be safe, in addition to aria-disabled="true", also include a tabindex="-1" attribute on these links to prevent them from receiving keyboard focus, and use custom JavaScript to disable their functionality altogether.

    Primary link Link

    HTML

                                                                                
<a href="#" class="btn btn-primary btn-lg disabled" tabindex="-1" role="button" aria-disabled="true" data-cnds-button-init>Primary link</a>
<a href="#" class="btn btn-secondary btn-lg disabled" tabindex="-1" role="button" aria-disabled="true" data-cnds-button-init>Link</a>

    Block buttons

    Create responsive stacks of full-width, “block buttons” like those in Bootstrap 4 with a mix of our display and gap utilities. By using utilities instead of button specific classes, we have much greater control over spacing, alignment, and responsive behaviors.

    HTML

                                                                                
                                <div class="d-grid gap-2">
    <button class="btn btn-primary" type="button" data-cnds-button-init>Button</button>
    <button class="btn btn-primary" type="button" data-cnds-button-init>Button</button>
</div>

    Here we create a responsive variation, starting with vertically stacked buttons until the md breakpoint, where .d-md-block replaces the .d-grid class, thus nullifying the gap-2 utility. Resize your browser to see them change.

    HTML

                                                                                
                                <div class="d-grid gap-2 d-md-block">
    <button class="btn btn-primary" type="button" data-cnds-button-init>Button</button>
    <button class="btn btn-primary" type="button" data-cnds-button-init>Button</button>
</div>

    You can adjust the width of your block buttons with grid column width classes. For example, for a half-width “block button”, use .col-6. Center it horizontally with .mx-auto, too.

    HTML

                                                                                
                                <div class="d-grid gap-2 col-6 mx-auto">
    <button class="btn btn-primary" type="button" data-cnds-button-init>Button</button>
    <button class="btn btn-primary" type="button" data-cnds-button-init>Button</button>
</div>

    Additional utilities can be used to adjust the alignment of buttons when horizontal. Here we’ve taken our previous responsive example and added some flex utilities and a margin utility on the button to right align the buttons when they’re no longer stacked.

    HTML

                                                                                
                                <div class="d-grid gap-2 d-md-flex justify-content-md-end">
    <button class="btn btn-primary me-md-2" type="button" data-cnds-button-init>Button</button>
    <button class="btn btn-primary" type="button" data-cnds-button-init>Button</button>
</div>

    API Documentation

    Introduction

    Usage

    Via data attributes

    Add data-cnds-button-init to any .btn element to automatically initialize the Button component. For toggle buttons, also add data-cnds-toggle="button". For fixed action buttons (FAB), add data-cnds-button-init to the .fixed-action-btn container.

    HTML
                                                    
<!-- Basic button (no JS needed) -->
<button type="button" class="btn btn-primary">Button</button>

<!-- Toggle button -->
<button type="button" class="btn btn-primary" data-cnds-toggle="button" data-cnds-button-init>
  Toggle button
</button>

<!-- Fixed action button (FAB) -->
<div class="fixed-action-btn" data-cnds-button-init>
  <a class="btn btn-primary btn-floating btn-lg">
    <i class="fas fa-pencil-alt"></i>
  </a>
  <ul class="list-unstyled">
    <li><a class="btn btn-danger btn-floating btn-lg"><i class="mdi mdi-star"></i></a></li>
    <li><a class="btn btn-warning btn-floating btn-lg"><i class="mdi mdi-account"></i></a></li>
    <li><a class="btn btn-success btn-floating btn-lg"><i class="mdi mdi-email"></i></a></li>
  </ul>
</div>
    Via JavaScript

    You can also create Button instances programmatically using the Nimbus.Button constructor.

    JAVASCRIPT
                                                    
// Initialize a fixed action button
const fabElement = document.getElementById('myFab');
const fabInstance = new Nimbus.Button(fabElement);

// Open the FAB list
fabInstance.show();

// Close the FAB list
fabInstance.hide();

// Toggle the FAB list
fabInstance.toggle();

    Note: Standard buttons (.btn-primary, .btn-secondary, etc.) do not require JavaScript initialization. The data-cnds-button-init attribute is only needed for toggle buttons and fixed action buttons (FAB).

    Methods

    The following methods are available on the Nimbus.Button instance.

    Method Description Example
    toggle Toggles the button state. For regular buttons, toggles the .active class and aria-pressed attribute. For fixed action buttons, opens or closes the child list. instance.toggle()
    show Opens the fixed action button child list. Only applies to .fixed-action-btn elements. Triggers show.cnds.button and shown.cnds.button events. instance.show()
    hide Closes the fixed action button child list. Only applies to .fixed-action-btn elements. Triggers hide.cnds.button and hidden.cnds.button events. instance.hide()
    dispose Destroys the button instance, removing event listeners and stored data. instance.dispose()
    getInstance Static. Returns the Button instance associated with a DOM element, or null if none exists. Nimbus.Button.getInstance(element)
    getOrCreateInstance Static. Returns the Button instance associated with a DOM element, or creates a new one if it hasn't been initialized. Nimbus.Button.getOrCreateInstance(element)
    JAVASCRIPT
                                                    
// Get an existing instance
const fabEl = document.getElementById('fixed1');
const fabInstance = Nimbus.Button.getInstance(fabEl);

// Or get/create
const instance = Nimbus.Button.getOrCreateInstance(fabEl);

// Use methods
instance.show();   // open FAB list
instance.hide();   // close FAB list
instance.toggle(); // toggle FAB list
instance.dispose(); // destroy instance

    Events

    The Button component exposes events for the fixed action button (FAB) lifecycle. These events are dispatched on the .fixed-action-btn element.

    Event Description
    show.cnds.button Fires immediately when the show() method is called. Can be prevented with event.preventDefault().
    shown.cnds.button Fires after the FAB child list is fully visible and all CSS transitions have completed.
    hide.cnds.button Fires immediately when the hide() method is called. Can be prevented with event.preventDefault().
    hidden.cnds.button Fires after the FAB child list is fully hidden and all CSS transitions have completed.
    JAVASCRIPT
                                                    
const myFab = document.getElementById('fixed1');

myFab.addEventListener('show.cnds.button', function (e) {
  // FAB is about to open
  console.log('FAB opening...');
});

myFab.addEventListener('shown.cnds.button', function (e) {
  // FAB is fully open
  console.log('FAB opened.');
});

myFab.addEventListener('hide.cnds.button', function (e) {
  // FAB is about to close
  console.log('FAB closing...');
});

myFab.addEventListener('hidden.cnds.button', function (e) {
  // FAB is fully closed
  console.log('FAB closed.');
});

// Prevent opening
myFab.addEventListener('show.cnds.button', function (e) {
  e.preventDefault(); // FAB will not open
});
