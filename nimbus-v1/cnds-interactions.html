    Interactions

    Interaction utilities are CSS-only classes that give you precise control over how users engage with elements on the page — whether they can select text, trigger pointer events, or respond to cursor changes. Because they map directly to CSS properties, no JavaScript is required and they compose cleanly with every other Nimbus utility class.

    This page documents two utility groups: Text selection controls whether and how a user can highlight text inside an element, and Pointer events controls whether an element responds to mouse clicks, touch taps, and stylus interactions at all.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Text selection

    The user-select CSS property controls whether and how a user can select text inside an element. Nimbus exposes three utility classes that cover the most common scenarios:

    • .user-select-all — the element's entire text content is selected in a single click. Use this for copy-friendly targets such as API keys, terminal commands, or shareable URLs.
    • .user-select-auto — restores the browser's default selection behaviour, inheriting from the parent element. Use this to opt a child element back in when its parent has .user-select-none.
    • .user-select-none — prevents text from being selected. Apply this to UI chrome such as button labels, icon labels, and drag-handle regions where accidental text selection would degrade usability.

    This paragraph will be entirely selected when clicked by the user.

    This paragraph has default select behavior.

    This paragraph will not be selectable when clicked by the user.

    HTML

    <p class="user-select-all">This paragraph will be entirely selected when clicked by the user.</p>
<p class="user-select-auto">This paragraph has default select behavior.</p>
<p class="user-select-none">This paragraph will not be selectable when clicked by the user.</p>

    Pointer events

    Nimbus provides .pe-none and .pe-auto utility classes to disable or restore an element's response to pointer input — mouse clicks, touch taps, and stylus interactions. Both classes map directly to the CSS pointer-events property and can be applied to any element or used on a parent to affect an entire subtree.

    This link can not be clicked.

    This link can be clicked (this is default behavior).

    This link can not be clicked because the pointer-events property is inherited from its parent. However, this link has a pe-auto class and can be clicked.

    HTML

    <p>
    <a href="#" class="pe-none">This link</a> can not be clicked.
</p>
<p>
    <a href="#" class="pe-auto">This link</a> can be clicked (this is default behavior).
</p>
<p class="pe-none">
    <a href="#">This link</a> can not be clicked because
    the <code>pointer-events</code> property is inherited
    from its parent. However,
    <a href="#" class="pe-auto">this link</a> has a
    <code>pe-auto</code> class and can be clicked.
</p>

    The .pe-none class (and the pointer-events CSS property it sets) only prevents interactions with a pointer (mouse, stylus, touch). Links and controls with .pe-none are, by default, still focusable and actionable for keyboard users. To ensure that they are completely neutralized even for keyboard users, you may need to add further attributes such as tabindex="-1" (to prevent them from receiving keyboard focus) and aria-disabled="true" (to convey the fact they are effectively disabled to assistive technologies), and possibly use JavaScript to completely prevent them from being actionable. If possible, the simpler solution is:

    • For form controls, add the disabled HTML attribute.
    • For links, remove the href attribute, making it a non-interactive anchor or placeholder link.

    API Documentation

    Introduction

    The Nimbus interaction utilities are CSS-only — no JavaScript initialisation is required. Each class maps directly to a single CSS property and applies !important to ensure the declaration always wins regardless of selector specificity. The utilities are stateless and composable: they combine cleanly with any other Nimbus class and work in both light and dark themes without modification.

    Because user-select and pointer-events are inherited CSS properties, applying a utility class to a parent element automatically cascades the value to all descendants. A child may override the inherited value by applying the corresponding -auto class.

    CSS classes

    The following classes control text selection and pointer interaction behaviour. All classes are defined in css/core/interactions.css and require no JavaScript.

    Class CSS property Value Description
    .user-select-all user-select all Selects the element's entire text content in a single click. Use for copy-friendly targets such as API keys, terminal commands, or shareable URLs.
    .user-select-auto user-select auto Restores the browser's default text-selection behaviour, inheriting from the parent. Use to opt a child element back in when its parent has .user-select-none.
    .user-select-none user-select none Prevents the element's text from being selected. Apply to UI chrome such as button labels, icon labels, and drag-handle regions where accidental text selection degrades usability.
    .pe-none pointer-events none Disables all pointer interactions — mouse clicks, touch taps, and stylus input. Inherited by descendants; a child can override with .pe-auto.
    .pe-auto pointer-events auto Restores the element's default pointer-events behaviour. Use on a child to re-enable clicks inside a .pe-none parent.

    Accessibility

    .pe-none only suppresses pointer input — it does not remove an element from the keyboard focus order or hide it from assistive technologies. An element with .pe-none remains reachable via Tab and fully actionable via Enter or Space. To completely neutralise an element for all users, combine pointer-events suppression with the following:

    • Add tabindex="-1" to remove the element from the keyboard focus order.
    • Add aria-disabled="true" to convey the disabled state to screen readers.
    • For form controls, use the native disabled HTML attribute instead — it handles focus removal, ARIA state, and pointer suppression in a single step.
    • For links, remove the href attribute to make the element a non-interactive placeholder anchor.

    .user-select-none has no direct impact for keyboard or screen-reader users. Avoid applying it to content that users legitimately need to copy, such as code snippets, error messages, or contact details.
