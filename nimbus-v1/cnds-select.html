    v1Select
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The Select component replaces the browser-native <select> element with a fully styled, keyboard-accessible dropdown that matches the Nimbus design language. It supports single and multiple selection, option grouping, search filtering, placeholder text, and programmatic control through a JavaScript API.

    Use the Select component when users must choose from a fixed list of options. For free-form input with suggestions, use Autocomplete instead. All options are configurable via data-cnds-* attributes or a JavaScript options object passed to new Nimbus.Select(element, options).

    Note: Read the API Documentation to find all available options and advanced customization

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Add data-cnds-select-init to a plain <select> element to replace it with the Nimbus-styled dropdown. The component inherits existing <option> and <optgroup> elements, so no markup changes to the options are required.

    HTML
                                    
<select data-cnds-select-init>
    <option value="1">One</option>
    <option value="2">Two</option>
    <option value="3">Three</option>
    <option value="4">Four</option>
    <option value="5">Five</option>
    <option value="6">Six</option>
    <option value="7">Seven</option>
    <option value="8">Eight</option>
</select>

    Count badge on the “All” option

    Mark the empty-value option with data-cnds-all-option and the component appends a .badge showing how many selectable options the list holds — every option except the placeholder and the “all” option itself. The count is computed on render, so an option list that arrives from an API stays accurate without the markup restating the number.

    Search

    Set filter option to true to enable options filtering.

    The filter field carries its own clear button. It appears only while the field has text, and clicking it empties the search, re-renders the full option list, returns focus to the field and fires search.cnds.select with an empty value — so a consumer listening for typing needs no second listener for the clear. Nothing to opt into; it ships with data-cnds-filter="true".

    HTML
                                    
<select data-cnds-select-init data-cnds-filter="true">
    <option value="1">One</option>
    <option value="2">Two</option>
    <option value="3">Three</option>
    <option value="4">Four</option>
    <option value="5">Five</option>
    <option value="6">Six</option>
    <option value="7">Seven</option>
    <option value="8">Eight</option>
    <option value="9">Nine</option>
    <option value="10">Ten</option>
</select>

    API Documentation

    Introduction

    The Nimbus Select component replaces native <select> elements with a fully styled, accessible custom dropdown. It is initialised automatically via the data-cnds-select-init attribute or programmatically through new Nimbus.Select(element, options). The dropdown is appended to document.body (or a specified container) so it escapes any overflow: hidden clipping contexts. All design tokens use the --cnds-select-* namespace and respond automatically to data-cnds-theme="dark".

    Usage

    Via data attributes

    Add data-cnds-select-init to any <select> element. All options can be set with data-cnds-* attributes. No additional JavaScript is required.

    HTML
    <select data-cnds-select-init>
    <option value="1">One</option>
    <option value="2">Two</option>
    <option value="3">Three</option>
</select>

    Via JavaScript

    Pass an options object as the second argument to override any default.

    JAVASCRIPT
    const mySelect = new Nimbus.Select(
    document.getElementById('mySelect'),
    { visibleOptions: 8, clearButton: true }
);

    Options

    Options can be passed via data attributes or JavaScript. For data attributes, convert camelCase names to kebab-case and prefix with data-cnds-, e.g. visibleOptions → data-cnds-visible-options="8".

    Name Type Default Description
    clearButton Boolean false Displays a clear button that resets the current selection.
    container String 'body' CSS selector of the element the dropdown is appended to. Use a modal selector when the select is inside a modal.
    filter Boolean false Displays a search input at the top of the dropdown for filtering options.
    filterPlaceholder String 'Search...' Placeholder text for the filter input. Requires filter: true.
    helperText String '' Static helper text rendered below the trigger input.
    iconPosition String 'left' Position of the option image set via data-cnds-icon. Accepts 'left' or 'right'.
    showGroup Boolean false Show the chosen option as a breadcrumb of its <optgroup> — GROUP > Option — in the closed trigger. Turn it on where the group carries meaning rather than just tidying the list: without it the group is visible while the list is open and gone the moment it closes. The group is upper-cased to match .select-option-group-label, which does it in CSS; the trigger is an <input>, so its value is one string and text-transform cannot apply to part of it. The underlying <select> value is untouched.
    groupSeparator String '  >  ' What sits between the group and the option when showGroup is on.
    invalidFeedback String 'Invalid' Message shown below the field when validation fails. Requires validation: true.
    optionHeight Number 44 Height in pixels of each option row. Used to calculate the dropdown max-height.
    placeholder String '' Text shown in the trigger when no option is selected.
    validFeedback String 'Valid' Message shown below the field when validation passes. Requires validation: true.
    validation Boolean false Enables required-value validation on form submit. Applies is-valid or is-invalid to the wrapper and shows feedback text.
    visibleOptions Number 5 Maximum number of options visible in the dropdown before scrolling.

    Methods

    Name Description Example
    open() Opens the dropdown. mySelect.open()
    close() Closes the dropdown. mySelect.close()
    toggle() Opens the dropdown if closed; closes it if open. mySelect.toggle()
    getValue() Returns the current value. A string for single selects; an array of strings for multiselect. mySelect.getValue()
    setValue(value) Programmatically sets the selection. Pass a single string for single selects or an array for multiselect. mySelect.setValue('3')
    dispose() Destroys the component instance and restores the original <select> element. mySelect.dispose()
    getInstance(el) Static. Returns the Select instance bound to a DOM element, or null. Nimbus.Select.getInstance(el)
    getOrCreateInstance(el) Static. Returns an existing instance or creates a new one. Nimbus.Select.getOrCreateInstance(el)
    JAVASCRIPT
    const selectEl = document.getElementById('mySelect');
const select = Nimbus.Select.getInstance(selectEl);
select.open();

    Events

    All events are dispatched on the original <select> element and bubble up the DOM.

    Event Description
    open.cnds.select Fires immediately before the dropdown opens.
    opened.cnds.select Fires after the dropdown is fully open and the open animation has started.
    close.cnds.select Fires immediately before the dropdown closes.
    closed.cnds.select Fires after the close transition completes and the dropdown is hidden.
    valueChanged.cnds.select Fires whenever the selection changes — on option click or programmatic setValue().
    optionSelected.cnds.select Fires when an individual option is selected.
    optionDeselected.cnds.select Fires when an individual option is deselected (multiselect only).
    search.cnds.select Fires on each keystroke in the filter input. The search term is available as event.detail.value.
    JAVASCRIPT
    const mySelect = document.getElementById('mySelect');
mySelect.addEventListener('valueChanged.cnds.select', (e) => {
    const select = Nimbus.Select.getInstance(mySelect);
    console.log('New value:', select.getValue());
});

    CSS classes

    The following classes are generated by the component or can be applied manually. All structural classes are namespaced with select-.

    Class Element Description
    .select-wrapper <div> Outer flex-column container. Hosts all --cnds-select-* tokens. Added automatically by the component.
    .select-wrapper.is-valid <div> Applied when validation passes. Shows valid feedback text below the field.
    .select-wrapper.is-invalid <div> Applied when validation fails. Shows invalid feedback text below the field.
    .select-wrapper.select-disabled <div> Reduces opacity and disables pointer events when the native select is disabled.
    .select-label <label> Label element. Place a <label class="form-label select-label"> immediately after the <select> in the HTML.
    .select-input <input> The visible trigger input. Read-only; displays the current selection or placeholder text.
    .select-dropdown-container <div> Absolutely-positioned container appended to body (or the configured container). The component automatically adds select-product-casefusion, select-product-expireon, or select-product-hyperlize by detecting the select-wrapper-{product} class on any ancestor element, so selected-state colors match the active product theme.
    .select-dropdown-container.open-above <div> Added automatically by the component when insufficient viewport space exists below the field and more room is available above. Resets margin-top to 0 (the 2 px gap is baked into the JS top calculation) and sets transform-origin: bottom center on the inner panel so the scale animation expands downward. Never set this class manually.
    .select-dropdown <div> The dropdown panel. Receives .open to trigger the scale-in animation.
    .select-option <li> Individual option row. Modifiers: .selected, .active, .disabled.
    .select-option-icon <img> Circular thumbnail rendered when an option has data-cnds-icon. Add .select-option-icon-right when iconPosition is 'right'.
    .select-custom-content <div> Place a sibling <div class="select-custom-content"> immediately after the <select> to inject custom content at the bottom of the dropdown.

    Theme variables

    These tokens are overridden in dark.css on the [data-cnds-theme="dark"] .select-dropdown-container and [data-cnds-theme="dark"] .select-wrapper selectors. Note: because the dropdown is appended to body, dark-theme tokens must be declared on .select-dropdown-container directly — they cannot cascade from .select-wrapper. Product-theme selected-state overrides follow the same pattern: the component adds select-product-{theme} to the dropdown container so that .select-dropdown-container.select-product-expireon and .select-dropdown-container.select-product-hyperlize selectors in select.css apply the correct highlight colors.

    Accessibility

    The Select component implements the WAI-ARIA Combobox pattern. Key attributes and behaviours:

    • The trigger input carries role="combobox", aria-haspopup="listbox", and aria-expanded (toggled on open/close).
    • The dropdown panel carries role="listbox"; each option carries role="option" and aria-selected.
    • Multiselect dropdowns include aria-multiselectable="true" on the listbox.
    • ↓ / ↑ moves keyboard focus through options. Enter or Space confirms the active option. Escape closes the dropdown and returns focus to the trigger.
    • If the native <select> has an id, the dropdown container receives a matching id suffixed with -dropdown, and the trigger sets aria-controls accordingly.
    • Use a visible <label class="form-label select-label"> immediately after the <select> in the source HTML — the component promotes it above the trigger and associates it visually.
