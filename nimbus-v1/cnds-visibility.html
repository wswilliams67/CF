    Visibility utilities control whether an element is rendered on screen without affecting its position or space in the document flow. Unlike display utilities, setting an element to .invisible hides it visually and from assistive technologies while still preserving the space it occupies in the layout.

    Use .visible to explicitly reset CSS visibility to visible — useful when a parent element sets visibility: hidden and you need to re-show a specific child. Use .invisible to hide an element without collapsing its space, preventing layout reflow in grid or flex containers where removing items would shift surrounding content. Both utilities use !important to override component-level specificity. Also available are .object-fit-cover and .object-fit-contain for controlling how images or videos fit inside a fixed-size container.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Apply .visible or .invisible to any element to control its CSS visibility property. Both classes use !important to override specificity conflicts. The critical distinction from display: none is that .invisible elements are still rendered in the layout — they take up the same width, height, and margin as if they were visible — but they are not painted on screen and are hidden from assistive technologies.

    The demo below shows three equally sized boxes. The middle box carries .invisible: its space is preserved in the row, but it is not visible. This layout-preservation behaviour makes .invisible useful wherever removing an element would cause undesirable reflow — for example, placeholders in grid layouts or items that toggle in and out of view without shifting surrounding content.

    Visually hidden

    The .visually-hidden class makes an element invisible to sighted users while keeping it fully accessible to assistive technologies such as screen readers. It does this by collapsing the element to a 1×1 pixel area with overflow: hidden and clip: rect(0,0,0,0) — the element remains in the accessibility tree and its text content is announced, but it occupies no visible space in the layout.

    The companion class .visually-hidden-focusable extends this behaviour for interactive elements such as links and buttons: the element is clipped until it receives keyboard focus, at which point it becomes fully visible. This is the standard pattern for "Skip to main content" links required by WCAG 2.4.1 (Bypass Blocks). The :focus-within selector means the element also becomes visible when a descendant receives focus.

    Common use cases for .visually-hidden include: providing labels for icon-only buttons, augmenting link text that is visually clear but ambiguous out of context ("Read more" → "Read more about Accessibility"), and adding live-region announcements for dynamic content updates.

    HTML

    <!-- Icon-only button: visually hidden label for screen readers -->
<button class="btn btn-primary" type="button">
    <i class="mdi mdi-magnify mdi-18px" aria-hidden="true"></i>
    <span class="visually-hidden">Search</span>
</button>

<!-- Skip-nav link: appears visually on keyboard focus -->
<a class="visually-hidden-focusable" href="#main-content">
    Skip to main content
</a>

    CSS

    /* Hidden from sighted users; preserved in the accessibility tree */
.visually-hidden,
.visually-hidden-focusable:not(:focus):not(:focus-within) {
  width:      1px  !important;
  height:     1px  !important;
  padding:    0    !important;
  margin:     -1px !important;
  overflow:   hidden    !important;
  clip:       rect(0, 0, 0, 0) !important;
  white-space: nowrap   !important;
  border:     0    !important;
  position:   absolute  !important;
}

    Object fit

    Object-fit utilities control how a replaced element — typically an <img> or <video> — scales and positions its content within its container box. These classes map directly to the CSS object-fit property and are useful when you need to constrain media to a fixed-size container without distortion.

    Five values are available: contain scales the media to fit entirely within the box (letterboxed); cover fills the box by cropping the media proportionally; fill stretches the media to fill the box regardless of aspect ratio (may distort); scale-down uses whichever is smaller — none or contain; and none renders the media at its intrinsic size, overflowing the container if necessary.

    All five values are also available as responsive breakpoint variants (-sm-, -md-, -lg-, -xl-, -xxl-), enabling different fit strategies at different viewport widths.

<img src="..." class="object-fit-sm-contain object-fit-lg-cover" alt="..." />

    CSS

    .object-fit-contain { object-fit: contain    !important; }
.object-fit-cover   { object-fit: cover      !important; }
.object-fit-fill    { object-fit: fill       !important; }
.object-fit-scale   { object-fit: scale-down !important; }
.object-fit-none    { object-fit: none       !important; }

/* Responsive variants — generated for sm (576px), md (768px),
   lg (992px), xl (1200px), xxl (1400px). Example: */
@media (min-width: 992px) {
  .object-fit-lg-contain { object-fit: contain    !important; }
  .object-fit-lg-cover   { object-fit: cover      !important; }
  .object-fit-lg-fill    { object-fit: fill       !important; }
  .object-fit-lg-scale   { object-fit: scale-down !important; }
  .object-fit-lg-none    { object-fit: none       !important; }
}

    Accessibility

    Visibility utilities have direct accessibility implications that differ depending on which class is applied:

    • .invisible — hides the element both visually and from the accessibility tree. Screen readers will not announce its contents. This is equivalent to setting visibility: hidden and carries the same accessibility semantics as aria-hidden="true". Use it when you want to preserve layout space but suppress the content entirely.
    • .visually-hidden — the opposite contract: the element is removed from the visual presentation but remains fully present in the accessibility tree. Screen readers will announce it. Use this for supplementary context that is clear from visual design alone (icon labels, augmented link text, live-region announcements).
    • .visually-hidden-focusable — extends .visually-hidden for keyboard-operable elements. Required for skip-navigation links to satisfy WCAG 2.4.1 (Bypass Blocks). The element must be the first interactive element in the <body> so keyboard users can reach it before navigating into repeated content.
    • Object-fit utilities do not affect accessibility directly, but always supply a meaningful alt attribute on <img> elements regardless of the fit applied. If the image is purely decorative, use alt="".

    For more information see the WAI-ARIA 1.2 specification and WCAG 2.1 Understanding documents.

    API Documentation

    Introduction

    The Nimbus visibility module is a CSS-only utility set — no JavaScript initialisation is required. All classes use !important to guarantee they override component-level or inline specificity conflicts. The module is fully theme-neutral: none of the visibility utilities alter color, typography, or spacing, so they compose cleanly with any Nimbus theme. Three conceptually distinct groups of utilities are provided:

    • Layout visibility (.visible / .invisible) — toggle CSS visibility while preserving document flow.
    • Accessibility visibility (.visually-hidden / .visually-hidden-focusable) — remove an element from the visual painting surface while keeping it in the accessibility tree.
    • Object-fit utilities (.object-fit-{value} and responsive variants) — control how replaced elements scale within their containers.

    Usage

    Add any visibility class directly to the element. No wrapper, data attribute, or JavaScript call is needed. Classes are composable — you may apply a breakpoint-specific object-fit class alongside a layout or accessibility class on the same element.

    HTML
    <!-- Toggle visual presence while preserving layout space -->
<div class="invisible">Hidden but still occupies space</div>

<!-- Accessible label hidden from sighted users -->
<span class="visually-hidden">Additional context for screen readers</span>

<!-- Responsive image scaling within a fixed-size container -->
<img src="photo.jpg" class="object-fit-cover w-100 h-100" alt="Description" />

    CSS classes

    All classes are defined in css/core/visibility.css and require no JavaScript. Classes marked with a breakpoint suffix are generated for sm (≥576 px), md (≥768 px), lg (≥992 px), xl (≥1200 px), and xxl (≥1400 px).

    Class Element Description
    .visible Any Forces visibility: visible. Overrides any inherited or component-scoped visibility: hidden.
    .invisible Any Forces visibility: hidden. The element is not painted and is removed from the accessibility tree, but its box — including margin and padding — is still rendered in the layout flow.
    .visually-hidden Any Collapses the element to a 1×1 px clipped area, removing it from the visual presentation without removing it from the accessibility tree. Screen readers will still announce its content.
    .visually-hidden-focusable Focusable (links, buttons) Extends .visually-hidden: the element is clipped until it or a descendant receives keyboard focus, at which point the clip is released and the element becomes fully visible. Required for skip-navigation links (WCAG 2.4.1).
    .object-fit-contain <img>, <video> Sets object-fit: contain. The media is scaled proportionally to fit entirely within the box, letterboxed if the aspect ratios differ.
    .object-fit-cover <img>, <video> Sets object-fit: cover. The media is scaled proportionally to fill the box completely, cropping whichever axis overflows.
    .object-fit-fill <img>, <video> Sets object-fit: fill. The media is stretched to fill the box in both dimensions. Aspect ratio is not preserved; distortion may result.
    .object-fit-scale <img>, <video> Sets object-fit: scale-down. The media is sized as though none or contain were specified — whichever produces the smaller result.
    .object-fit-none <img>, <video> Sets object-fit: none. The media is rendered at its intrinsic size, ignoring the box dimensions. May overflow the container; use overflow: hidden on the parent to clip it.
    .object-fit-{bp}-{value} <img>, <video> Responsive variants for each of the five values above. Replace {bp} with sm, md, lg, xl, or xxl and {value} with contain, cover, fill, scale, or none. Example: .object-fit-lg-cover.

    Accessibility

    The following guidance covers the accessibility contract for each class group:

    • .invisible — because the element is removed from the accessibility tree, add aria-hidden="true" explicitly when using this class to document intent and avoid future regressions. Do not apply it to elements that contain interactive children (focusable children inside a visibility: hidden ancestor are unreachable by keyboard).
    • .visually-hidden — the text content is announced by screen readers. Ensure the copy is meaningful in isolation. Avoid duplicating text that is already announced elsewhere on the page to prevent double-reading.
    • .visually-hidden-focusable — place skip-nav links as the first child of <body>. The link must point to a valid id that corresponds to the main landmark (<main id="main-content">). This pattern satisfies WCAG 2.4.1 and Section 508 §1194.22(o).
    • Object-fit utilities — always provide a descriptive alt attribute on <img> elements. If the image is decorative, use alt="" so screen readers skip it. The object-fit property has no accessibility semantics of its own.

    For the full specifications see the WAI-ARIA Authoring Practices and the Section 508 developer guidance.
