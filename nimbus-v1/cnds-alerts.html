    v1 Alerts
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Alerts deliver contextual feedback messages in response to user actions. They are available in nine color variants — primary, secondary, success, danger, caution, warning, info, light, and dark — and can be rendered as static inline banners or as floating, auto-dismissing toasts that stack in a corner of the viewport.

    Use the data-cnds-position attribute to control where floating alerts appear, and set data-cnds-autohide="true" with a data-cnds-delay value for transient notifications. Add .alert-dismissible and a .btn-close element to let users manually dismiss an alert — a close button suppresses the autohide timer so the alert persists until dismissed.

    Note: Read the API documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic examples

    Theming. Alerts are deliberately not themed — every variant uses one colour scheme in both light and dark mode. An alert is an interruption, and it should look the same wherever it appears rather than blending into whichever theme the user happens to be running. The variant colours are hard-coded in alerts.css and there are no [data-cnds-theme="dark"] .alert-* overrides. Do not add any.

    Caution vs Warning. .alert-caution is the orange step between .alert-warning (yellow) and .alert-danger (red). Use warning for something the user should notice, caution for something that needs care before proceeding, and danger for something that has failed or is destructive. Caution measures 6.24:1 in light and 7.12:1 in dark, past WCAG AA. Both deviate from Figma to get there. Text/Light/Caution (#b35900) on Surface/Alert/Background/Caution (#ffd7ad) is only 3.58:1, and no lighter background on the ramp rescues it — caution-50 reaches 4.49:1 and still misses — so light moves the text to caution-800. Dark keeps Figma’s caution text and darkens the surface to caution-900 instead, which also stops a permanent in-page alert being the loudest thing on the page.

    Dismissing

    Using the alert JavaScript plugin, it's possible to dismiss any alert inline. The close button uses the mdi-close icon from Material Design Icons at 24px, rendered automatically via CSS. Here's how:

    • Be sure you've loaded the alert plugin, or the compiled Nimbus JavaScript.
    • Add a close button and the .alert-dismissible class, which adds extra padding to the right of the alert and positions the close button. The .btn-close element automatically renders the mdi-close icon via CSS — no inner markup is needed.
    • On the close button, add the data-cnds-dismiss="alert" attribute, which triggers the JavaScript functionality. Be sure to use the button element with it for proper behavior across all devices.
    • To animate alerts when dismissing them, be sure to add the .fade and .show classes.

    Autohide behaviour: When a floating/stacking alert contains a close button (.btn-close), it is treated as persistent and will wait for the user to click the close icon before hiding — the autohide timer is suppressed. Alerts without a close button are treated as transient and will automatically fade out after the configured delay.

    Stacking

    You can turn on stacking your alerts using the data-cnds-stacking attribute.

    HTML

                                                
<div class="container text-center">
    <button type="button" class="btn btn-primary" id="stacking-trigger-example">
        Show notification
    </button>
</div>

    JAVASCRIPT

                                                
let alertCount = 0;

function* colorGenerator(i) {
  const colors = ['primary', 'warning', 'info', 'success', 'secondary', 'danger'];

  while (true) {
    yield colors[i];
    i++;
    if (i > colors.length - 1) {
      i = 0;
    }
  }
}

const colorIterator = colorGenerator(0);

document.getElementById('stacking-trigger-example').addEventListener('click', () => {
  alertCount++;
  color = colorIterator.next().value;

  const alert = document.createElement('div');
  // Danger alerts get a close button (persistent — must be manually dismissed).
  // All other colors are transient (auto-fade after delay).
  const closeBtn = color === 'danger'
    ? '<button type="button" class="btn-close" data-cnds-dismiss="alert" aria-label="Close"></button>'
    : '';
  alert.innerHTML = `
    <p class="mb-0"><strong>${alertCount}.</strong> Stacking alerts</p>
    ${closeBtn}
  `;
  alert.classList.add('alert', 'fade');
  if (color === 'danger') alert.classList.add('alert-dismissible');

  document.body.appendChild(alert);

  const alertInstance = new Nimbus.Alert(alert, {
    color,
    stacking: true,
    hidden: true,
    width: '450px',
    position: 'bottom-right',
    autohide: true,
    delay: 5000,
  });

  alertInstance.show();
});

    Icon alignment

    An alert with a leading icon wraps it in .alert-icon — the component's own 24px box. A bare <i class="mdi …"> is sized by its font metrics instead, so the glyph does not match the other alerts on the page.

    The icon centres while the message is short and moves to the first line once it is tall. Centring is right at one or two lines. At three or more the glyph ends up level with the middle of a paragraph, marking nothing — so it aligns to the first line instead.

    CSS cannot count lines, so components/alert.js measures each alert against its own line-height and applies .alert-align-top at three lines or more. The trigger is the rendered count, not the character count — a two-line alert becomes four in a narrow panel — so it re-measures on resize. It runs over every .alert, whether or not the element was initialised as a component.

    Apply .alert-align-top by hand for a message you know will be long. After writing an alert's text from script, call Nimbus.Alert.alignIcons() — the line count is not known until it renders.

    One line — the icon centres.
    Two lines of message text, which still centres the icon between them.
    Three lines or more, at which point the icon stops centring and aligns itself to the first line of the message.

    HTML

    
<!-- .alert-icon is the component's 24px box. Alignment is automatic. -->
<div class="alert alert-warning" role="alert">
  <span class="alert-icon" aria-hidden="true"><i class="mdi mdi-alert"></i></span>
  <span>Your message here.</span>
</div>

<!-- Force it, for a message known to be long -->
<div class="alert alert-warning alert-align-top" role="alert"> … </div>

    JAVASCRIPT

    
// After writing alert text from script, re-measure:
document.querySelector("#my-alert span:last-child").textContent = message;
Nimbus.Alert.alignIcons();          // all alerts
Nimbus.Alert.alignIcon(element);    // just one

    Declaring it instead — data-cnds-alert-align

    The automatic pass has to measure, and an alert inside a display: none container measures zero. So a long alert in a modal, offcanvas, tab pane or collapse paints centred and then jumps to the top the moment its container opens. That is correct, and it is visible.

    When the content is known at author time, declare the alignment instead. data-cnds-alert-align="top" (or "center") applies the class up front, so the first paint is already right, and tells the automatic pass to leave that alert alone.

    Authoring .alert-align-top on its own is not enough: the automatic pass sets the class both ways and will strip it on any pass that measures short. The attribute is what makes the choice stick. 

    <!-- Five lines, inside a modal: pin it and skip the measurement -->
<div class="alert alert-warning alert-align-top"
     data-cnds-alert-align="top" role="status">
  <span class="alert-icon" aria-hidden="true"><i class="mdi mdi-alert"></i></span>
  <span>A long message that will always wrap …</span>
</div>

    Leave it off for text that comes from a user, an API or a translation — there the line count is not knowable in advance and measuring is the point.

    API Documentation

    Introduction

    Usage

    Via data attributes

    Using the Alert component doesn't require any additional JavaScript code - simply add data-cnds-alert-init attribute to .alert and use other data attributes to set all options.

    HTML
                                                        
<div class="alert fade show" id="example" data-cnds-alert-init data-cnds-color="primary" data-cnds-autohide="true" data-cnds-delay="2000" role="alert">
  Example
</div>
    Dismiss

    Dismissal can be achieved with data attributes on a button within the alert as demonstrated below:

    HTML
                                                    
<button type="button" class="btn-close" data-cnds-dismiss="alert" aria-label="Close"></button>

    or on a button outside the alert using the data-cnds-target as demonstrated below:

    HTML
                                                    
<button type="button" class="btn-close" data-cnds-dismiss="alert" data-cnds-target="#my-alert" aria-label="Close"></button>
    Via JavaScript
    JAVASCRIPT
                                                    
const element = document.querySelector('.alert');
new Nimbus.Alert(element);

    Options

    Options can be passed via data attributes or JavaScript. For data attributes, append the option name to data-cnds-, as in data-cnds-offset="".

    Name Type Default Description
    position String / null null Sets the position of the alert. It can include horizontal options: top or bottom, and vertical options: left, center, or right. It can also be a combination of any horizontal and vertical values, for example, top-left
    delay Number 5000 Sets the delay in milliseconds before the alert auto-hides. Only applies to transient alerts (those without a close button) when autohide is true.
    autohide boolean false Enables automatic hiding after the delay. Note: if the alert contains a close button (.btn-close or [data-cnds-dismiss="alert"]), autohide is suppressed and the alert will persist until the user clicks the close icon. Alerts without a close button are treated as transient and will auto-fade.
    width String / null null Sets width of alert (e.g. '450px')
    container String / null null Defines the selector (id or class) of the parent element. When set, the alert uses position: absolute within the container instead of position: fixed on the viewport.
    offset Number 10 Defines offset of the element
    stacking Boolean false Enables stacking alerts
    appendToBody Boolean false Appends element to the end of the body
    hidden Boolean false When true, the alert starts hidden and must be shown programmatically via show()
    color String / null null Sets the color variant of an alert — primary | secondary | success | danger | caution | warning | info | light | dark

    Methods

    The following methods are available on the Nimbus.Alert instance.

    Name Description Example
    show Manually shows an alert myAlert.show()
    hide Manually hides an alert myAlert.hide()
    close Manually hides an alert (deletes it from DOM) myAlert.close()
    dispose Removes an Nimbus.Alert instance myAlert.dispose()
    getInstance Static method which allows you to get the alert instance associated to a DOM element. Nimbus.Alert.getInstance(myAlert)
    getOrCreateInstance Static method which returns an alert instance associated to a DOM element or create a new one in case it wasn't initialized. Nimbus.Alert.getOrCreateInstance(myAlert)
    update Updates options of an Nimbus.Alert instance myAlert.update({position: 'top-right'})
    JAVASCRIPT
                                                    
const alertEl = document.getElementById('show-example');
const alert = new Nimbus.Alert(alertEl);
alert.show();

    Events

    The following events are fired on the alert element and can be listened to with addEventListener.

    Name Description
    close.cnds.alert Fires immediately when the close instance method is called.
    closed.cnds.alert Fired when the alert has been closed and CSS transitions have completed.
    show.cnds.alert This event is triggered when a new alert is about to be shown. By using e.preventDefault() you can implement custom validation.
    shown.cnds.alert This event is triggered after the alert has been shown.
    hide.cnds.alert This event is triggered when a new alert is about to be hidden. By using e.preventDefault() you can implement custom validation.
    hidden.cnds.alert This event is triggered after the alert has been hidden.
    JAVASCRIPT
                                                    
const alert = document.getElementById('example')
alert.addEventListener('close.cnds.alert', () => {
  // do something
});

    The four neutrals do not use the semantic tokens. .alert-primary, .alert-secondary, .alert-light and .alert-dark take the neutral surface ramp, matching the Note component — whose Figma variables (Surface/Note/*) are the source of truth. The primary / secondary subtle tokens are brand blue (#e5e6f6 / #0f1129), so pointing a neutral variant at them turns a grey alert blue: a change of identity, not of theme. The five semantic variants need no dark override — their -bg-subtle / -text-emphasis / -border-subtle tokens already theme themselves.
