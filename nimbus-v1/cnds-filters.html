    The Filters plugin dynamically shows and hides content items based on category buttons, with no external library dependencies. Items declare their categories with data-cnds-category; filter buttons declare their value with data-cnds-filter. When a button is clicked the plugin hides non-matching items and shows matching ones, applying a smooth fade-scale animation by default. Add data-cnds-filters-init to the button container for zero-JavaScript auto-initialization on DOMContentLoaded. For more control, instantiate with new Nimbus.Filters(el, options) to enable multi-select mode, attach a search input, disable animation, or drive the filter programmatically through the instance API.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    The simplest integration requires only HTML markup — no JavaScript. Add data-cnds-filters-init to the button container and the plugin auto-initialises on DOMContentLoaded. The element immediately after the button container is used as the items container by default. Each filter button carries data-cnds-filter="category" (or "all" for the reset button), and each item carries data-cnds-category="category". Clicking a category button hides non-matching items and shows matching ones; clicking "All" restores every item.

    Multi-select filter

    Pass multiSelect: true to allow multiple active categories simultaneously. Clicking a second category button adds it to the active set rather than replacing the current selection, so items matching any active category remain visible. Clicking the "All" button clears every active category and restores all items. Items that belong to more than one category declare a comma-separated list in data-cnds-category (e.g., "frontend,design") and match if any of their declared categories is in the active set. Multi-select mode requires JavaScript initialization — it cannot be activated through data attributes alone.

    Filter with search

    Pass a searchInput CSS selector to wire a text input that narrows visible items by their full text content, combined with the active category filter. The search is debounced at 200 ms to avoid excessive filtering on rapid keystrokes. Both filters are applied with AND logic — an item must match the active category and contain the search term to remain visible. Pass an explicit target selector when the items container is not the immediate next sibling of the button container.

    No animation

    Pass animation: false to show and hide items instantly without any transition. This is the correct option for accessibility: users who have enabled the prefers-reduced-motion OS setting benefit from immediate state changes with no visual motion. The recommended pattern is to read the media query at runtime and pass the result to the animation option so the plugin automatically adapts to the user's system preference — see the JavaScript example below.

    Programmatic control

    Store the instance returned by new Nimbus.Filters(el, config) and call its methods at any time from external code. Use filter(category) to activate a category, reset() to restore all items, or getActiveFilters() to read the current active set as an array. The plugin fires a filter.cnds.filters DOM custom event on the button container after every filter change — both from button clicks and programmatic calls — so other parts of the UI can react to updated state via a single event listener rather than polling.

    Click "Get Active Filters" to see the current filter state.

    API Documentation

    Introduction

    Nimbus.Filters is a lightweight, dependency-free filtering plugin bundled inside nimbus.js. It hides and shows items inside a container based on data-cnds-category attributes on those items and data-cnds-filter attributes on control buttons. The plugin supports both markup-driven auto-initialization (via data-cnds-filters-init) and explicit JavaScript construction (new Nimbus.Filters(el, options)) for programmatic control, multi-select mode, and search integration.

    The constructor takes two arguments: the button container element and a plain options object. It returns an instance with methods for programmatic control and fires a filter.cnds.filters custom DOM event on the button container after every filter change. Call instance.dispose() before removing the element from the DOM to clean up event listeners.

    Data attributes

    Using the Filters plugin doesn't require any JavaScript — add data-cnds-filters-init to the button container and the plugin auto-initialises on DOMContentLoaded. Use the additional data-cnds-* attributes below to configure the target container and define category values on buttons and items.

    Attribute Element Description
    data-cnds-filters-init Button container Auto-initializes the Filters plugin on DOMContentLoaded
    data-cnds-target Button container CSS selector for the items container; defaults to the next sibling element when omitted
    data-cnds-filter Button Category name this button filters for; use "all" for the reset button that shows every item
    data-cnds-category Item Category or comma-separated list of categories this item belongs to (e.g., "frontend,design")

    Options

    Options are passed as a plain object to the Nimbus.Filters constructor. When using data-cnds-filters-init for auto-init, set target via the data-cnds-target attribute; all other options require JavaScript initialization.

    Name Type Default Description
    target String | null null CSS selector for the items container. When null, the next sibling of the button container is used
    itemSelector String "[data-cnds-category]" CSS selector used to find filterable items within the target container
    activeClass String "active" CSS class applied to the currently active filter button
    hiddenClass String "d-none" CSS class applied to items that do not match the active filter or search term
    animation Boolean true When true, items fade in and scale up when shown, and fade out when hidden. Set to false for instant toggle
    animationDuration Number 300 Duration in milliseconds of the fade-scale animation. Has no effect when animation is false
    multiSelect Boolean false When true, clicking a category button adds it to the active set rather than replacing the current selection. Clicking "All" clears the set
    searchInput String | null null CSS selector for a text input element. When provided, the plugin listens for input events (debounced at 200 ms) and combines the text search with the active category filter

    Methods

    Method Parameters Description Example
    filter(category) category — String Activates the given category. Pass "all" to reset to showing all items. Respects multiSelect mode instance.filter('design')
    search(term) term — String Filters items by text content. Combined with the active category filter. Pass an empty string to clear the search instance.search('alpha')
    reset() — Clears all active category filters and the search term, restoring all items to visible instance.reset()
    getActiveFilters() — Returns an array of the currently active category strings. Returns ["all"] when no specific category is selected instance.getActiveFilters()
    dispose() — Destroys the plugin instance and removes all event listeners. Call before removing the element from the DOM instance.dispose()

    Events

    Event Description
    filter.cnds.filters Fired on the button container element after each filter change (button click or programmatic call). event.detail.filters is an array of the currently active category strings. Example: ['design', 'frontend'] in multi-select mode, or ['all'] after a reset.
    JAVASCRIPT
    var container = document.getElementById('my-btn-container');
container.addEventListener('filter.cnds.filters', function(event) {
  console.log('Active filters:', event.detail.filters);
  // e.g. ['design'] or ['all']
});

    Accessibility

    The Filters plugin is designed to work with standard HTML interactive elements so it inherits native keyboard and screen-reader support. Follow the patterns below to ensure Section 508 and WCAG 2.1 AA compliance.

    • Wrap the filter buttons in an element with role="group" and an aria-label that describes the filter set (e.g., aria-label="Filter by category"). This creates a logical group that assistive technologies announce when focus enters the button row.
    • Filter buttons are standard <button> elements and are fully keyboard accessible. No additional ARIA roles or attributes are needed on the buttons themselves.
    • When using a status output to reflect the current filter state (e.g., the active category or count of visible items), add aria-live="polite" to the output element. This causes screen readers to announce the updated text without interrupting the current narration. Use aria-live="assertive" only if the change is time-critical.
    • Do not rely on color alone to indicate which filter button is active. The .active class changes both background color and border, which provides a visual distinction, but the button's changed state is not announced to screen readers unless you also add aria-pressed="true" to the active button and aria-pressed="false" to inactive ones. Update these attributes after each filter change.
    • When animation: true (the default), respect the user's OS motion preference by checking window.matchMedia('(prefers-reduced-motion: reduce)').matches at init time and passing the result to the animation option. See the No animation section for an implementation example.
