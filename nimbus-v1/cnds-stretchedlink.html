    v1Stretched link
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The .stretched-link utility makes any containing block fully clickable by expanding a nested <a> element to cover its positioned ancestor via a CSS ::after pseudo-element. No JavaScript is required — the effect is achieved entirely through CSS and works with any element that establishes a containing block.

    Use .stretched-link on cards, media tiles, list items, and grid cells where the entire surface should be tappable without wrapping the whole component in an anchor tag. Nimbus cards have position: relative set by default, so no extra wrapper is needed. For custom components or column-based layouts, ensure the nearest positioned ancestor is the element you want to make clickable — the Containing block section in the API documentation explains how to diagnose and correct unexpected click boundaries.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic examples

    Add .stretched-link to a link to make its containing block clickable via a ::after pseudo-element. In most cases, this means that an element with position: relative that contains a link with the .stretched-link class becomes fully clickable.

    Nimbus cards already have position: relative set by default, so you can safely add .stretched-link to any link inside a card body without additional HTML changes.

    Multiple links and tap targets are not recommended with stretched links. However, position and z-index overrides can isolate individual links when required — see Identifying the containing block in the API Documentation for details.

    Identifying the containing block

    If a stretched link does not appear to cover the expected area, an intermediate element is almost certainly acting as an unintended containing block. The ::after pseudo-element always sizes itself relative to the nearest positioned ancestor. Any of the following CSS properties will make an element the containing block:

    • A position value other than static
    • A transform or perspective value other than none
    • A will-change value of transform or perspective
    • A filter value other than none or a will-change value of filter (Firefox only)

    Stretched link will not work here, because position: relative is added to the link

    This stretched link will only be spread over the p-tag, because a transform is applied to it.

    <div class="card" style="width: 18rem">
    <img src="img/cf/styleguide/041-1.webp" class="card-img-top"
         alt="Hollywood sign at dusk" />
    <div class="card-body">
        <h4 class="card-title">Card with stretched links</h4>
        <p class="card-text">
            Some quick example text to build on the card title and make up
            the bulk of the card's content.
        </p>
        <!-- ✗ position:relative on the <a> resets its own containing block -->
        <p class="card-text">
            <a href="#" class="stretched-link text-danger" style="position: relative">
                Stretched link will not work here, because
                position: relative is added to the link
            </a>
        </p>
        <!-- ✗ transform on the <p> creates a new stacking context -->
        <p class="card-text bg-light" style="transform: rotate(0)">
            This <a href="#" class="stretched-link">stretched link</a>
            will only be spread over the p-tag, because a transform is
            applied to it.
        </p>

    Accessibility

    The .stretched-link utility is entirely CSS-driven — no ARIA roles or attributes are added to the ::after pseudo-element. The underlying <a> element retains full native link semantics and must meet standard link accessibility requirements.

    • Descriptive link text. Screen readers announce only the text inside the <a> element — not the surrounding card or container content. Use text that identifies the destination or action, such as "View Case #1001" rather than "Read more".
    • aria-label for disambiguation. When multiple cards on the same page share identical link text (e.g., all say "Go somewhere"), add an aria-label with a fuller description: aria-label="View Case #1001 — Exchange Migration".
    • Keyboard navigation. Users navigate to the link with Tab / Shift+Tab and activate it with Enter. The focus ring renders on the <a> element; verify it is not obscured by the transparent ::after overlay (z-index: 1) in all supported browsers.
    • Avoid multiple stretched links per container. Overlapping ::after overlays produce unpredictable click and focus behaviour. If multiple links are required, use position and z-index overrides carefully — see Identifying the containing block.
    • Section 508 §1194.22(a). All non-text clickable regions must have a text equivalent. The <a> element's text content or aria-label satisfies this requirement. Do not substitute a <div> or <span> with a JavaScript click handler in place of a real <a href> — doing so removes keyboard access and assistive-technology support.

    API Documentation

    Introduction

    The Nimbus stretched-link utility is a CSS-only interaction pattern — no JavaScript initialisation is required. Adding .stretched-link to an <a> element causes its ::after pseudo-element to fill the nearest positioned ancestor (the containing block), making the entire block respond to pointer, touch, and keyboard events as a single link.

    The ::after pseudo-element is positioned absolutely with top: 0; right: 0; bottom: 0; left: 0 and z-index: 1. Any child element with a higher stacking context will remain independently interactive above the overlay. The utility is defined in css/core/interactions.css.

    Usage

    Place an <a href> element anywhere inside an ancestor that has a non-static position value and apply .stretched-link. The entire ancestor becomes clickable. If the ancestor does not already have a non-static position, add .position-relative to establish the containing block.

    HTML
    <!-- Minimum pattern: positioned ancestor + .stretched-link -->
<div class="position-relative">
    <p>Component content</p>
    <a href="/destination" class="stretched-link">Descriptive link text</a>
</div>

    CSS classes

    The following classes control stretched-link behaviour. All classes are CSS-only and require no JavaScript.

    Class Element Description
    .stretched-link <a> Generates a transparent ::after pseudo-element (position: absolute; top: 0; right: 0; bottom: 0; left: 0; z-index: 1) that fills the nearest positioned ancestor, making it fully clickable. Defined in css/core/interactions.css.
    .position-relative any block element Sets position: relative !important. Apply to a wrapper element to establish it as the containing block when it does not already have a non-static position. Defined in css/core/position.css.

    Identifying the containing block

    The ::after pseudo-element is sized and positioned relative to the nearest ancestor whose position is not static. If the stretched link covers a smaller area than expected — or no area at all — an intermediate element is likely acting as an unintended containing block.

    The following CSS properties on any ancestor will make it the containing block and constrain the stretched link to that element's bounds:

    • position set to anything other than static (e.g., relative, absolute, fixed, sticky)
    • transform or perspective set to any value other than none
    • will-change set to transform or perspective
    • filter set to any value other than none, or will-change: filter (Firefox only)

    To diagnose issues, open browser DevTools, inspect the element tree, and look for any intermediate ancestor with one of the above properties. Remove or override the offending property, or restructure the markup so the desired containing block is the nearest positioned ancestor of the .stretched-link.

    Accessibility

    The following requirements apply to all stretched-link implementations:

    • Always use a native <a href> element. Do not substitute a <div>, <span>, or <button> with a click handler — these lack the built-in keyboard navigation and screen-reader semantics of a real link.
    • Provide descriptive link text. Screen readers announce only the content inside the <a> element, not the surrounding card or container.
    • Use aria-label when the visible link text alone is insufficient to identify the destination (e.g., multiple cards on the same page each containing a link labelled "Read more").
    • Verify the focus ring on the <a> element is visible and not obscured by the transparent ::after overlay. Test with keyboard navigation (Tab / Shift+Tab) across all supported browsers.
    • Section 508 §1194.22(a): all non-text clickable regions must have a text equivalent — satisfied by the <a> element's text content or aria-label.
