    v1 Containers
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Containers are a fundamental building block of Nimbus that contain, pad, and align your content within a given device or viewport.

    Nimbus provides three container variants to cover the most common layout needs: .container steps up in max-width at each breakpoint for a constrained reading width, .container-fluid always spans the full viewport width for edge-to-edge layouts like navigation bars and hero sections, and .container-{breakpoint} is fluid below the named breakpoint then switches to fixed-width at and above it. Containers must wrap a .row element for the grid system to work correctly.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    How it works

    Containers are the most basic layout element in Nimbus and are required when using our default grid system. Containers are used to contain, pad, and (sometimes) center the content within them. While containers can be nested, most layouts do not require a nested container.

    Nimbus comes with three different containers:

    • .container — a responsive, fixed-width container whose max-width steps up at each breakpoint (sm, md, lg, xl, xxl), keeping content at an optimal reading width on every screen size.
    • .container-fluid — always width: 100% at every breakpoint, spanning the full width of the viewport. Ideal for full-bleed layouts such as navigation bars and hero sections.
    • .container-{breakpoint} — behaves as width: 100% (fluid) up to the named breakpoint, then switches to the responsive max-width behaviour from that breakpoint upward. For example, .container-md is full-width below 768px and fixed-width from 768px onward.

    Default container

    Our default .container class is a responsive, fixed-width container. Its max-width changes at each breakpoint — for example it is 540px wide at sm, stepping up to 1320px at xxl — keeping content at a comfortable reading width rather than stretching edge to edge on large screens.

    .container — max-width constrained at each breakpoint
    HTML 
    <div class="container">
  <!-- Content here -->
</div>

    Responsive containers

    Responsive containers (.container-{breakpoint}) are width: 100% — fully fluid — up to the specified breakpoint. Once the viewport reaches that breakpoint, the container switches to the same stepped max-width behaviour as .container. For example, .container-sm is 100% wide on extra-small screens and becomes fixed-width from the sm breakpoint (576px) upward, scaling through md, lg, xl, and xxl.

    .container-sm
    .container-md
    .container-lg
    .container-xl
    .container-xxl
    HTML 
    <div class="container-sm">100% wide until small breakpoint</div>
<div class="container-md">100% wide until medium breakpoint</div>
<div class="container-lg">100% wide until large breakpoint</div>
<div class="container-xl">100% wide until extra large breakpoint</div>
<div class="container-xxl">100% wide until extra extra large breakpoint</div>

    Fluid containers

    Use .container-fluid for a full-width container that is always width: 100% at every breakpoint, spanning the entire width of the viewport. No max-width is ever applied. This is the right choice for full-bleed layouts — navigation bars, hero banners, and dashboard toolbars that must not be constrained by a max-width.

    .container-fluid — always 100% width
    HTML 
    <div class="container-fluid">
  ...
</div>

    Sass

    As shown above, Nimbus generates a series of predefined container classes to help you build the layouts you desire. You may customize these predefined container classes by modifying the Sass map (found in _variables.scss) that powers them:

    SCSS 
    $container-max-widths: (
  sm: 540px,
  md: 720px,
  lg: 960px,
  xl: 1140px,
  xxl: 1320px
);

    In addition to customizing the Sass, you can also create your own containers with our Sass mixin.

    SCSS 
    // Source mixin
@mixin make-container($padding-x: $container-padding-x) {
  width: 100%;
  padding-right: $padding-x;
  padding-left: $padding-x;
  margin-right: auto;
  margin-left: auto;
}

// Usage
.custom-container {
  @include make-container();
}

    API Documentation

    Container Classes

    The following table lists all available container classes, their behavior, and the breakpoint at which they become fixed-width.

    Class Behavior Fixed-width starts at
    .container Responsive fixed-width container. Sets max-width at each breakpoint. 576px (sm)
    .container-sm 100% wide until the sm breakpoint, then fixed-width. 576px (sm)
    .container-md 100% wide until the md breakpoint, then fixed-width. 768px (md)
    .container-lg 100% wide until the lg breakpoint, then fixed-width. 992px (lg)
    .container-xl 100% wide until the xl breakpoint, then fixed-width. 1200px (xl)
    .container-xxl 100% wide until the xxl breakpoint, then fixed-width. 1400px (xxl)
    .container-fluid Full-width container, always width: 100% at all breakpoints. Never (always fluid)

    CSS Custom Properties

    Container elements use the following CSS custom properties (design tokens) for gutter control.

    Property Default Description
    --cnds-gutter-x 1.5rem Horizontal gutter width. Applied as padding-left and padding-right (half value each side).
    --cnds-gutter-y 0 Vertical gutter width. Not applied by default on containers.

    Accessibility

    Container classes are CSS layout wrappers and carry no ARIA requirements. However, consider the following:

    • The .container and .container-fluid elements are purely presentational — do not assign landmark roles to them. Use semantic HTML elements (<main>, <nav>, <aside>) inside containers to provide accessibility landmarks.
    • Container max-width constraints do not affect the accessibility tree. Content within containers remains fully accessible regardless of the container type used.
