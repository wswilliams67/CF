    v1Input Group
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Input Groups extend form controls by prepending or appending text labels, icons, buttons, or dropdown triggers to a text input, select, or textarea. All content within an .input-group renders as a single joined widget — borders collapse between children, and border-radius is applied only to the outermost corners.

    Use an input group when the addon provides essential context for the field (for example, a currency symbol, a URL prefix, or an action button that operates on the input value). For standalone decorative icons inside the field, use the Input Fields component instead.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Product themes

    Accessibility

    Screen readers will have trouble with your forms if you don't include a label for every input. For input groups, the .input-group-text addon is not announced as a label by default — ensure each <input> has either a visible <label> with a matching for attribute, or an aria-label / aria-labelledby attribute.

    Use aria-describedby on the <input> pointing to the id of the .input-group-text addon when the addon supplies supplementary context (for example, a currency symbol or a domain suffix) rather than a primary label. For icon-only addons, add a <span class="visually-hidden"> inside the .input-group-text to give screen readers a text alternative.

    API Documentation

    Introduction

    The .input-group component is built entirely in CSS — no JavaScript initialisation is required for text, checkbox, radio, or button addons. Dropdown toggle buttons within an input group require data-cnds-dropdown-init on the <button> element; nimbus.js registers the click handler and manages the open/closed state. The component uses a shared set of form custom properties from forms.css — no dedicated input-group variables are defined.

    Usage

    Wrap any combination of .input-group-text, <button>, and .form-control elements inside a .input-group div. The order in the DOM determines the visual left-to-right order.

    HTML
    <div class="input-group">
  <span class="input-group-text" id="desc-addon">@</span>
  <input type="text" class="form-control" aria-label="Username" aria-describedby="desc-addon" />
</div>

    CSS classes

    Class Element Description
    .input-group <div> Required wrapper. display: flex; flex-wrap: wrap; align-items: stretch. All direct children share a collapsed border and joined border-radius.
    .input-group-sm <div> Small size modifier. Scales all children to the form-control-sm height and padding.
    .input-group-lg <div> Large size modifier. Scales all children to the form-control-lg height and padding.
    .input-group-text <span> or <label> Addon container. Renders as a flex row, vertically centred. Shares border and background with the enclosing group.
    .flex-nowrap utility on <div> Prevents the group from wrapping onto a second line (flex-wrap: nowrap).
    .has-validation <div> Signals that the group contains a validated input. Adjusts border-radius so the validation feedback icon is not hidden by rounded corners.

    CSS custom properties

    .input-group inherits the form-control custom properties defined in forms.css. Override any of these on a parent element to restyle the entire group.

    Property Default Description
    --cnds-input-padding-y 0.375rem Vertical padding used by .input-group-text and .form-control.
    --cnds-input-padding-x 0.75rem Horizontal padding used by .input-group-text and .form-control.
    --cnds-input-font-size 1rem Font size for all children. Overridden by input-group-sm / input-group-lg.
    --cnds-input-border-width 1px Border width on .input-group-text and .form-control. Negative margin collapses adjacent borders.
    --cnds-input-border-color var(--cnds-primary-gray-300, #bdbdbd) Shared border color. Theme-aware — overridden in dark mode.
    --cnds-input-border-radius 0.25rem Applied only to the first and last children; inner children have their adjacent corners set to 0.
    --cnds-input-disabled-bg #e9ecef Background of .input-group-text and disabled .form-control.

    Theme variables

    The following properties are overridden in dark.css on the [data-cnds-theme="dark"] selector.

    Token Light value Dark value

    Accessibility

    • Every <input> must have an accessible name. Use a visible <label for="id"> outside the .input-group, or supply aria-label on the input.
    • Use aria-describedby on the <input> pointing to the id of a .input-group-text that supplies supplementary context (units, domain suffix, currency symbol).
    • For icon-only .input-group-text addons, include <span class="visually-hidden">descriptive text</span> inside the addon so screen readers announce the purpose.
    • Dropdown toggle buttons must have aria-expanded="false" set initially; nimbus.js toggles it on open/close.
    • Do not rely on the visual position of addons alone to convey meaning — all context must be available in text through labels or ARIA attributes.
