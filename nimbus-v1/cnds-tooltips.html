    v1Tooltips
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Nimbus Tooltips display brief, informative text when users hover over, focus on, or tap an element. Built on the Nimbus component system and powered by Popper.js for intelligent placement, they surface supplementary context — such as a description of an icon or a clarification of a form field — without cluttering the UI.

    Tooltips are opt-in: each element must be individually initialized using the data-cnds-tooltip-init attribute or via JavaScript. Placement is controlled with data-cnds-placement and defaults to top. Tooltip text is read from the element's native title attribute, which Nimbus moves to an internal store to prevent the browser's own tooltip from appearing alongside it.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Add data-cnds-tooltip-init and a title attribute to any interactive element to activate a tooltip. Nimbus reads the title value, stores it internally, and renders the tooltip on hover or focus. Hover the link below to see it in action — the tooltip defaults to top placement when no data-cnds-placement is specified.

    Hover the link to see the tooltip

    HTML

    <p>
    Hover the link to see the
    <a href="#" data-cnds-tooltip-init title="Hi! I'm tooltip">tooltip</a>
</p>

    Overview

    Before using tooltips, be aware of the following behaviors and constraints:

    • Tooltips are opt-in for performance reasons, so you must initialize them yourself.
    • Tooltips with zero-length titles are never displayed.
    • Specify container: 'body' to avoid rendering problems in more complex components (like our input groups, button groups, etc).
    • Triggering tooltips on hidden elements will not work.
    • Tooltips for .disabled or disabled elements must be triggered on a wrapper element.
    • When triggered from hyperlinks that span multiple lines, tooltips will be centered. Use white-space: nowrap; on your <a>s to avoid this behavior.
    • Tooltips must be hidden before their corresponding elements have been removed from the DOM.
    • Tooltips can be triggered thanks to an element inside a shadow DOM.

    Four directions

    Use data-cnds-placement to control which side of the triggering element the tooltip appears on. Four explicit values are supported: top, right, bottom, and left. Specifying auto lets Popper.js dynamically reorient the tooltip to stay visible within the viewport. Hover the buttons below to see each direction.

    HTML

    <button type="button" class="btn btn-secondary" data-cnds-tooltip-init data-cnds-placement="top" title="Tooltip on top">
    Tooltip on top
</button>
<button type="button" class="btn btn-secondary" data-cnds-tooltip-init data-cnds-placement="right" title="Tooltip on right">
    Tooltip on right
</button>
<button type="button" class="btn btn-secondary" data-cnds-tooltip-init data-cnds-placement="bottom" title="Tooltip on bottom">
    Tooltip on bottom
</button>
<button type="button" class="btn btn-secondary" data-cnds-tooltip-init data-cnds-placement="left" title="Tooltip on left">
    Tooltip on left
</button>

    Set data-cnds-html="true" to render HTML markup inside the tooltip. Only use this when the content is from a trusted source — never pass user-generated strings into an HTML tooltip, as it creates an XSS risk.

    HTML

    <button type="button" class="btn btn-secondary" data-cnds-tooltip-init data-cnds-html="true" title="<em>Tooltip</em> <u>with</u> <b>HTML</b>">
    Tooltip with HTML
</button>

    Disabled elements

    Elements with the disabled attribute aren’t interactive: they dispatch no pointer events and cannot take focus, so a tooltip attached to one would silently never fire. The component handles this for you. Put data-cnds-tooltip-init and the title on the disabled control itself and Tooltip wraps it in an interactive <span>, gives that wrapper the tab stop and the help cursor, moves its own listeners onto it, and stops the control swallowing the pointer.

    No wrapper markup and no inline styles. If a <span class="d-inline-block"> wrapper is already present it is reused rather than doubled, so existing hand-written markup keeps working. Call instance.sync() if the control’s disabled state changes after initialisation.

    Write the title as the reason, not a restatement of the label — “Save requires a title”, not “Save”. The tooltip exists because a dim control says only that nothing will happen; the operator still needs to know why. The wrapper takes cursor: help for that reason rather than not-allowed.

    HTML

    <button class="btn btn-primary" type="button" disabled
        data-cnds-tooltip-init title="Saving requires a case title">
    Disabled button
</button>

<!-- Rendered. The component adds the wrapper; you never write it: -->
<span class="d-inline-block tooltip-disabled-host" tabindex="0"
      data-cnds-tooltip-wrapped="true">
    <button class="btn btn-primary" type="button" disabled
            data-cnds-tooltip-init data-cnds-original-title="Saving requires a case title">
        Disabled button
    </button>
</span>

    API Documentation

    Introduction

    The Nimbus Tooltip is a JavaScript-powered component that displays contextual text when a user hovers, focuses, or taps an element. It is built on Popper.js for intelligent, collision-aware placement — the tooltip automatically repositions to stay within the viewport when the preferred side is clipped. Each tooltip instance is opt-in and must be individually initialized via the data-cnds-tooltip-init attribute or through the JavaScript API.

    The component is fully theme-aware: tooltip background and text colors adapt automatically when the data-cnds-theme="dark" attribute is present on a parent element. All color values meet WCAG AA contrast requirements against their respective theme backgrounds.

    Usage

    Via data attributes

    Using the Tooltip component requires no additional JavaScript code — simply add the data-cnds-tooltip-init attribute to an element and use data-cnds-* attributes to set options.

    HTML
    <button type="button" class="btn btn-secondary" data-cnds-tooltip-init title="Tooltip on top">
    Tooltip on top
</button>
    Via JavaScript
    JAVASCRIPT
    const triggerEl = document.getElementById('myTooltip');
const instance = new Nimbus.Tooltip(triggerEl);
    Overflow auto and scroll

    Tooltip position attempts to automatically change when a parent container has overflow: auto or overflow: scroll like our .table-responsive, but still keeps the original placement's positioning. To resolve, set the boundary option to anything other than the default value, 'scrollParent', such as 'window':

    JAVASCRIPT
    const exampleEl = document.getElementById('example');
const tooltip = new Nimbus.Tooltip(exampleEl, {
  boundary: 'window'
});
    Markup

    The required markup for a tooltip is only a data attribute and title on the HTML element you wish to have a tooltip. The generated markup of a tooltip is rather simple, though it does require a position (by default, set to top by the plugin).

    HTML
    <!-- HTML to write -->
<a href="#" data-cnds-tooltip-init title="Some tooltip text!">Hover over me</a>

<!-- Generated markup by the plugin -->
<div class="tooltip tooltip-top" role="tooltip" data-cnds-placement="top">
    <div class="tooltip-arrow"></div>
    <div class="tooltip-inner">Some tooltip text!</div>
</div>
    Keyboard and assistive technology users

    You should only add tooltips to HTML elements that are traditionally keyboard-focusable and interactive (such as links or form controls). Although arbitrary HTML elements (such as <span>s) can be made focusable by adding the tabindex="0" attribute, this will add potentially annoying and confusing tab stops on non-interactive elements for keyboard users, and most assistive technologies currently do not announce the tooltip in this situation. Additionally, do not rely solely on hover as the trigger for your tooltip, as this will make your tooltips impossible to trigger for keyboard users.

    Options

    Options can be passed via data attributes or JavaScript. For data attributes, append the option name to data-cnds-, as in data-cnds-placement="top".

    Note: For security reasons the sanitize, sanitizeFn and allowList options cannot be supplied using data attributes.

    Name Type Default Description
    animation boolean true Apply a CSS fade transition to the tooltip.
    container string | element | false false Appends the tooltip to a specific element. Example: container: 'body'. This option is particularly useful in that it allows you to position the tooltip in the flow of the document near the triggering element — which will prevent the tooltip from floating away from the triggering element during a window resize.
    customClass string | function '' Add classes to the tooltip when it is shown. These classes are added in addition to any classes specified in the template. To add multiple classes, separate them with spaces: 'class-1 class-2'. You can also pass a function that should return a single string containing additional class names.
    delay number | object 0 Delay showing and hiding the tooltip (ms) — does not apply to manual trigger type. If a number is supplied, delay is applied to both hide/show. Object structure: delay: { "show": 500, "hide": 100 }
    html boolean false Allow HTML in the tooltip. If true, HTML tags in the tooltip's title will be rendered. If false, innerText is used. Use plain text if you're concerned about XSS attacks.
    placement string | function 'top' How to position the tooltip: auto | top | bottom | left | right. When auto is specified, it will dynamically reorient the tooltip. When a function is used, it is called with the tooltip DOM node as its first argument and the triggering element as its second.
    selector string | false false If a selector is provided, tooltip objects will be delegated to the specified targets. Used to apply tooltips to dynamically added DOM elements via event delegation with addEventListener.
    template string '<div class="tooltip" role="tooltip"><div class="tooltip-arrow"></div><div class="tooltip-inner"></div></div>' Base HTML to use when creating the tooltip. The tooltip's title will be injected into .tooltip-inner. .tooltip-arrow becomes the tooltip's arrow. The outermost wrapper must have the .tooltip class and role="tooltip".
    title string | element | function '' Default title value if title attribute isn't present. If a function is given, it will be called with its this reference set to the element the tooltip is attached to.
    trigger string 'hover focus' How the tooltip is triggered: click | hover | focus | manual. Multiple triggers can be separated with a space. 'manual' indicates programmatic triggering only and cannot be combined with other values. 'hover' alone makes tooltips unreachable for keyboard users.
    offset number | string | function 0 Offset of the tooltip relative to its target. When a function is used, it is called with an object containing offset data and must return an object with the same structure. For more information refer to Popper's offset docs.
    fallbackPlacement string | array 'flip' Specify which position Popper will use on fallback. Refer to Popper's behavior docs.
    boundary string | element 'clippingParents' Overflow constraint boundary of the tooltip. Accepts 'viewport', 'window', 'scrollParent', or an HTMLElement reference (JavaScript only). Refer to Popper's detectOverflow docs.
    sanitize boolean true Enable or disable sanitization. If activated, the template and title options will be sanitized.
    allowList object Default value Object which contains allowed attributes and tags.
    sanitizeFn null | function null Supply your own sanitize function. Useful if you prefer a dedicated library to perform sanitization.
    popperConfig null | object null To change Nimbus's default Popper config, see Popper's configuration.

    Data attributes for individual tooltips: Options for individual tooltips can alternatively be specified through the use of data attributes, as explained above.

    Methods

    Asynchronous methods and transitions: All API methods are asynchronous and start a transition. They return to the caller as soon as the transition is started but before it ends. In addition, a method call on a transitioning component will be ignored.

    Name Description Example
    show Reveals an element's tooltip. Returns to the caller before the tooltip has actually been shown (i.e. before the shown.cnds.tooltip event occurs). This is considered a "manual" triggering of the tooltip. Tooltips whose title and content are both zero-length are never displayed. instance.show()
    hide Hides an element's tooltip. Returns to the caller before the tooltip has actually been hidden (i.e. before the hidden.cnds.tooltip event occurs). This is considered a "manual" triggering of the tooltip. instance.hide()
    toggle Toggles an element's tooltip. Returns to the caller before the tooltip has actually been shown or hidden (i.e. before the shown.cnds.tooltip or hidden.cnds.tooltip event occurs). This is considered a "manual" triggering of the tooltip. instance.toggle()
    dispose Hides and destroys an element's tooltip. Tooltips that use delegation (created using the selector option) cannot be individually destroyed on descendant trigger elements. instance.dispose()
    getInstance Static method which allows you to get the tooltip instance associated to a DOM element. Nimbus.Tooltip.getInstance(el)
    getOrCreateInstance Static method which allows you to get the tooltip instance associated with a DOM element or create a new one in case it wasn't initialized. Nimbus.Tooltip.getOrCreateInstance(el)
    enable Gives an element's tooltip the ability to be shown. Tooltips are enabled by default. instance.enable()
    disable Removes the ability for an element's tooltip to be shown. The tooltip will only be able to be shown if it is re-enabled. instance.disable()
    toggleEnabled Toggles the ability for an element's tooltip to be shown or hidden. instance.toggleEnabled()
    update Updates the position of an element's tooltip. instance.update()
    JAVASCRIPT
    const tooltipEl = document.getElementById('myTooltip');
const tooltip = new Nimbus.Tooltip(tooltipEl);
tooltip.show();

    Events

    All tooltip events are fired on the trigger element (the element with data-cnds-tooltip-init or initialized via JavaScript), not on the generated tooltip bubble. Listen for events using addEventListener on that element.

    Event type Description
    show.cnds.tooltip Fires immediately when the show instance method is called.
    shown.cnds.tooltip Fires when the tooltip has been made visible to the user (waits for CSS transitions to complete).
    hide.cnds.tooltip Fires immediately when the hide instance method has been called.
    hidden.cnds.tooltip Fires when the tooltip has finished being hidden from the user (waits for CSS transitions to complete).
    inserted.cnds.tooltip Fires after the show.cnds.tooltip event when the tooltip template has been added to the DOM.
    JAVASCRIPT
    const tooltipEl = document.getElementById('myTooltip');
tooltipEl.addEventListener('hidden.cnds.tooltip', () => {
  // do something...
});

    CSS custom properties

    All custom properties are defined on .tooltip in tooltips.css and can be overridden per-instance (inline style attribute) or globally via a CSS rule targeting .tooltip.

    Property Default Description
    --cnds-tooltip-zindex var(--cnds-zindex-tooltip, 1080) Stack order of the tooltip element, ensuring it appears above most UI layers.
    --cnds-tooltip-max-width 200px Maximum width of the tooltip bubble. Content wraps when this limit is reached.
    --cnds-tooltip-padding-x 1rem Horizontal padding inside the tooltip bubble.
    --cnds-tooltip-padding-y 0.75rem Vertical padding inside the tooltip bubble.
    --cnds-tooltip-margin (unset) Outer margin of the tooltip element. Unset by default; Popper.js controls offset via the offset option.
    --cnds-tooltip-font-size 0.8125rem Font size of the tooltip text (13 px at the default root size).
    --cnds-tooltip-color var(--cnds-surface-dark-50, #e8e8e8) Text color inside the tooltip. Theme-aware — overridden in dark mode via dark.css.
    --cnds-tooltip-bg var(--cnds-surface-light-800, #525252) Background color of the tooltip bubble and its arrow. Theme-aware — overridden in dark mode via dark.css.
    --cnds-tooltip-border-radius var(--cnds-border-radius, 0.25rem) Corner rounding of the tooltip bubble.
    --cnds-tooltip-opacity 0.9 Opacity of the tooltip when visible. Applied via the .show class added by Nimbus.
    --cnds-tooltip-arrow-width 0.8rem Width of the directional caret. Width and height values swap for left/right placements.
    --cnds-tooltip-arrow-height 0.4rem Height (depth) of the directional caret. Swaps with width for left/right placements.

    Accessibility

    Tooltips are surfaced to assistive technologies via the role="tooltip" attribute set on the generated tooltip element. Nimbus automatically sets the aria-describedby relationship on the trigger element referencing the tooltip's id so screen readers announce the tooltip text when the trigger receives focus.

    • Only add tooltips to keyboard-focusable, interactive elements such as <a>, <button>, or form controls.
    • Tooltips triggered only by hover are inaccessible to keyboard-only users. Always include focus in the trigger — the default 'hover focus' value covers both.
    • If you must attach a tooltip to a non-focusable element (such as a <span>), add tabindex="0" so keyboard users can reach it.
    • Disabled elements cannot receive focus or pointer events. Wrap a disabled element in a <span tabindex="0"> and attach the tooltip to the wrapper — see Disabled elements for an example.
    • Tooltip text should be concise and informative. Avoid duplicating visible label text; use tooltips to add non-essential supplementary context only.

    For the full specification, see the WAI-ARIA Authoring Practices for the tooltip pattern.
