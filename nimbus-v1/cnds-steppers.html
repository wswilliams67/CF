    v1 Stepper
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The CNDS Stepper guides users through a multi-step process by breaking it into discrete, sequenced stages. Steps can be arranged horizontally, vertically, or in a compact mobile layout (dot indicator or progress bar). Navigation can be open — allowing the user to jump to any step — or locked to a strict linear order. Individual steps can be marked optional, decorated with custom icons, or wired to per-step form validation so users can only advance when the current step is valid.

    Add data-cnds-stepper-init to any .stepper element to auto-initialize on page load, or call new Nimbus.Stepper(element, options) for programmatic control. Use the stepper for multi-page forms, onboarding flows, configuration wizards, and any process where users must complete steps in order before proceeding.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Linear stepper

    In linear mode the user must complete each step in order before advancing. Add data-cnds-stepper-linear="true" to the .stepper element to enforce this. Clicking an unreached step header or calling to() with a skipped index is silently blocked. Moving forward automatically marks the previous step as completed.

    API Documentation

    Introduction

    The CNDS Stepper component is part of the Nimbus JavaScript namespace. It can be initialized automatically via the data-cnds-stepper-init attribute placed on the .stepper element, or programmatically with new Nimbus.Stepper(element, options). All configuration options can also be set as data-cnds-stepper-* attributes directly on the .stepper element. The stepper supports horizontal, vertical, and mobile layouts with responsive breakpoints, linear navigation enforcement, step validation, and full keyboard accessibility.

    Usage

    Via data attributes

    Using the Stepper component doesn't require any additional JavaScript code — simply add the data-cnds-stepper-init attribute to the .stepper element and use other data-cnds-stepper-* attributes to configure options.

    HTML
    <ul class="stepper" data-cnds-stepper-init data-cnds-stepper-linear="true">
    <li class="stepper-step active">
        <div class="stepper-head">
            <span class="stepper-icon"></span>
            <div class="stepper-label-group">
                <span class="stepper-label">Step 1</span>
                <span class="stepper-sublabel">Details</span>
            </div>
        </div>
        <div class="stepper-content">
            <p>Step 1 content goes here.</p>
            <div class="stepper-actions">
                <button class="btn btn-primary" data-cnds-stepper-next>Next</button>
            </div>
        </div>
    </li>
    <!-- additional .stepper-step items -->
</ul>
    Via JavaScript
    JAVASCRIPT
    const element = document.querySelector('.stepper');
const stepper = new Nimbus.Stepper(element, {
  linear: true,
  animation: true,
  noEditable: false,
  mobileBarBreakpoint: 4
});

    Options

    Options can be passed via data attributes or the JavaScript constructor. For data attributes, use the data-cnds-stepper-* naming pattern (e.g. data-cnds-stepper-linear="true").

    JavaScript configuration options

    Name Data attribute Type Default Description
    animation data-cnds-stepper-animation Boolean true Set to false to disable the slide animation when the active step changes.
    linear data-cnds-stepper-linear Boolean false When true, enforces sequential navigation — users cannot skip ahead more than one step at a time.
    noEditable data-cnds-stepper-no-editable Boolean false When true, prevents navigating back to a completed step to edit it. Completed steps become non-clickable.
    mobileBarBreakpoint data-cnds-stepper-mobile-bar-breakpoint Number 4 The step count threshold above which the mobile stepper displays a progress bar instead of individual dots.

    Additional data attributes

    The following attributes are read directly from the DOM and are not part of the JavaScript configuration object. They are set on the .stepper element (or on individual .stepper-step items where noted).

    Attribute Values Description
    data-cnds-stepper-type "horizontal" | "vertical" | "mobile" Sets the initial layout of the stepper. Defaults to "horizontal" when omitted.
    data-cnds-stepper-vertical-breakpoint Number (px) Viewport width in pixels below which the stepper automatically switches to the vertical layout.
    data-cnds-stepper-mobile-breakpoint Number (px) Viewport width in pixels below which the stepper automatically switches to the mobile layout.
    data-cnds-stepper-optional="true" On .stepper-step <li> Marks a step as optional. The step can be skipped without being marked as completed or errored.

    CSS classes

    The following classes control stepper structure, layout, and state. State classes are toggled automatically by the component JavaScript.

    Class Element Description
    .stepper <ul> Root container. Renders as a horizontal flex row by default. Hosts all CSS custom properties for the component.
    .stepper-vertical <ul> Layout modifier — switches the stepper to a vertical column layout. Applied automatically when the viewport drops below data-cnds-stepper-vertical-breakpoint.
    .stepper-mobile <ul> Layout modifier — switches to the compact mobile layout with a progress indicator. Applied automatically below data-cnds-stepper-mobile-breakpoint.
    .stepper-step <li> Individual step wrapper. Contains the step head and content panel.
    .stepper-head element inside .stepper-step Clickable step header containing the icon, label, and optional sublabel. Clicking navigates to that step (unless disabled or noEditable is set).
    .stepper-icon element inside .stepper-head Circular step indicator. Displays an auto-incrementing counter by default. Place an <i> element inside to show a custom icon instead.
    .stepper-label element inside .stepper-head Primary step label text.
    .stepper-sublabel element inside .stepper-head Optional secondary label displayed below the primary label.
    .stepper-label-group element inside .stepper-head Flex column wrapper for .stepper-label and .stepper-sublabel. Use when both are present.
    .stepper-content element inside .stepper-step Collapsible content panel for the step. Visible only when the parent .stepper-step has the .active class.
    .stepper-actions element inside .stepper-content Flex wrapper for navigation buttons (Back / Next) within a step's content panel.
    .active .stepper-step State — the currently visible step. Only one step carries this class at a time.
    .completed .stepper-step State — the step has been validated and passed. The icon shows a checkmark.
    .editable .stepper-step State — applied when the user navigates back to a completed step to edit it.
    .error .stepper-step State — the step has a validation error. The icon shows an error indicator.
    .disabled .stepper-step State — the step is not clickable or navigable.

    Methods

    Name Description Example
    next() Advance to the next step stepper.next()
    prev() Return to the previous step stepper.prev()
    to(index) Navigate to the step at the given zero-based index. In linear mode, jumping ahead more than one step is silently blocked. stepper.to(2)
    completeStep(index) Mark the step at the given index as completed (defaults to the current step). Fires stepComplete.cnds.stepper. stepper.completeStep()
    setError(index) Apply the error state to the step at the given index (defaults to the current step). stepper.setError()
    reset() Remove all active, completed, and error states and return to step 0. stepper.reset()
    getInstance Static method which allows you to get the stepper instance associated to a DOM element. Nimbus.Stepper.getInstance(el)
    getOrCreateInstance Static method which returns the stepper instance associated to a DOM element or creates a new one in case it wasn't initialized. Nimbus.Stepper.getOrCreateInstance(el)
    JAVASCRIPT
    const myStepperEl = document.getElementById('stepper');
const stepper = new Nimbus.Stepper(myStepperEl);
stepper.next();

    Events

    Name Description
    stepChange.cnds.stepper Fired on the .stepper element before the active step changes. Call e.preventDefault() to cancel the navigation. Event detail: { from: number, to: number }.
    stepComplete.cnds.stepper Fired on the .stepper element when a step is marked completed (either by moving forward or by calling completeStep()). Event detail: { step: number }.
    complete.cnds.stepper Fired on the .stepper element when the last step is reached and all steps have been marked completed.
    JAVASCRIPT
    const stepper = document.querySelector('.stepper');
stepper.addEventListener('stepChange.cnds.stepper', () => {
  // do something...
});

    Accessibility

    The CNDS Stepper does not inject ARIA roles or attributes automatically. Follow the guidance below to meet Section 508 / WCAG 2.1 AA requirements.

    • Add aria-label to the <ul class="stepper"> element (e.g. aria-label="Checkout steps") so screen readers announce the landmark with a meaningful name.
    • Add aria-current="step" to the initially active .stepper-step <li>. Update this attribute dynamically by listening to stepChange.cnds.stepper and moving the attribute to the newly active step on each transition.
    • The .stepper-head element is a <div> that responds to click. To make step navigation keyboard accessible, add tabindex="0" and role="button" to each .stepper-head, or replace the inner markup with a native <button>. Without this, keyboard-only users cannot activate individual steps (WCAG 2.1.1).
    • Add aria-disabled="true" to any .stepper-step that carries the .disabled class so assistive technologies announce the disabled state rather than relying on visual styling alone.
    • Step states — completed, active, error — are currently communicated by color only. Pair each state with a visible text label or an aria-label on the .stepper-icon (e.g. aria-label="Step 1 — completed") so users who cannot distinguish colors understand the state (WCAG 1.4.1).
    • All CNDS semantic color tokens used for step icon states meet WCAG AA contrast requirements (4.5:1 minimum) against both light and dark theme backgrounds.
    • When a step contains a form, wrap required fields with aria-required="true" and associate error messages using aria-describedby pointing to the .cf-input-error element so screen readers announce validation errors inline.

    For full specifications, see WAI-ARIA Authoring Practices and the Section 508 ICT Standards.
