    v1 Popovers
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Nimbus Popovers are contextual floating overlays that display a header and rich body content anchored to a trigger element. Unlike tooltips, popovers are click-triggered, persist until dismissed, and can contain formatted text, links, or structured content — making them suitable for inline help, feature callouts, and supplementary detail panels.

    Popovers are opt-in for performance reasons and must be individually initialized using data-cnds-popover-init or via the Nimbus.Popover JavaScript API. Placement is controlled with data-cnds-placement and supports four directions: top, right, bottom, and left. The component automatically flips to the opposite side when the preferred placement would overflow the viewport, and repositions on scroll and resize while open.

    A directional pointer arrow is rendered by default for all four placements and follows the active side when auto-flip engages. The arrow can be hidden per-component or globally by setting --cnds-popover-arrow-display: none in the appropriate CSS scope. Use the viewportPadding option to reserve clearance from fixed chrome such as sticky headers or floating toolbars.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Click the button below to open a popover. The popover displays a header set by the title attribute and a body set by data-cnds-content. It closes when you click outside it or click the trigger again.

    HTML

    <button type="button" class="btn btn-lg btn-primary" data-cnds-popover-init title="Popover title" data-cnds-content="And here's some amazing content. It's very engaging. Right?">
    Click to toggle popover
</button>

    Overview

    Things to know when using the Nimbus Popover component:

    • Popovers are opt-in for performance reasons — you must initialize them yourself.
    • A popover with zero-length title and content will never be displayed.
    • Triggering popovers on hidden elements will not work.
    • Popovers on .disabled or disabled elements must be triggered from a wrapper element — see Disabled elements.
    • When triggered from anchors that wrap across multiple lines, popovers will be centered across the anchors’ combined width. Use .text-nowrap on <a> elements to prevent this.
    • Popovers must be hidden before their corresponding trigger elements are removed from the DOM.
    • Popovers can be triggered from an element inside a shadow DOM.

    Four directions

    Use data-cnds-placement to control where the popover appears relative to its trigger — top, right, bottom, or left. The default is right.

    HTML

    <button type="button" class="btn btn-secondary" data-cnds-popover-init data-cnds-placement="top" data-cnds-content="Vivamus sagittis lacus vel augue laoreet rutrum faucibus.">
    Popover on top
</button>

<button type="button" class="btn btn-secondary" data-cnds-popover-init data-cnds-placement="right" data-cnds-content="Vivamus sagittis lacus vel augue laoreet rutrum faucibus.">
    Popover on right
</button>

<button type="button" class="btn btn-secondary" data-cnds-popover-init data-cnds-placement="bottom" data-cnds-content="Vivamus sagittis lacus vel augue laoreet rutrum faucibus.">
    Popover on bottom
</button>

<button type="button" class="btn btn-secondary" data-cnds-popover-init data-cnds-placement="left" data-cnds-content="Vivamus sagittis lacus vel augue laoreet rutrum faucibus.">
    Popover on left
</button>

    Dismiss on next click

    Use data-cnds-trigger="focus" to dismiss the popover when the user clicks or focuses any other element. This is commonly used for popovers that should close as soon as the user moves on.

    Specific markup required for dismiss-on-next-click:
    For consistent cross-browser behavior, use an <a> element — not <button> — and include a tabindex attribute so keyboard users can trigger and dismiss it.

    Dismissible popover

    HTML

    <a tabindex="0" class="btn btn-lg btn-primary" role="button" data-cnds-popover-init data-cnds-trigger="focus" title="Dismissible popover" data-cnds-content="And here’s some amazing content. It’s very engaging. Right?">
    Dismissible popover
</a>

    Disabled elements

    Disabled elements ignore pointer and focus events, so popovers cannot be triggered on them directly. Wrap the disabled element in a <span> with tabindex="0", attach data-cnds-popover-init to the wrapper, and set pointer-events: none on the inner button so hover events reach the wrapper.

    Use data-cnds-trigger="hover" on the wrapper so the popover provides immediate visual feedback — users typically do not expect to click a disabled control.

    HTML

    <span class="d-inline-block" tabindex="0" data-cnds-popover-init data-cnds-trigger="hover" data-cnds-content="This action is currently disabled.">
    <button class="btn btn-primary" style="pointer-events: none" type="button" disabled>Disabled button</button>
</span>

    API Documentation

    Usage

    Via data attributes

    Using the Popovers component doesn't require any additional JavaScript code - simply add data-cnds-popover-init attribute to toggle element and use other data attributes to set all options.

    HTML
    <button type="button" class="btn btn-lg btn-primary" data-cnds-popover-init title="Popover title" data-cnds-content="And here's some amazing content. It's very engaging. Right?">
    Click to toggle popover
</button>
    Via JavaScript:
    JAVASCRIPT
    const element = document.getElementById('example')
const instance = new Nimbus.Popover(element, options)
    Making popovers work for keyboard and assistive technology users

    To allow keyboard users to activate your popovers, you should only add them to HTML elements that are traditionally keyboard-focusable and interactive (such as links or form controls). Although arbitrary HTML elements (such as <span>s) can be made focusable by adding the tabindex="0" attribute, this will add potentially annoying and confusing tab stops on non-interactive elements for keyboard users, and most assistive technologies currently do not announce the popover’s content in this situation. Additionally, do not rely solely on hover as the trigger for your popovers, as this will make them impossible to trigger for keyboard users.

    While you can insert rich, structured HTML in popovers with the html option, we strongly recommend that you avoid adding an excessive amount of content. The way popovers currently work is that, once displayed, their content is tied to the trigger element with the aria-describedby attribute. As a result, the entirety of the popover’s content will be announced to assistive technology users as one long, uninterrupted stream.

    Additionally, while it is possible to also include interactive controls (such as form elements or links) in your popover (by adding these elements to the allowList or allowed attributes and tags), be aware that currently the popover does not manage keyboard focus order. When a keyboard user opens a popover, focus remains on the triggering element, and as the popover usually does not immediately follow the trigger in the document’s structure, there is no guarantee that moving forward/pressing TAB will move a keyboard user into the popover itself. In short, simply adding interactive controls to a popover is likely to make these controls unreachable/unusable for keyboard users and users of assistive technologies, or at the very least make for an illogical overall focus order. In these cases, consider using a modal dialog instead.

    Options

    Options can be passed via data attributes or JavaScript. For data attributes, append the option name to data-cnds-, as in data-cnds-animation="".

    Note: For security reasons the sanitize option cannot be supplied using data attributes.

    Name Type Default Description
    animation boolean true Apply a CSS fade transition to the popover
    container string | element 'body' Appends the popover to a specific element. Defaults to 'body', which lets the popover escape overflow:hidden ancestors. Pass a CSS selector string or a DOM element reference to use a different container.
    content string | element | function ''

    Default content value if data-cnds-content attribute isn't present.

    If a function is given, it will be called with its this reference set to the element that the popover is attached to.

    customClass string | function ''

    Add classes to the popover when it is shown. Note that these classes will be added in addition to any classes specified in the template. To add multiple classes, separate them with spaces: 'class-1 class-2'.

    You can also pass a function that should return a single string containing additional class names.

    delay number | object 0

    Delay showing and hiding the popover (ms) - does not apply to manual trigger type

    If a number is supplied, delay is applied to both hide/show

    Object structure is: delay: { "show": 500, "hide": 100 }

    html boolean false Insert HTML into the popover. If false, innerText property will be used to insert content into the DOM. Use text if you're worried about XSS attacks.
    placement string 'right' Preferred side for the popover: 'top', 'right', 'bottom', or 'left'. The component automatically flips to the opposite side when the preferred placement would overflow the viewport — no extra configuration required.
    title string | element | function ''

    Default title value if title attribute isn't present.

    If a function is given, it will be called with its this reference set to the element that the popover is attached to.

    trigger string 'click' How popover is triggered - click | hover | focus | manual. You may pass multiple triggers; separate them with a space. manual cannot be combined with any other trigger.
    offset array | string [0, 12] Pixel offset of the popover relative to its trigger. Accepts an array [skid, distance] or a comma-separated string "0, 12". skid shifts the popover along the trigger axis; distance controls the gap between the trigger and the arrow.
    sanitize boolean true When true, content and title strings are sanitized before insertion. Set to false only when html: true and the source is trusted.
    dismissOnOutsideClick boolean true When true, a click anywhere outside the popover or its trigger element hides the popover automatically.
    viewportPadding number | object 8 Minimum distance (px) the popover must maintain from each viewport edge. Accepts a single number (applied to all four sides) or an object with individual top, bottom, left, and right values. Use this to clear fixed chrome: e.g. viewportPadding: { top: headerHeight + 8, bottom: pagerHeight + 8, left: 8, right: 8 }.

    Data attributes for individual popovers:
    Options for individual popovers can alternatively be specified through the use of data attributes, as explained above.

    CSS customization tokens
    Token Default Description
    --cnds-popover-arrow-display block Controls arrow visibility. Set to none on the .popover element or a customClass scope to suppress the arrow for a specific variant.
    Example: .my-popover { --cnds-popover-arrow-display: none; }
    --cnds-popover-arrow-width 1rem Base spread of the arrow triangle (perpendicular to the tip direction).
    --cnds-popover-arrow-height 0.5rem Depth of the arrow triangle (along the tip direction).
    --cnds-popover-max-width 276px Maximum width of the popover panel.

    Methods

    Asynchronous methods and transitions:
    All API methods are asynchronous and start a transition. They return to the caller as soon as the transition is started but before it ends. In addition, a method call on a transitioning component will be ignored.

    Method Description Example
    show Reveals an element’s popover. Returns to the caller before the popover has actually been shown (i.e. before the shown.cnds.popover event occurs). This is considered a “manual” triggering of the popover. Popovers whose title and content are both zero-length are never displayed. myPopover.show()
    hide Hides an element’s popover. Returns to the caller before the popover has actually been hidden (i.e. before the hidden.cnds.popover event occurs). This is considered a “manual” triggering of the popover. myPopover.hide()
    toggle Toggles an element’s popover. Returns to the caller before the popover has actually been shown or hidden (i.e. before the shown.cnds.popover or hidden.cnds.popover event occurs). This is considered a “manual” triggering of the popover. myPopover.toggle()
    dispose Hides and destroys an element’s popover. Popovers that use delegation (which are created using the selector option) cannot be individually destroyed on descendant trigger elements. myPopover.dispose()
    enable Gives an element’s popover the ability to be shown. Popovers are enabled by default. myPopover.enable()
    disable Removes the ability for an element’s popover to be shown. The popover will only be able to be shown if it is re-enabled. myPopover.disable()
    toggleEnabled Toggles the ability for an element’s popover to be shown or hidden. myPopover.toggleEnabled()
    update Updates the position of an element’s popover. myPopover.update()
    getInstance Static method which allows you to get the popover instance associated with a DOM element. Nimbus.Popover.getInstance(element)
    getOrCreateInstance Static method which allows you to get the popover instance associated with a DOM element or create a new one in case it wasn't initialized. Nimbus.Popover.getOrCreateInstance(element)
    JAVASCRIPT
    const exampleTriggerEl = document.getElementById('example')
const popover = new Nimbus.Popover(exampleTriggerEl)
popover.show()

    Events

    Event type Description
    show.cnds.popover This event fires immediately when the show instance method is called.
    shown.cnds.popover This event is fired when the popover has been made visible to the user (will wait for CSS transitions to complete).
    hide.cnds.popover This event is fired immediately when the hide instance method has been called.
    hidden.cnds.popover This event is fired when the popover has finished being hidden from the user (will wait for CSS transitions to complete).
    inserted.cnds.popover This event is fired after the show.cnds.popover event when the popover template has been added to the DOM.
    JAVASCRIPT
    const myPopoverTrigger = document.getElementById('myPopover')
myPopoverTrigger.addEventListener('hidden.cnds.popover', () => {
  // do something...
})
