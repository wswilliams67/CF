    v1Vertical rule
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The vertical rule (<div class="vr">) is a thin, inline-block element that renders a vertical divider line within horizontal layouts. Inspired by the HTML <hr> element, it stretches automatically to fill the cross-axis of any flex or hstack container, making it ideal for separating toolbar actions, statistic columns, and inline content groups.

    By default the rule is 2px wide and inherits the current text color at reduced opacity, so it adapts automatically to light and dark themes without any override. Apply a bg-* semantic color class to give the divider a deliberate hue — for example bg-success for a status indicator or bg-secondary for a neutral separator. Combine the rule with the .hstack utility or a flex container to create evenly spaced, aligned groups of inline controls, statistics, or labels.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    How it works

    Vertical rules share their behavioral model with the <hr> element, allowing you to create vertical dividers in common horizontal layouts. They are styled with the following fixed characteristics:

    • They are 2px wide by default
    • They have a min-height of 1em
    • Their color is drawn from currentColor at reduced opacity — override with any bg-* utility to apply a solid semantic color
    • Inside a flex container they use align-self: stretch to fill the container's cross-axis automatically

    Customize them with additional utility classes as needed.

    Example

    Apply .vr to an empty <div> to render a vertical divider. Without an explicit background-color utility the rule inherits the current text color at reduced opacity. The nine variants below demonstrate the default appearance followed by each semantic bg-* color class. Add aria-hidden="true" to every .vr element — it is decorative and must be removed from the accessibility tree.

    <div class="hstack gap-3">
  <div class="vr" aria-hidden="true"></div>

  <div class="vr bg-info" aria-hidden="true"></div>
  <div class="vr bg-light" aria-hidden="true"></div>
  <div class="vr bg-dark" aria-hidden="true"></div>

    API Documentation

    Introduction

    The Nimbus vertical rule component is a CSS-only layout utility — no JavaScript initialisation is required. It is implemented as an inline-block element with align-self: stretch so it automatically fills the cross-axis of any flex container. Color is determined by currentColor at reduced opacity, making the rule theme-aware without additional overrides. Apply any bg-* utility class to override the color with a solid semantic value.

    The .vr-blurry modifier is also CSS-only. It applies a gradient that fades to transparent at both ends, producing a softer visual separator. Both variants adapt automatically when the data-cnds-theme="dark" attribute is present on the <html> element.

    Usage

    Place an empty <div class="vr"> wherever a vertical separator is needed inside a flex or hstack container. Because the rule is a decorative element that conveys no information to assistive technologies, always add aria-hidden="true" to remove it from the accessibility tree.

    HTML
    <!-- Minimum markup: vr inside an hstack -->
<div class="hstack gap-3">
  <span>Item one</span>
  <div class="vr" aria-hidden="true"></div>
  <span>Item two</span>
</div>

    CSS classes

    The following classes control vertical rule structure and appearance. All classes are CSS-only and require no JavaScript.

    Class Element Description
    .vr <div> Vertical rule base class. Renders as display: inline-block with align-self: stretch inside flex containers. Width is var(--cnds-border-width). Color inherits from currentColor at reduced opacity. Always pair with aria-hidden="true".
    .vr-blurry <div> Modifier applied alongside .vr. Replaces the solid background with a CSS gradient that fades to transparent at both ends. Specify an explicit height or rely on flex stretch to control the rule's length.
    .vr.bg-* <div> Any Nimbus background-color utility (bg-primary, bg-secondary, bg-success, bg-danger, bg-warning, bg-info, bg-light, bg-dark) can be combined with .vr to apply a solid semantic color, overriding the default currentColor inheritance.

    CSS custom properties

    The vertical rule element respects the following global Nimbus CSS custom properties defined in nimbus.css. Override them on the .vr element inline or via a CSS rule to adjust individual instances.

    Property Default Description
    --cnds-border-width 2px Controls the width (thickness) of the vertical rule. Defined globally in nimbus.css; override on the .vr element inline to change a single instance.
    --cnds-border-opacity 0.25 The opacity applied to the rule's currentColor when no bg-* utility class is present. Lower values produce a more subtle rule; higher values increase visibility.

    Theme variables

    The vertical rule component adapts to the active theme automatically. The default .vr draws its color from currentColor, which resolves to the theme's body text color — dark in light mode and light in dark mode. No explicit theme variable overrides are required for the base rule.

    The .vr-blurry modifier uses a CSS gradient derived from the same currentColor source, so it also adapts when the theme changes without additional configuration. When a bg-* utility class is applied, the color resolves to the corresponding Nimbus semantic token defined in light.css and overridden in dark.css, ensuring consistent contrast across both themes.

    Since vertical rules are purely decorative, they are excluded from WCAG success criteria 1.4.3 (Contrast: Minimum) and 1.4.11 (Non-text Contrast). No contrast validation is required for .vr or .vr-blurry.

    Accessibility

    Vertical rules are decorative visual elements that convey no semantic information to users. Follow these guidelines for an accessible implementation:

    • Always add aria-hidden="true" to every .vr element to remove it from the accessibility tree. Without this attribute, screen readers announce an unnamed generic element, which is confusing to keyboard users.
    • Do not use .vr as a structural separator that carries meaning (for example, separating distinct navigation regions). Use a labelled <hr> or an element with role="separator" and an accessible name instead.
    • The default <div> element is not focusable and requires no additional changes to remain out of the keyboard tab order.
    • When positioned absolutely inside a column (as in the practical example), confirm the containing block has position: relative so the rule does not escape its intended layout boundary.

    For comprehensive guidance on decorative content, see the WAI-ARIA understanding document for non-text content (WCAG 1.1.1).
