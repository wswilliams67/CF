Introduction

The Header module provides two complementary navigation bars that together form the complete application header. The Utility Navigation Bar (.nav-cf-utility) is a slim, always-dark strip that carries product branding, global search, notifications, theme switching, portal selection, and authentication. The Main Navigation Bar sits directly below and houses the product tab navigation — the primary mechanism for moving between top-level application views.

The utility bar always renders on --cnds-surface-dark-600 (#171717) regardless of the active page theme. It spans the full viewport width and remains fluid at all breakpoints. A .ca-title-bar strip optionally sits below the main nav, displaying a back button, the current page title, a section label, and a product-colored accent stripe.

The left region (.fr_logo) holds the product logo image and two-part product name (.product-bold / .product-light). The right region (.fr_tools) is a flex row of icon buttons, dividers, and interactive widgets separated by .utility-divider rules. A 48 px gap separates the two regions.

Note: Read the API Documentation to find all available CSS classes, custom properties, options, and methods.

Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

Utility Navigation Bar

The logged-out state renders the product logo and name on the left. On the right, the tools strip contains a global search toggle, a notifications bell with an unread-count badge, a theme toggle, a portal switcher, and a Sign In affordance. Vertical dividers (.utility-divider) separate each tool group. The demos below show the minimal structure; the HTML example shows a complete logged-out implementation.

The search toggle (.nav-search-toggle) opens an animated panel that expands horizontally into the tools strip. The panel contains a text input (.nav-search-input), an inline clear button (.nav-search-clear-btn), a Submit button (.nav-search-submit), and an Advanced Search filter button (.nav-search-filter-btn). When the panel expands beyond the available space, the portal name and user name labels collapse automatically via the .nav-labels-collapsed modifier.

The notifications bell toggles between mdi-bell (unread items present) and mdi-bell-outline (all read). A red numeric badge (.nav-bell-badge) is overlaid on the icon and announced to screen readers via aria-live="polite". Clicking the bell opens a scrollable .notif-popover listing each notification with subject, timestamp, expand, and dismiss controls.

Logged In State

When a user is authenticated, replace the Sign In item with a .user-info-wrapper containing a 24 px circular avatar (.user-avatar) and the user's display name (.user-name-label). Clicking the wrapper opens an account dropdown (.account-menu) with Preferences and Sign Out actions.

The portal switcher (.portal-switcher-wrapper) displays the current portal name alongside a chevron icon. Clicking opens a dropdown listing all available portals; the active one carries the .active modifier. Both the portal dropdown and the account menu share the .account-menu pattern — a labelled header row, item links, and a CSS triangle arrow that centers itself over the trigger element via the --menu-arrow-outer / --menu-arrow-inner custom properties set by setMenuArrow().

In the logged-in state the search panel also includes a Topic multi-select (data-cnds-select-init with data-cnds-count-label). Selecting a single topic shows its name in the trigger; selecting more than one shows a count (e.g., 2 topics). The All option deselects all others and closes the dropdown; deselecting every specific option automatically restores All. Size the select to its longest option by calling fitSelectToLongestOption() inside a cnds.ready event listener.

Main Navigation Bar

The Main Navigation Bar (.navbar.navbar-cf) is the primary application header. It sits directly below the Utility Navigation Bar in the sticky header stack and renders at a fixed 56 px height on a theme-aware background (--cnds-navbar-bg). All content is centered within a fluid container and the bar collapses to a hamburger toggler below the configured breakpoint.

All three Cloudficient products use the Nimbus tab component (.nav-tabs-nimbus) as the primary navigation mechanism inside the main nav bar, wrapped in a product-specific container that controls the surface colour and active indicator: .ca-main-nav-wrapper for CaseFusion (green indicator), .eo-main-nav-wrapper for ExpireOn (indigo indicator), and .hl-main-nav-wrapper for Hyperlize (yellow indicator). Each wrapper provides rounded corners, padding, and theme-aware background switching.

CaseFusion

CaseFusion applications use the Nimbus tab component (.nav-tabs-nimbus.nav-tabs-casefusion) as the primary navigation mechanism inside the main nav bar. Each tab maps to a top-level application view. The tab bar renders on a dark surface with a green active indicator (--nimbus-tab-indicator: #5ccb59) and sits directly below the Utility Navigation Bar in the sticky header stack. Tab overflow is handled automatically — tabs that do not fit collapse into a ⋮ overflow dropdown that opens above all page content via the shared overflow portal. The dropdown closes when the user scrolls the page or clicks outside it, and stays open while the viewport is resized horizontally.

API Documentation

Introduction

The CNDS navbar module covers two distinct components. The Base Navbar (.navbar) is a general-purpose, responsive navigation bar driven entirely by CSS — no JavaScript is required for layout or theming. It supports collapsible content, brand links, nav links, and a mobile toggler through a set of CSS custom properties and breakpoint-based expand modifiers.

The Utility Navigation Bar (.nav-cf-utility) is a slim, always-dark header strip that sits above the main navigation. It has no Nimbus component class — interactive regions (search panel, notification popover, portal switcher, account menu) are wired via plain JavaScript. The bar always renders on --cnds-nav-utility-bg (#171717) regardless of the active page theme. The left region (.fr_logo) holds the product mark and two-part name; the right region (.fr_tools) is a flex row of icon buttons, dividers, and interactive widgets.

CSS classes

Base navbar

The following classes are defined in css/components/navbar.css and control the responsive, collapsible main navigation bar. All classes are CSS-only.

Class Element Description
.navbar any Root element. Flex container; hosts all --cnds-navbar-* custom properties.
.navbar-brand <a> Brand/logo link. Applies brand padding, font size, and color tokens.
.navbar-nav <ul> Navigation link list. Vertical flex by default; becomes horizontal when the navbar expands.
.nav-link <a> / <button> Individual navigation link. Applies color, padding, and transition tokens. Add .active for the current page or .disabled to disable.
.navbar-text any Plain inline text in the navbar, styled with the navbar color token.
.navbar-collapse <div> Collapsible content container. Shown/hidden by the toggler below the expand breakpoint.
.navbar-toggler <button> Mobile toggle button. Hidden above the expand breakpoint.
.navbar-toggler-icon <span> Hamburger icon inside the toggler, rendered via background-image.
.navbar-nav-scroll <div> Wraps a .navbar-nav to enable vertical scrolling when the collapsed menu is taller than the viewport.
.navbar-expand .navbar Always-expanded variant. Never collapses regardless of viewport width.
.navbar-expand-{sm|md|lg|xl|xxl} .navbar Expands at the specified breakpoint (576 px, 768 px, 992 px, 1200 px, 1400 px). Below the breakpoint, content collapses behind the toggler.
Utility navigation bar

The following classes define the structure and state of the utility navigation bar. Layout classes are CSS-only; state modifiers (.open, .active) are toggled by JavaScript.

Class Element Description
.nav-cf-utility <nav> Root element. Sets the dark background, height, and flex layout.
.fr_logo <div> Left region. Contains the product logo image and .fr_product-name.
.fr_product-name <div> Flex row for the two-part product name.
.product-bold <span> Bold portion of the product name.
.product-light <span> Light-weight portion of the product name.
.fr_tools <div> Right region. Flex row containing all tool widgets and dividers.
.utility-divider <span> 1 px vertical rule that separates tool groups. Decorative — add aria-hidden="true".
.nav-search-wrapper <div> Flex container for the search toggle button and animated panel.
.nav-search-panel <div> Animated slide-in panel. Hidden by default; add .open to show. Manage aria-hidden in sync.
.nav-search-fields <div> Inner flex row holding the input, topic selector, Submit, and filter button.
.nav-search-input-wrapper <div> Relative wrapper for the text input and inline clear button.
.nav-search-toggle <button> Icon button that opens and closes the search panel. Add .active when the panel is open.
.nav-search-submit <button> Tertiary-style Search button inside the panel.
.nav-search-filter-btn <button> Advanced-search icon button inside the panel.
.nav-icon-btn <button> Generic utility icon button (bell, theme toggle).
.nav-bell-badge <span> Unread-count badge overlaid on the bell icon. Hidden when empty.
.notif-popover <div> Notification popover panel. Hidden by default; add .open to show.
.notif-header <div> Popover header row with title and unread/total counts. Add .scrolled to render a drop shadow when the list is scrolled.
.notif-item <div> Single notification row. Add .unread for bold subject and red dot; add .expanded to reveal the message body.
.notif-expand <button> Chevron button that expands the notification message body.
.notif-dismiss <button> Close button that removes the notification from the list.
.portal-switcher-wrapper <div> Relative wrapper for the portal trigger and dropdown menu.
.portal-switcher <span> Inline trigger displaying the current portal name and chevron.
.portal-switcher-label <span> Portal name text. Collapses to zero width when the search panel needs the space.

JavaScript

The utility navigation bar has no Nimbus component class. All interactive behaviors — search panel animation, notification popover, portal and account menus, label collapse, and tooltips — are wired via a single initialization function scoped to a prefix string that disambiguates multiple instances on the same page.

Functions
Function Signature Description
initDemoNav initDemoNav(prefix) Wires all interactive behaviors for a nav instance. prefix is prepended to each element ID to support multiple instances on one page.
renderDemoNotifications renderDemoNotifications(listEl, data) Populates a .notif-list element from an array of notification objects with subject, timestamp, message, and unread properties.
updateCounts updateCounts(popoverEl, listEl) Refreshes the unread and total count text in .notif-count-unread and .notif-count-total.
updateBellState updateBellState(bellIconEl, bellBadgeEl, listEl) Toggles the bell icon between mdi-bell (unread items) and mdi-bell-outline (all read) and sets the badge count. Clears the badge text when count is zero.
fitSelectToLongestOption fitSelectToLongestOption(id) Patches a Nimbus Select instance to match the trigger and dropdown widths to the longest option text using Canvas measureText. Must be called after cnds.ready.
attachTooltipBelow attachTooltipBelow(el, tip[, guard]) Attaches mouseenter / mouseleave tooltip behavior to el. Reads data-tooltip for text. The optional guard callback suppresses the tooltip when it returns true.
setMenuArrow setMenuArrow(menu, trigger) Sets --menu-arrow-outer and --menu-arrow-inner CSS custom properties on menu so the CSS triangle arrow centers horizontally over the trigger element.
initTabOverflow initTabOverflow(nav) — auto-applied Called automatically for every .nav-tabs-nimbus:not(.flex-column) at page load. Creates the ⋮ overflow button (.nav-tabs-more-btn) and dropdown (.nav-tabs-more-dropdown), inserts the shared #cnds-tab-overflow-portal into <body>, and wires a ResizeObserver to recalculate overflow on container resize. Do not call manually.

The overflow menu requires no manual initialization — initTabOverflow is applied to all qualifying tab bars automatically. A single #cnds-tab-overflow-portal overlay is shared across all tab bar instances; dropdowns teleport into it on open and return to their .nav-tabs-more-item on close.

Data attributes
Attribute Element Description
data-tooltip any interactive element Tooltip text displayed by attachTooltipBelow(). Update dynamically to change the tooltip label on state change (e.g., "Open search" → "Close search").
data-cnds-count-label <select> Label suffix appended to the count when more than one option is selected (e.g., "topics" → "2 topics"). Patched by fitSelectToLongestOption().

Accessibility

The following ARIA attributes are required for a Section 508 / WCAG 2.1 AA compliant utility navigation bar:

  • Add aria-label to the root <nav> to distinguish it from other navigation landmarks on the page.
  • Add aria-hidden="true" to all decorative icon <span> and <i> elements so screen readers skip them.
  • Add aria-hidden="true" to .nav-search-panel when closed; remove the attribute when open.
  • Add aria-expanded, aria-controls, and a descriptive aria-label to every toggle button. Update aria-expanded and aria-label dynamically when state changes.
  • Add aria-haspopup="dialog" to the notifications bell button; add role="dialog", aria-modal="true", and aria-label to the popover panel.
  • Add aria-haspopup="menu" to portal and account triggers; add role="menu" to each .account-menu and role="menuitem" to each .account-menu-item.
  • Add role="button" and tabindex="0" to <span> elements used as interactive triggers (.portal-switcher, .user-info).
  • Add aria-live="polite" and aria-atomic="true" to .nav-bell-badge so count changes are announced by screen readers.
  • Add aria-label and tabindex="-1" to the clear button inside the search input.
  • Implement keyboard handlers: Enter / Space to activate triggers, Escape to close any open panel or menu, and ArrowDown / ArrowUp to navigate within menus.

For the full keyboard interaction model, see the WAI-ARIA Authoring Practices Guide.

Behavior

The overflow script is applied automatically to every .nav-tabs-nimbus:not(.flex-column) at page load. When tabs overflow the available width the ⋮ button appears and excess tabs are moved into the dropdown. Clicking the ⋮ button teleports the dropdown into #cnds-tab-overflow-portal and positions it below the button using viewport coordinates. The dropdown closes when the user clicks outside it or scrolls the page; it stays open and repositions when the viewport is resized horizontally. On close, the dropdown returns to its .nav-tabs-more-item container so the ResizeObserver-driven overflow recalculation continues to function correctly.
