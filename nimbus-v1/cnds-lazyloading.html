    v1Lazy Loading
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Lazy Loading defers the download of images, iframes, and background images until they are about to enter the viewport. The component uses the browser-native IntersectionObserver API — no scroll listeners, no polling. When an observed element crosses the viewport boundary, nimbus.js swaps the deferred data-cnds-src into the element's live src and applies a cnds-lazy-loaded CSS class that you can use to trigger reveal transitions. The component auto-initializes on DOMContentLoaded — no JavaScript call required for static content.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Add data-cnds-lazy and data-cnds-src to any <img> or <iframe>. When the element is within 200 px of the viewport, nimbus.js swaps data-cnds-src into src and adds the cnds-lazy-loaded class. Wrap the <img> in a <div class="ll-placeholder"> to show a themed grey box while the asset is in flight — the wrapper approach prevents the broken-image indicator that browsers render on a srcless <img>.

    Scroll down to load images
    HTML
    <!-- ll-placeholder : grey 16:9 wrapper shown while the image loads.
     Wrap the <img> so the placeholder div provides dimensions;
     the <img> itself has no src until IntersectionObserver fires. -->
<div class="ll-placeholder">
  <img
    data-cnds-lazy
    data-cnds-src="img/photo.jpg"
    alt="Description of image"
  />
</div>

    Offset

    By default, the IntersectionObserver begins loading assets 200 px before they enter the viewport (rootMargin "200px 0px"). This pre-fetch buffer ensures images are ready by the time the user scrolls to them. Pass a custom rootMargin to Nimbus.LazyLoad.init() to widen or narrow that buffer for your specific use case — for example, "500px 0px" on image-heavy pages with slower connections, or "0px" for strict on-demand loading.

    Note: Call Nimbus.LazyLoad.destroy() before Nimbus.LazyLoad.init() if you need to change the rootMargin after page load. Calling init() without destroying the previous observer will create a second, independent observer.

    Strict — rootMargin: "0px"

    Image loads only when it enters the visible area

    Keep scrolling…

    Status: Not loaded

    Pre-fetch — rootMargin: "200px 0px"

    Image loads 200 px before entering the visible area

    Keep scrolling…

    JAVASCRIPT
    // Re-initialize the global observer with a wider pre-fetch margin.
// destroy() must be called first to disconnect the previous observer.
Nimbus.LazyLoad.destroy();
Nimbus.LazyLoad.init({ rootMargin: '500px 0px' });

    Error

    When a lazy-loaded asset fails to fetch — broken URL, network error, or server failure — nimbus.js adds the cnds-lazy-error CSS class to the <img> element. Wrap the image in a <div class="ll-error-wrap"> and use the CSS :has() selector to style the wrapper once the error class is present on the child. The example below switches from a grey placeholder to a dashed outline, keeping the layout intact even when individual assets are unavailable.

    Successful load

    Failed load — cnds-lazy-error applied

    HTML
    <!-- ll-error-wrap: grey placeholder that adds a dashed outline
     via :has() once nimbus.js applies cnds-lazy-error to the child img -->
<div class="ll-error-wrap">
  <img
    data-cnds-lazy
    data-cnds-src="img/photo.jpg"
    alt="Description of image"
  />
</div>
    CSS
    /* Grey placeholder wrapper (same as ll-placeholder) */
.ll-error-wrap {
  position: relative;
  display: block;
  background-color: var(--cnds-secondary-bg, #e9ecef);
  border-radius: 0.25rem;
  overflow: hidden;
  aspect-ratio: 16 / 9;
}
/* Switch to red dashed outline once nimbus.js adds cnds-lazy-error to the child img */
.ll-error-wrap:has(> img.cnds-lazy-error) {
  border: 2px dashed var(--cnds-danger, #dc3545);
}
/* Error message overlay — sits above the hidden broken image */
.ll-error-wrap:has(> img.cnds-lazy-error)::after {
  content: "Failed to load";
  position: absolute;
  inset: 0;
  display: flex;
  align-items: center;
  justify-content: center;
  color: var(--cnds-danger, #dc3545);
  font-size: 0.8125rem;
}
/* Image fills wrapper */
.ll-error-wrap > img {
  display: block;
  width: 100%;
  height: auto;
}
/* Hide broken-image indicator */
.ll-error-wrap > img.cnds-lazy-error {
  visibility: hidden;
}

    Animations

    Because nimbus.js adds cnds-lazy-loaded to the element after the asset loads, you can trigger any CSS transition or animation purely in CSS — no additional JavaScript is required. The example below uses the ll-anim helper class (defined in the page <style> block) to fade in and lift each image upward as it loads. Apply the same pattern to any Nimbus animation utility class or custom transition rule.

    HTML
    <!-- Stagger three images using transition-delay on the inner <img> -->
<div class="ll-placeholder">
  <img data-cnds-lazy data-cnds-src="img/photo-1.jpg"
       alt="..." class="ll-anim" />
</div>

<div class="ll-placeholder">
  <img data-cnds-lazy data-cnds-src="img/photo-2.jpg"
       alt="..." class="ll-anim" style="transition-delay: 100ms" />
</div>

<div class="ll-placeholder">
  <img data-cnds-lazy data-cnds-src="img/photo-3.jpg"
       alt="..." class="ll-anim" style="transition-delay: 200ms" />
</div>
    CSS
    /* Start hidden; nimbus.js adds cnds-lazy-loaded after the asset loads */
.ll-anim {
  opacity: 0;
  transform: translateY(10px);
  transition: opacity 0.5s ease, transform 0.5s ease;
}
.ll-anim.cnds-lazy-loaded {
  opacity: 1;
  transform: translateY(0);
}

    Background images

    Use data-cnds-bg to defer background images on any element — not just <img> tags. When the element enters the viewport, nimbus.js sets its background-image CSS property to the URL in data-cnds-bg and adds cnds-lazy-loaded. Pair with a background-color placeholder in CSS so the element has visible dimensions before the image arrives.

    Scroll down to load images
    HTML
    <!-- data-cnds-lazy : registers with IntersectionObserver
     data-cnds-bg   : background-image URL applied on intersection
     role + aria-label : required for accessibility on decorative containers -->
<div
  data-cnds-lazy
  data-cnds-bg="img/hero.jpg"
  class="ll-bg-demo"
  role="img"
  aria-label="Description of background image"
></div>
    CSS
    /* Placeholder: provides visible dimensions and a neutral bg color
   while the background image is in-flight */
.ll-bg-demo {
  min-height: 220px;
  border-radius: 0.375rem;
  background-color: var(--cnds-secondary-bg, #e9ecef);
  background-size: cover;
  background-position: center;
  transition: background-image 0.4s ease;
}

    API Documentation

    Introduction

    The Nimbus LazyLoad component ( js/components/lazy-load.js) wraps the browser-native IntersectionObserver API. On DOMContentLoaded it scans the document for every element matching [data-cnds-lazy] and registers each with a single shared observer.

    When an observed element crosses the configured rootMargin boundary, the component:

    1. Reads data-cnds-src (or data-cnds-lazy if it holds a URL) and sets the element's src.
    2. Reads data-cnds-srcset and sets srcset on <img> elements.
    3. Reads data-cnds-bg and sets style.backgroundImage on any element.
    4. Adds cnds-lazy-loaded after a successful load, or cnds-lazy-error on failure.
    5. Removes the data-cnds-lazy, data-cnds-src, and data-cnds-srcset attributes and stops observing the element.

    If IntersectionObserver is not available, all elements are loaded immediately as a fallback.

    Usage

    The component auto-initializes — no JavaScript is needed for static content. For elements inserted into the DOM after page load, call Nimbus.LazyLoad.observe(el) or Nimbus.LazyLoad.refresh() to register them with the existing observer.

    Via data attributes

    Add data-cnds-lazy to any element and set the deferred URL in data-cnds-src (<img> / <iframe>), data-cnds-srcset (responsive images), or data-cnds-bg (background images on any element). No JavaScript call is required.

    HTML
    <!-- Standard image — wrap in a placeholder div to avoid the broken-image indicator -->
<div class="ll-placeholder">
  <img data-cnds-lazy data-cnds-src="img/photo.jpg" alt="Description" />
</div>

<!-- Responsive image with srcset -->
<div class="ll-placeholder">
  <img data-cnds-lazy
       data-cnds-src="img/photo-800.jpg"
       data-cnds-srcset="img/photo-400.jpg 400w, img/photo-800.jpg 800w"
       sizes="(max-width: 600px) 400px, 800px"
       alt="Description" />
</div>

<!-- Background image on a div (no wrapper needed — data-cnds-bg targets the div itself) -->
<div data-cnds-lazy data-cnds-bg="img/hero.jpg"
     class="ll-bg-demo" role="img" aria-label="Description"></div>

    Via JavaScript

    Use Nimbus.LazyLoad.observe(el) to register a single element added dynamically, or Nimbus.LazyLoad.refresh() to re-scan the entire document for new [data-cnds-lazy] elements. Use Nimbus.LazyLoad.init(options) only when you need to change the global rootMargin or threshold — call Nimbus.LazyLoad.destroy() first to disconnect the existing observer.

    JAVASCRIPT
    // Register a single dynamically inserted element
var newImg = document.createElement('img');
newImg.setAttribute('data-cnds-lazy', '');
newImg.setAttribute('data-cnds-src', 'img/photo.jpg');
newImg.alt = 'Description';
document.querySelector('.gallery').appendChild(newImg);
Nimbus.LazyLoad.observe(newImg);

// Re-scan the DOM after injecting multiple new lazy elements
Nimbus.LazyLoad.refresh();

// Re-initialize with a custom rootMargin
Nimbus.LazyLoad.destroy();
Nimbus.LazyLoad.init({ rootMargin: '500px 0px' });

    Options

    Options are passed to Nimbus.LazyLoad.init() as a plain object. They configure the shared IntersectionObserver and the CSS class names applied to elements on load and error. All options are global — per-element overrides are not supported.

    Name Type Default Description
    rootMargin String "200px 0px" CSS margin applied to the viewport root. Controls how far outside the viewport elements are observed. Follows CSS shorthand syntax ("top right bottom left").
    threshold Number 0.01 Fraction of the element that must be visible before the observer fires. 0.01 fires on first pixel; 1 requires the full element to be in view.
    loaded String "cnds-lazy-loaded" CSS class added to an element after its asset loads successfully. Override to integrate with a custom CSS framework or naming convention.
    error String "cnds-lazy-error" CSS class added to an element when its asset fails to load. Style this class to provide a meaningful error state (see the Error section above).

    Methods

    All methods are available on the window.Nimbus.LazyLoad namespace object. There is no per-instance API — the component manages a single shared IntersectionObserver.

    Method Signature Description
    init init(options?) Creates the shared IntersectionObserver and observes all current [data-cnds-lazy] elements. Called automatically on DOMContentLoaded. Call manually only when re-initializing with different options (destroy first).
    observe observe(element) Registers a single DOM element with the existing observer. Use this for elements added to the DOM after DOMContentLoaded.
    refresh refresh() Re-scans the document for [data-cnds-lazy] elements not yet loaded and registers them with the observer. Use after injecting a batch of new lazy elements.
    destroy destroy() Disconnects the IntersectionObserver and sets the internal reference to null. Call before init() when changing global options.
    JAVASCRIPT
    // Register a dynamically inserted element
Nimbus.LazyLoad.observe(document.getElementById('newImage'));

// Re-scan after injecting multiple new elements
Nimbus.LazyLoad.refresh();

// Change rootMargin after page load
Nimbus.LazyLoad.destroy();
Nimbus.LazyLoad.init({ rootMargin: '400px 0px', threshold: 0.05 });

    CSS state classes

    The Nimbus LazyLoad component does not dispatch custom events. Instead, it communicates state by adding CSS classes to the element. Listen for state changes using a MutationObserver targeting the element's classList, or use CSS directly to style each state.

    Class When applied Notes
    cnds-lazy-loaded After the asset loads successfully (native load event on the element). The data-cnds-lazy, data-cnds-src, and data-cnds-srcset attributes are removed at the same time.
    cnds-lazy-error When the asset fails to load (native error event on the element). Style this class to display a fallback state. The data-cnds-lazy attribute is not removed so the element can be retried with Nimbus.LazyLoad.refresh().
    JAVASCRIPT
    // Detect load completion via MutationObserver (no custom events)
var img = document.getElementById('myImage');

var mo = new MutationObserver(function (mutations) {
  mutations.forEach(function (mutation) {
    if (mutation.type === 'attributes' && mutation.attributeName === 'class') {
      if (img.classList.contains('cnds-lazy-loaded')) {
        console.log('Asset loaded successfully:', img.src);
        mo.disconnect();
      }
      if (img.classList.contains('cnds-lazy-error')) {
        console.warn('Asset failed to load');
        mo.disconnect();
      }
    }
  });
});

mo.observe(img, { attributes: true });
