    Clearfix

    Clearfix is a CSS utility that forces a container element to expand around its floated children. When all child elements are floated, the parent collapses to zero height because floated elements are removed from the normal document flow. Adding .clearfix to the parent element inserts an invisible ::after pseudo-element with clear: both, restoring the container's height without requiring extra markup.

    Use clearfix when a container holds only floated children and must visually wrap around them — for example, a toolbar with buttons floated to opposite sides. Modern layouts built with Flexbox or CSS Grid do not require clearfix because those models keep children within the normal flow. Clearfix is most relevant when working with legacy float-based layouts or integrating third-party content that uses floats.

    Basic example

    The .clearfix class and the clearfix() SCSS mixin are two ways to apply the same technique. Use the HTML class when working directly in templates or markup. Use the mixin when you want to extend a custom SCSS selector without adding a utility class to the HTML.

    Apply .clearfix to the parent element in HTML:

    HTML
    <div class="clearfix">...</div>

    The underlying SCSS mixin generates a ::after pseudo-element that clears both float directions:

    SCSS
    @mixin clearfix() {
  &::after {
    display: block;
    clear: both;
    content: "";
  }
}

    Include the mixin in any custom SCSS selector to apply clearfix without adding a class to the HTML:

    SCSS
    .element {
  @include clearfix;
}

    The example below demonstrates the effect in practice. Both buttons are floated in opposite directions inside a container div. Because .clearfix is applied to that div, the container stretches to fully enclose both buttons. Without it, the container would collapse and the buttons would overflow outside their parent, breaking the layout.

    HTML
    <div class="bg-blue-50 clearfix">
    <button type="button" class="btn btn-primary float-start">
        Example Button floated left
    </button>
    <button type="button" class="btn btn-primary float-end">
        Example Button floated right
    </button>
</div>

    API Documentation

    Introduction

    The Nimbus clearfix utility is a CSS-only helper — no JavaScript initialization is required. It forces a container element to expand around its floated children by inserting a clearing ::after pseudo-element. When all children are floated, the browser removes them from the normal document flow and the container collapses to zero height. Clearfix restores that height by injecting an invisible block after the floated content that forces the container to stretch around it.

    Two equivalent forms are provided: the .clearfix utility class for use directly in markup, and the clearfix() SCSS mixin for applying the same technique inside a custom selector without adding a class to the HTML.

    Usage

    Apply .clearfix to the parent container element — not to the floated children. The class inserts a ::after pseudo-element with clear: both that restores the container's height without requiring extra markup. Use the SCSS mixin when you want to apply the technique to a custom selector without adding a utility class to the HTML.

    HTML
    <div class="clearfix">
    <button type="button" class="btn btn-primary float-start">Left</button>
    <button type="button" class="btn btn-primary float-end">Right</button>
</div>
    SCSS
    .my-toolbar {
  @include clearfix;
}

    CSS classes

    The following classes and selectors make up the clearfix implementation. Both are CSS-only and require no JavaScript.

    Class / Selector Applied to Description
    .clearfix any block container Apply to the parent of floated children. Triggers the clearing ::after pseudo-element that forces the container to expand around its floated content.
    .clearfix::after generated pseudo-element The clearing element inserted after all floated children. Rendered as display: block with clear: both and content: "". The empty content value ensures screen readers do not announce it.

    CSS output

    Both the .clearfix utility class and the clearfix() SCSS mixin compile to the same CSS rule. The display: block declaration ensures the pseudo-element establishes a block formatting context so that clear: both takes effect correctly.

    CSS
    .clearfix::after {
  display: block;
  clear: both;
  content: "";
}

    SCSS mixin

    The clearfix() mixin generates the same ::after clearing rule as the utility class. Use it inside any SCSS selector to avoid adding .clearfix to the HTML. The & parent-selector reference ensures the pseudo-element targets the correct compiled selector.

    Mixin Arguments Description
    clearfix() none Outputs a ::after rule on the enclosing selector with display: block, clear: both, and content: "". Include via @include clearfix; — no arguments accepted.
    SCSS — mixin definition
    @mixin clearfix() {
  &::after {
    display: block;
    clear: both;
    content: "";
  }
}
    SCSS — usage
    .my-toolbar {
  @include clearfix;
}

// Compiles to:
// .my-toolbar::after {
//   display: block;
//   clear: both;
//   content: "";
// }

    Accessibility

    Clearfix has no effect on the accessibility tree and requires no ARIA attributes. The ::after pseudo-element uses content: "", which means it carries no text and is not announced by screen readers. The technique is purely presentational — it corrects a layout side-effect of CSS floats without altering document semantics.

    • Do not add aria-hidden to the clearfix container. The container itself may hold meaningful content; hiding it would remove that content from the accessibility tree.
    • Floated child elements remain in normal document order in the DOM and are fully accessible to keyboard and screen-reader users regardless of their visual float position.
    • If the floated children form a functional group (such as a toolbar), wrap them in an appropriate landmark or labelled region — clearfix itself provides no grouping semantics.
