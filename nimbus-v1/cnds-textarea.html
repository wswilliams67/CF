    v1Textarea
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The textarea component collects multi-line free-form text from users. Use it when the expected input spans more than one line — such as comments, notes, descriptions, or messages. For short, bounded values (email, phone, search), use a single-line input instead.

    The component uses the standard .cf-input-field wrapper system shared with all CNDS input controls. Size modifiers, product-theme modifiers, helper text, error messaging, and the character counter all work identically to their single-line counterparts.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    The minimum markup is a <label>, a <textarea class="cf-input-control"> inside .cf-input-wrapper, and both wrapped in .cf-input-field with a product modifier. The rows attribute sets the initial visible height; the textarea is user-resizable vertically by default. Always pair the for attribute on the label with the id on the textarea.

    HTML

    <div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="taBasic">Message</label>
    <div class="cf-input-wrapper">
        <textarea class="cf-input-control" id="taBasic" rows="4" placeholder="Enter your message here..."></textarea>
    </div>
</div>

    States

    The textarea has five visual states. Default shows an empty field ready for input. Filled shows the field with user-entered content. Error is triggered by adding .is-invalid to .cf-input-field — the border turns red and the .cf-input-error message replaces the helper text. Disabled applies the native disabled attribute, reducing opacity and removing the field from the tab order. Readonly applies the native readonly attribute, keeping the value visible and selectable but preventing edits.

    Disabled

    Add the disabled boolean attribute to the <textarea> when the field should be entirely inert — it cannot be focused, edited, or submitted with the form. The field is removed from the tab order and rendered at reduced opacity. Use readonly instead when the value should remain visible and copyable.

    HTML

    <div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="taDisabled">Message</label>
    <div class="cf-input-wrapper">
        <textarea class="cf-input-control" id="taDisabled" rows="4"
            placeholder="Disabled textarea" disabled></textarea>
    </div>
</div>

    Readonly

    Add the readonly boolean attribute when the value should be visible and selectable but not editable. Unlike disabled, a readonly textarea remains focusable, participates in tab order, and its value is included in form submissions. The field renders with a muted background to visually distinguish it from an editable state.

    HTML

    <div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="taReadonly">Message</label>
    <div class="cf-input-wrapper">
        <textarea class="cf-input-control" id="taReadonly" rows="4" readonly>This content cannot be edited.</textarea>
    </div>
</div>

    Helper text

    Place the .cf-input-helper row directly after .cf-input-wrapper to display guidance and validation feedback below the textarea. .cf-input-helper-text holds contextual instructions and is hidden automatically when .is-invalid is present on .cf-input-field. .cf-input-error holds the validation message and is shown only when .is-invalid is applied. Both elements can coexist in the DOM — the component toggles their visibility via CSS.

    Associate helper text with the control. Add aria-describedby="helperId" to the <textarea> and a matching id to the helper span. When both helper text and an error message are present, space-separate both IDs: aria-describedby="helperId errorId". This ensures screen readers announce all relevant context when the field receives focus.

    We read every submission.

    HTML

    <div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="taHelper">Feedback</label>
    <div class="cf-input-wrapper">
        <textarea class="cf-input-control" id="taHelper" rows="4"
            placeholder="Share your thoughts..." aria-describedby="taHelperText"></textarea>
    </div>
    <div class="cf-input-helper">
        <span id="taHelperText" class="cf-input-helper-text">We read every submission.</span>
    </div>
</div>

    Add .is-invalid to .cf-input-field to swap the helper text for the error message and apply the danger border.

    Character counter

    Display a live character count by adding a .cf-input-counter span to .cf-input-helper and setting the maxlength attribute on the <textarea>. The browser enforces the character limit natively; the counter span is updated via a small oninput handler (or equivalent event listener). Include the counter's id in the textarea's aria-describedby so screen readers announce the remaining count when the field is focused.

    Maximum 160 characters. 0/160

    HTML

    <div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="taCounter">Bio</label>
    <div class="cf-input-wrapper">
        <textarea class="cf-input-control" id="taCounter" rows="4" maxlength="160"
            placeholder="Tell us about yourself..."
            aria-describedby="taCounterHelper taCounterCount"
            oninput="document.getElementById('taCounterCount').textContent = this.value.length + '/160'"></textarea>
    </div>
    <div class="cf-input-helper">
        <span id="taCounterHelper" class="cf-input-helper-text">Maximum 160 characters.</span>
        <span id="taCounterCount" class="cf-input-counter">0/160</span>
    </div>
</div>

    Autosize

    Nimbus supports automatic height adjustment via the Autosize library. Once initialized, the textarea expands as the user types and contracts when content is deleted. The rows attribute sets the minimum visible height — Autosize will not shrink the field below that baseline. Pass a selector, node, NodeList, or HTMLCollection to the autosize() call after the DOM is ready.

    Height adjusts to content.

    HTML

    <div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="taAutosize">Message</label>
    <div class="cf-input-wrapper">
        <textarea class="cf-input-control" id="taAutosize" rows="2"
            placeholder="Start typing — the textarea grows automatically..."
            aria-describedby="taAutosizeHelp"></textarea>
    </div>
    <div class="cf-input-helper">
        <span id="taAutosizeHelp" class="cf-input-helper-text">Height adjusts to content.</span>
    </div>
</div>

    JAVASCRIPT

    // from a NodeList
autosize(document.querySelectorAll('textarea'));

// from a single Node
autosize(document.querySelector('textarea'));

// from a single ID
autosize(document.getElementById('textarea_id'));

    API Documentation

    Introduction

    The Nimbus textarea component is CSS-only — no JavaScript initialisation is required for core styling. It shares the .cf-input-field wrapper, label, and helper-row system with all CNDS input controls. The element-level difference is that <textarea> replaces <input>, and the icon (when present) is anchored to the top-right of the wrapper rather than vertically centred. The component is fully theme-aware: background, border, text, placeholder, and error colors adapt automatically when data-cnds-theme="dark" is set on any ancestor. The Autosize library is optional and only required for auto-growing height behaviour.

    Usage

    Wrap a <textarea class="cf-input-control"> inside .cf-input-wrapper, then wrap both in .cf-input-field. Add a product modifier (.cf-input-field-casefusion etc.) to the same wrapper element to apply the correct focus ring for the target product. Optionally append .cf-input-helper below the wrapper for helper text, error messages, and character counters.

    HTML
    <div class="cf-input-field cf-input-field-casefusion">
    <label class="cf-input-label" for="id">Label</label>
    <div class="cf-input-wrapper">
        <textarea class="cf-input-control" id="id" rows="4"
            placeholder="Placeholder..." aria-describedby="helpId"></textarea>
    </div>
    <div class="cf-input-helper">
        <span id="helpId" class="cf-input-helper-text">Helper text.</span>
        <span class="cf-input-error">Error message.</span>
        <span class="cf-input-counter">0/160</span>
    </div>
</div>

    Accessibility

    Follow these requirements for an accessible textarea implementation:

    • Always pair the textarea with a visible <label> using a matching for / id relationship. Do not rely on placeholder as a label substitute — placeholders disappear on input and have insufficient color contrast in most browsers.
    • Link helper text and error messages to the textarea via aria-describedby. When multiple elements describe the field, space-separate their IDs: aria-describedby="helpId errorId".
    • The disabled attribute is announced by screen readers and removes the field from the tab order. Use it when the field should be entirely inert. Use readonly when the value should be visible and selectable but not editable.
    • When marking a field as required, include both the visual asterisk (.cf-input-required) and the native required attribute on the <textarea>. This ensures browsers and assistive technologies surface the requirement.
    • If using a character counter, include the counter element's ID in aria-describedby so screen readers announce the remaining character count alongside the field.

    For the full specification, see the WAI-WCAG 2.1 — Labels or Instructions.

    JavaScript

    The textarea component requires no JavaScript for core styling or validation states. The only JavaScript API is the autosize() utility, used exclusively for auto-growing height behaviour. It is defined as an inline page script and has no external dependency.

    Function Parameter Type Description
    autosize(target) target Element | NodeList | HTMLCollection Initialises auto-growing height on the supplied textarea element(s). Sets overflow: hidden and resize: none on each element, then attaches an input listener that resets the height to auto before reading scrollHeight — this two-step pattern ensures the field shrinks as well as grows. The initial height is applied immediately on call so the field renders correctly on page load. Non-textarea elements in the target collection are silently skipped.
    JAVASCRIPT
    // Single element by ID
autosize(document.getElementById('myTextarea'));

// NodeList — all matching textareas
autosize(document.querySelectorAll('textarea.cf-input-control'));

// HTMLCollection
autosize(document.getElementsByClassName('cf-input-control'));
