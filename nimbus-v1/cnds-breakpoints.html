    v1 Breakpoints
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Breakpoints are the triggers in Nimbus for how your layout responsive changes across device or viewport sizes. Nimbus uses a mobile-first approach: the six breakpoints (xs: 0px, sm: 576px, md: 768px, lg: 992px, xl: 1200px, xxl: 1400px) define the minimum viewport width at which utility classes and media queries take effect. Classes with a breakpoint infix (e.g. col-md-6, d-lg-flex) apply at that breakpoint and above.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Core concepts

    • Breakpoints are the building blocks of responsive design. Use them to control when your layout can be adapted at a particular viewport or device size.

    • Use media queries to architect your CSS by breakpoint. Media queries are a feature of CSS that allow you to conditionally apply styles based on a set of browser and operating system parameters. We most commonly use min-width in our media queries.

    • Mobile first, responsive design is the goal. Nimbus CSS aims to apply the bare minimum of styles to make a layout work at the smallest breakpoint, and then layers on styles to adjust that design for larger devices. This optimizes your CSS, improves rendering time, and provides a great experience for your visitors.

    • Use breakpoint infixes in utility class names. Nimbus utility classes accept breakpoint infixes to apply styles conditionally. For example, d-none d-md-block hides an element on mobile and shows it from md (768px) and above. The infix is omitted for xs since it is the default (no media query required).

    Available breakpoints

    Nimbus includes six default breakpoints, sometimes referred to as grid tiers, for building responsively. Each breakpoint defines the minimum viewport width at which its styles take effect — all classes apply at the given breakpoint and above (mobile-first). These breakpoints can be customized if you're using our source Sass files.

    Breakpoint Class infix Dimensions
    X-Small None 0–576px
    Small sm ≥576px
    Medium md ≥768px
    Large lg ≥992px
    Extra large xl ≥1200px
    Extra extra large xxl ≥1400px

    Each breakpoint size was chosen to be a multiple of 12 and to be representative of a subset of common device sizes and viewport dimensions. They don't specifically target every use case or device, but the provide ranges provide a strong and consistent foundation to build on for any nearly device.

    These breakpoints are customizable via Sass—you'll find them in a Sass map in our _variables.scss stylesheet.

    SCSS
    $grid-breakpoints: (
  xs: 0,
  sm: 576px,
  md: 768px,
  lg: 992px,
  xl: 1200px,
  xxl: 1400px
);

    Media queries

    Since Nimbus is developed to be mobile first, we use a handful of media queries to create sensible breakpoints for our layouts and interfaces. These breakpoints are mostly based on minimum viewport widths and allow us to scale up elements as the viewport changes. You can also write custom media queries using the Nimbus breakpoint CSS custom properties (e.g. var(--cnds-breakpoint-md)) or reference the Sass variables directly in component SCSS files.

    Min-width

    Nimbus primarily uses the following media query ranges—or breakpoints—in our source Sass files for our layout, grid system, and components.

    SCSS
    // Source mixins

// No media query necessary for xs breakpoint as it's effectively `@media (min-width: 0) { ... }`
@include media-breakpoint-up(sm) { ... }
@include media-breakpoint-up(md) { ... }
@include media-breakpoint-up(lg) { ... }
@include media-breakpoint-up(xl) { ... }
@include media-breakpoint-up(xxl) { ... }

// Usage

// Example: Hide starting at `min-width: 0`, and then show at the `sm` breakpoint
.custom-class {
  display: none;
}
@include media-breakpoint-up(sm) {
  .custom-class {
    display: block;
  }
}

    These Sass mixins translate in our compiled CSS using the values declared in our Sass variables. For example:

    SCSS
    /* X-Small devices (portrait phones, less than 576px) */
/* No media query for `xs` since this is the default in Nimbus */

/* Small devices (landscape phones, 576px and up) */
@media (min-width: 576px) { ... }

/* Medium devices (tablets, 768px and up) */
@media (min-width: 768px) { ... }

/* Large devices (desktops, 992px and up) */
@media (min-width: 992px) { ... }

/* X-Large devices (large desktops, 1200px and up) */
@media (min-width: 1200px) { ... }

/* XX-Large devices (larger desktops, 1400px and up) */
@media (min-width: 1400px) { ... }

    Max-width

    We occasionally use media queries that go in the other direction (the given screen size or smaller):

    SCSS
    // No media query necessary for xs breakpoint as it's effectively `@media (max-width: 0) { ... }`
@include media-breakpoint-down(sm) { ... }
@include media-breakpoint-down(md) { ... }
@include media-breakpoint-down(lg) { ... }
@include media-breakpoint-down(xl) { ... }
@include media-breakpoint-down(xxl) { ... }

// Example: Style from medium breakpoint and down
@include media-breakpoint-down(md) {
  .custom-class {
    display: block;
  }
}

    These mixins take those declared breakpoints, subtract .02px from them, and use them as our max-width values. For example:

    SCSS
    /* X-Small devices (portrait phones, less than 576px) */
@media (max-width: 575.98px) { ... }

/* Small devices (landscape phones, less than 768px) */
@media (max-width: 767.98px) { ... }

/* Medium devices (tablets, less than 992px) */
@media (max-width: 991.98px) { ... }

/* Large devices (desktops, less than 1200px) */
@media (max-width: 1199.98px) { ... }

/* X-Large devices (large desktops, less than 1400px) */
@media (max-width: 1399.98px) { ... }

/* XX-Large devices (larger desktops) */
/* No media query since the xxl breakpoint has no upper bound on its width */

    Why subtract .02px? Browsers don't currently support range context queries, so we work around the limitations of min- and max- prefixes and viewports with fractional widths (which can occur under certain conditions on high-dpi devices, for instance) by using values with higher precision.

    Single breakpoint

    There are also media queries and mixins for targeting a single segment of screen sizes using the minimum and maximum breakpoint widths.

    SCSS
    @include media-breakpoint-only(xs) { ... }
@include media-breakpoint-only(sm) { ... }
@include media-breakpoint-only(md) { ... }
@include media-breakpoint-only(lg) { ... }
@include media-breakpoint-only(xl) { ... }
@include media-breakpoint-only(xxl) { ... }

    For example the @include media-breakpoint-only(md) { ... } will result in:

    SCSS
    @media (min-width: 768px) and (max-width: 991.98px) { ... }

    Between breakpoints

    Similarly, media queries may span multiple breakpoint widths:

    SCSS
    @include media-breakpoint-between(md, xl) { ... }

    Which results in:

    SCSS
    /* Example */
/* Apply styles starting from medium devices and up to extra large devices */
@media (min-width: 768px) and (max-width: 1199.98px) { ... }

    API Documentation

    Introduction

    This section provides a complete reference for Nimbus breakpoint values, the available SCSS mixins for writing custom media queries, and the CSS custom properties exposed for use in component stylesheets. Nimbus uses a mobile-first grid with six breakpoints: xs (0), sm (576px), md (768px), lg (992px), xl (1200px), and xxl (1400px). All utility class infixes and SCSS mixins apply at the specified min-width and above.

    Breakpoint Values

    The following table lists all available breakpoints, their class infixes, and the corresponding min-width values used in media queries.

    Breakpoint Class infix Min-width Max-width
    X-Small None 0 575.98px
    Small sm 576px 767.98px
    Medium md 768px 991.98px
    Large lg 992px 1199.98px
    Extra large xl 1200px 1399.98px
    Extra extra large xxl 1400px No upper bound

    SCSS Mixins

    The following Sass mixins are available for targeting specific breakpoint ranges in your stylesheets.

    Mixin Description
    @include media-breakpoint-up($bp) Applies styles at the specified breakpoint and above (min-width). Values: sm, md, lg, xl, xxl.
    @include media-breakpoint-down($bp) Applies styles below the specified breakpoint (max-width minus 0.02px). Values: sm, md, lg, xl, xxl.
    @include media-breakpoint-only($bp) Applies styles only at the specified breakpoint range (between its min-width and the next breakpoint's max-width). Values: xs, sm, md, lg, xl, xxl.
    @include media-breakpoint-between($lower, $upper) Applies styles between two breakpoints (from the lower's min-width to the upper's max-width minus 0.02px).

    CSS Custom Properties

    Breakpoint values are available as CSS custom properties (design tokens) for reference in component SCSS files and inline styles. These are defined in the :root scope and can be referenced with var(--cnds-breakpoint-md) etc.

    Property Value Description
    --cnds-breakpoint-xs 0 X-Small breakpoint (default, no media query).
    --cnds-breakpoint-sm 576px Small breakpoint min-width.
    --cnds-breakpoint-md 768px Medium breakpoint min-width.
    --cnds-breakpoint-lg 992px Large breakpoint min-width.
    --cnds-breakpoint-xl 1200px Extra large breakpoint min-width.
    --cnds-breakpoint-xxl 1400px Extra extra large breakpoint min-width.

    Accessibility

    Breakpoint utilities control responsive layout and have no direct ARIA requirements. However, consider the following:

    • When content is hidden at certain breakpoints using d-none d-md-block, ensure the hidden content is not required for screen-reader users. If the content must remain accessible, use .visually-hidden instead of d-none.
    • Changes in layout at breakpoints should not alter the logical reading or interaction order for keyboard users. Always verify the DOM source order is meaningful independently of visual layout.
    • Avoid relying solely on breakpoints to hide complex interactive elements; use proper ARIA patterns (e.g., aria-expanded, aria-hidden) in combination with responsive classes.
