    v1 Sliding Panels (aka Offcanvas)
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    Sliding panels (also called offcanvas) are used for workflow tasks where a modal dialog would interrupt the user too heavily. The panel slides in from an edge of the viewport — by default the right — keeping the underlying page visible and partially interactive so users maintain context while completing focused tasks such as filling a form, reviewing item details, or accessing a secondary navigation menu.

    Sliding panels support configurable placement (.offcanvas-start, .offcanvas-end, .offcanvas-top, .offcanvas-bottom), width customization via sizing utilities, and independent backdrop and body-scroll options. Nimbus defaults all sliding panels to open from the right edge of the screen unless UX specifies otherwise.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    How it works

    Offcanvas is a sidebar component that can be toggled via JavaScript to appear from the top, left, right, or bottom edge of the viewport. Buttons or anchors are used as triggers that are attached to specific elements you toggle, and data attributes are used to invoke our JavaScript.

    • Offcanvas must be initialized using the data-cnds-offcanvas-init data attribute
    • Offcanvas shares some of the same JavaScript code as modals. Conceptually, they are quite similar, but they are separate plugins.
    • When shown, offcanvas includes a default backdrop that can be clicked to hide the offcanvas.
    • Similar to modals, only one offcanvas can be shown at a time.

    Heads up! Given how CSS handles animations, you cannot use margin or translate on an .offcanvas element. Instead, use the class as an independent wrapping element.

    Placement

    Use modifier classes to control which edge the panel slides in from. Nimbus uses the right edge as the default — use .offcanvas-end unless UX explicitly requires another direction:

    • .offcanvas-start — slides in from the left of the viewport
    • .offcanvas-end — slides in from the right of the viewport (Nimbus default)
    • .offcanvas-top — slides in from the top of the viewport
    • .offcanvas-bottom — slides in from the bottom of the viewport

    Sizing

    The default width for offcanvas components is 400px. To make a panel narrower or wider, apply a width utility class directly on the .offcanvas element using the Sizing Utilities. Width utilities (w-25, w-50, w-75, w-100) are expressed as a percentage of the viewport, so panels respond to the user's screen size automatically. The default 400px is recommended for task panels; use wider breakpoints only when the content genuinely requires it.

    Accessibility

    Since the offcanvas panel is conceptually a modal dialog, the following ARIA attributes and patterns are required for an accessible implementation:

    • Always add aria-labelledby="..." to the .offcanvas element, referencing the id of the panel’s visible title. This connects the panel to its heading for assistive technologies.
    • You do not need to add role="dialog" manually — Nimbus adds it automatically via JavaScript when the panel is initialized.
    • Always include a clearly labeled dismiss action inside the panel header (the .btn-close button with aria-label="Close") so keyboard and screen-reader users can close the panel without relying on the backdrop click.
    • Focus is trapped within the open panel automatically by Nimbus. When the panel closes, focus returns to the trigger element that opened it.
    • The panel can be dismissed with the Escape key by default. This behavior is controlled by the keyboard option.

    API Documentation

    The Nimbus Sliding Panel component is JavaScript-driven and must be initialized before trigger elements will function. Initialization can be declarative — by adding data-cnds-offcanvas-init to a trigger element — or programmatic, using new Nimbus.Offcanvas(el). Options for backdrop behavior, keyboard dismissal, and body scrolling are configurable per instance via data attributes or the JavaScript constructor.

    Introduction

    The offcanvas plugin utilizes a few classes and attributes to handle the heavy lifting:

    • data-cnds-offcanvas-init initializes the offcanvas plugin
    • .offcanvas hides the content
    • .offcanvas.show shows the content
    • .offcanvas-end slides the panel in from the right (Nimbus default)
    • .offcanvas-start slides the panel in from the left
    • .offcanvas-top slides the panel in from the top
    • .offcanvas-bottom slides the panel in from the bottom

    Usage

    Add a dismiss button with the data-cnds-dismiss="offcanvas" attribute, which triggers the JavaScript functionality. Be sure to use the <button> element with it for proper behavior across all devices.

    Via data attributes

    Add data-cnds-offcanvas-init with data-cnds-toggle="offcanvas" and a data-cnds-target or href to the element to automatically assign control of one panel element. The data-cnds-target attribute accepts a CSS selector to apply the panel to. Be sure to add the class offcanvas to the panel element. If you'd like it to default open, add the additional class show.

    Dismiss

    Dismissal can be achieved with data attributes on a button within the panel as demonstrated below:

    HTML
    									
									<button type="button" class="btn-close" data-cnds-dismiss="offcanvas" aria-label="Close"></button>

    or on a button outside the panel using the data-cnds-target as demonstrated below:

    HTML
    									
									<button type="button" class="btn-close" data-cnds-dismiss="offcanvas" data-cnds-target="#my-offcanvas" aria-label="Close"></button>

    While both ways to dismiss a panel are supported, keep in mind that dismissing from outside a panel does not match the WAI-ARIA modal dialog design pattern. Do this at your own risk.

    Via JavaScript

    Enable manually with:

    JAVASCRIPT
    									
									const offcanvasElements = Array.from(document.querySelectorAll('.offcanvas'));
									const offcanvasList = offcanvasElements.map(el => new Nimbus.Offcanvas(el));

    Options

    Options can be passed via data attributes or JavaScript. For data attributes, append the option name to data-cnds-, as in data-cnds-backdrop="".

    Name Type Default Description
    backdrop boolean true Apply a backdrop on body while the panel is open
    keyboard boolean true Closes the panel when the Escape key is pressed
    scroll boolean false Allow body scrolling while the panel is open

    Methods

    Asynchronous methods and transitions: All API methods are asynchronous and start a transition. They return to the caller as soon as the transition is started but before it ends. In addition, a method call on a transitioning component will be ignored.

    You can create a panel instance with the constructor, for example:

    JAVASCRIPT
    									
									const myOffcanvas = document.getElementById('myOffcanvas');
									const offcanvasInstance = new Nimbus.Offcanvas(myOffcanvas);
    Method Description
    toggle Toggles a panel element to shown or hidden. Returns to the caller before the panel has actually been shown or hidden (i.e. before the shown.cnds.offcanvas or hidden.cnds.offcanvas event occurs).
    show Shows a panel element. Returns to the caller before the panel has actually been shown (i.e. before the shown.cnds.offcanvas event occurs).
    hide Hides a panel element. Returns to the caller before the panel has actually been hidden (i.e. before the hidden.cnds.offcanvas event occurs).
    getInstance Static method which allows you to get the panel instance associated with a DOM element.

    Events

    Nimbus's Sliding Panel component exposes a few events for hooking into panel functionality.

    Event type Description
    show.cnds.offcanvas This event fires immediately when the show instance method is called.
    shown.cnds.offcanvas This event is fired when a panel has been made visible to the user (will wait for CSS transitions to complete).
    hide.cnds.offcanvas This event is fired immediately when the hide method has been called.
    hidden.cnds.offcanvas This event is fired when a panel has been hidden from the user (will wait for CSS transitions to complete).
    JAVASCRIPT
    									
									const myOffcanvas = document.getElementById('myOffcanvas');
									myOffcanvas.addEventListener('hidden.cnds.offcanvas', () => {
									  // do something...
									});

    Accessibility

    Nimbus's Sliding Panel is built with accessibility in mind, using standard ARIA roles and attributes to communicate panel state to assistive technologies.

    Attribute Applied to Description
    role="dialog" Panel element Identifies the panel as a dialog region
    aria-labelledby Panel element References the id of the .offcanvas-title element
    aria-hidden="true" Panel element Set when the panel is hidden; removed when visible
    aria-controls Trigger button References the id of the controlled panel element
    aria-expanded Trigger button Reflects the open/closed state of the panel (true / false)
    aria-label="Close" Close button Provides an accessible name for the close button

    The panel can be dismissed with the Escape key by default. This behavior is controlled by the keyboard option. When open, focus is trapped within the panel until it is dismissed.
