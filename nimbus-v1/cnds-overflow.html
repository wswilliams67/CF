    Overflow utilities control what happens when content is too large to fit inside its container. Apply a single class to set the CSS overflow, overflow-x, or overflow-y property without writing any custom CSS. The four base values — auto, hidden, visible, and scroll — are available as both shorthand utilities that affect both axes simultaneously and as axis-specific variants for precise control over horizontal and vertical behavior independently.

    These utilities are intentionally not responsive — they apply uniformly across all breakpoints. Use them on fixed-dimension containers where the overflow behavior must be predictable regardless of screen size.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    The four core overflow classes map directly to their CSS overflow values. Use .overflow-auto to show scrollbars only when content exceeds the container. Use .overflow-hidden to clip content at the container's edge with no scrollbar. Use .overflow-visible to let content render outside the container boundary. Use .overflow-scroll to always show scrollbars regardless of whether the content fits. These classes are not responsive by default.

    The overflow utilities are generated from the $overflows Sass variable in _variables.scss. To add or remove values, override that variable before importing Nimbus.

    Scrolling if needed

    Use .overflow-auto to show scrollbars only when the content exceeds the container's bounds. When the content fits, no scrollbars appear and no space is reserved for them. This is generally the preferred choice over .overflow-scroll because it avoids permanently reserving scrollbar space in containers where content may or may not overflow.

    Scrolling always

    Use .overflow-scroll to always reserve and display scrollbar tracks, even when the content fits inside the container. Unlike .overflow-auto, the scrollbar gutter is always present, which prevents layout shift when content is added dynamically. Note that some operating systems — including macOS by default — overlay scrollbars rather than reserving space for them, so the visual difference may not be apparent on all platforms.

    Scrolling horizontally always

    Use .overflow-x-scroll to confine scrolling to the horizontal axis and always show a horizontal scrollbar track. This is useful for content that is intentionally wider than its container — such as data tables, code blocks, or wide diagrams — where vertical layout should remain fixed. As with .overflow-scroll, the scrollbar may be overlaid rather than space-reserving on some operating systems.

    API Documentation

    Introduction

    The Nimbus overflow utilities are CSS-only — no JavaScript initialization is required. Each utility applies a single overflow, overflow-x, or overflow-y CSS property value via an !important declaration, ensuring the utility always takes precedence over component-level styles. The twelve utilities are grouped into three sets: two-axis shorthand (overflow-*), horizontal-axis only (overflow-x-*), and vertical-axis only (overflow-y-*). Because the utilities only control clipping and scrollbar behavior rather than color, they require no dark-mode overrides and are fully theme-aware by default.

    Usage

    Apply a single overflow class directly to any element that has constrained dimensions — a fixed width, max-width, height, or max-height. Without at least one constrained dimension the overflow behavior has no visible effect.

    HTML
    <div class="overflow-auto" style="max-width: 260px; max-height: 100px">...</div>

    CSS classes

    The following classes cover all twelve overflow utilities defined in overflow.css. All classes are CSS-only and require no JavaScript.

    Class CSS property Value Description
    .overflow-auto overflow auto Shows scrollbars on both axes only when content exceeds the container.
    .overflow-hidden overflow hidden Clips content at the container boundary on both axes. No scrollbar is shown.
    .overflow-visible overflow visible Content that exceeds the container renders outside its boundary on both axes.
    .overflow-scroll overflow scroll Always shows scrollbar tracks on both axes, even when content fits inside the container.
    .overflow-x-auto overflow-x auto Shows a horizontal scrollbar only when content is wider than the container. Vertical overflow is unaffected.
    .overflow-x-hidden overflow-x hidden Clips content horizontally at the container boundary. Vertical overflow is unaffected.
    .overflow-x-visible overflow-x visible Content wider than the container renders beyond its horizontal boundary. Vertical overflow is unaffected.
    .overflow-x-scroll overflow-x scroll Always shows a horizontal scrollbar track regardless of content width. Vertical overflow is unaffected.
    .overflow-y-auto overflow-y auto Shows a vertical scrollbar only when content is taller than the container. Horizontal overflow is unaffected.
    .overflow-y-hidden overflow-y hidden Clips content vertically at the container boundary. Horizontal overflow is unaffected.
    .overflow-y-visible overflow-y visible Content taller than the container renders beyond its vertical boundary. Horizontal overflow is unaffected.
    .overflow-y-scroll overflow-y scroll Always shows a vertical scrollbar track regardless of content height. Horizontal overflow is unaffected.

    Accessibility

    The following guidance applies when overflow utilities create scrollable or clipped regions:

    • Scrollable regions that are not naturally focusable (e.g., a <div>) must include tabindex="0" so keyboard users can focus the region and scroll with the arrow keys. The WAI-ARIA specification requires that any content reachable by mouse scroll also be reachable by keyboard.
    • Applying .overflow-hidden clips content for sighted users but does not remove it from the accessibility tree. Screen readers will still announce content that is visually clipped. If the intent is to hide content from all users, use the .d-none utility or aria-hidden="true" instead.
    • Avoid nesting two independently scrollable containers where both may receive keyboard focus — the inner scroll region can trap keyboard users and prevent navigation out of the container.
