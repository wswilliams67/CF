v1 Typography
This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

Nimbus™ typography provides a complete, opinionated type system for Cloudficient applications — covering page titles, hero taglines, display headings, category headings, body paragraphs, lists, inline elements, and custom monospace styles. All type styles are built on Nunito Sans as the primary typeface and JetBrains Mono for monospace code contexts. The system assumes the browser's default root font-size (typically 16px) so users can scale text globally through their browser settings without breaking the layout.

Global typography settings — base font-size, line-height, color, and font-family — are applied to the <body> element via Nimbus reboot styles and must not be overridden on individual pages. Use the documented utility classes and component classes instead. Heading levels (.h1–.h6) decouple visual size from semantic heading rank, and display utilities (.cf-display-1–.cf-display-7) provide large, impactful text for landing pages and hero sections. Product-variant modifier classes (.highlight-casefusion, .highlight-hyperlize, .highlight-expireon) apply a branded color underline to taglines and display text, staying in sync with the active product theme.

Note: Read the API Documentation to find all available options and advanced customization.

Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

Basic page typography

Page-level typography components used across Cloudficient applications for titles, hero sections, and labels.

Page Title

The page title is a flex container displayed in uppercase with wide letter-spacing. Uses Nunito Sans Bold at 14px with 8px letter-spacing. Supports an optional back button and a secondary title separated by a vertical divider.

Application Page Title Bar

The application page title bar sits below the main navigation inside the sticky header. It displays a back-navigation button, the current page title, a vertical divider, a section label, and a decorative CaseFusion green accent stripe that extends to fill the remaining width. All elements are arranged on a single flex row. Defined in css/components/navbar.css; no JavaScript required.

<p><s>This line of text is meant to be treated as no longer accurate.</s></p>
<p><ins>This line of text is meant to be treated as an addition to the document.</ins></p>
<p><u>This line of text will render as underlined</u></p>
<p><small>This line of text is meant to be treated as fine print.</small></p>
<p><strong>This line rendered as bold text.</strong></p>
<p class="mb-0"><em>This line rendered as italicized text.</em></p>

Beware that those tags should be used for semantic purpose:

  • <mark> represents text which is marked or highlighted for reference or notation purposes.
  • <small> represents side-comments and small print, like copyright and legal text.
  • <s> represents element that are no longer relevant or no longer accurate.
  • <u> represents a span of inline text which should be rendered in a way that indicates that it has a non-textual annotation.

If you want to style your text, you should use the following classes instead:

  • .mark will apply the same styles as <mark>.
  • .small will apply the same styles as <small>.
  • .text-decoration-underline will apply the same styles as <u>.
  • .text-decoration-line-through will apply the same styles as <s>.

API Documentation

Introduction

Typography components in Nimbus are pure CSS — no JavaScript initialization is required. Styles are applied via CSS classes on standard HTML elements. All components are fully theme-aware and automatically adapt to light and dark modes via CSS custom properties defined in css/core/typography.css and overridden by theme tokens in css/themes/light.css and css/themes/dark.css.

Usage

Notes are a pure CSS component — no JavaScript initialization is required. Apply the .note base class along with a color variant class such as .note-primary to any block-level element (typically <p> or <div>).

HTML
<p class="note note-info">
  <strong>Note info:</strong> Your informational message here.
</p>

Theme variables

Notes use the same colors in both light and dark themes. No dark-mode overrides are applied — the Figma design tokens defined in components/notes.css are theme-agnostic and render identically regardless of the active data-cnds-theme value.

Accessibility

Typography components are CSS-only and carry no inherent ARIA roles. Correct use of semantic HTML is required to produce accessible output.

  • Use <h1> through <h6> elements in a logical, non-skipping hierarchy. Reserve heading classes (.h1–.h6) for visual-only overrides on non-heading elements.
  • Do not use headings purely for visual effect. If a design calls for large text without semantic structure, use a non-heading element with the appropriate display or category class instead.
  • All semantic text colors (body, muted, links) meet WCAG AA contrast requirements in both light and dark themes. Do not override --cnds-body-color or --cnds-secondary-color with values below the 4.5 : 1 threshold.
  • Product highlight colors (.highlight-casefusion, .highlight-hyperlize, .highlight-expireon) convey brand identity through color. Ensure that product context is also conveyed by text or structure — never by color alone.
  • Abbreviations must include a title attribute that expands the abbreviation. Screen readers announce the full text when the title attribute is present.
  • Blockquote attribution must be placed outside the <blockquote> element. Wrap in a <figure> with a <figcaption class="blockquote-footer">.
