    v1Loading Management
    This application is not optimized for small screens. Please use a large tablet, laptop, or desktop computer to continue.

    The Loading Management component overlays a configurable spinner and optional message on any container element while content or data is loading. It can be attached to a specific parent element (table, card, section) or expanded to cover the full viewport. The overlay is positioned automatically and removed programmatically when loading completes.

    Initialization is declarative or programmatic. Add data-cnds-init="loading" and data-cnds-loading to a container and Nimbus shows the spinner on page load with no JavaScript required. For dynamic workflows — such as showing a spinner during an API call and hiding it on success — instantiate new Nimbus.Loading(element, options) directly and call show() and hide() in your fetch handlers. Three product-branded full-viewport curtain animations are also available for initial page load screens: CaseFusion, ExpireOn, and Hyperlize.

    Note: Read the API Documentation to find all available options and advanced customization.

    Note: To preview components in different themes, click the theme toggle button / in the header navigation bar.

    Basic example

    Add data-cnds-init="loading" and data-cnds-loading directly to the container element. Nimbus automatically positions a .loading-overlay inside it and centers the spinner when the page loads. No JavaScript is required.

    HTML
    <div id="my-container"
     style="height: 300px; width: 100%"
     data-cnds-init="loading"
     data-cnds-loading
     data-cnds-text="Loading"></div>

    JavaScript init

    Use new Nimbus.Loading(element, options) to initialise the component from JavaScript. This approach is useful when the loader element is inserted dynamically, when you need to pass options that cannot be expressed as data attributes, or when you want to retain a reference to the instance so you can call dispose() later.

    HTML
    <div id="my-container" style="height: 300px; width: 100%"></div>
    JAVASCRIPT
    const loadingEl = document.querySelector('#my-container');
const loader = new Nimbus.Loading(loadingEl, { text: 'Loading' });

loader.show();

// When loading is complete:
loader.hide();

    Colors

    Apply any Bootstrap text-color utility (text-primary, text-success, text-danger, text-warning, etc.) to both the .loading-icon spinner and the .loading-text span to match your product's color language. The overlay backdrop is unaffected.

    HTML
    <div id="my-container" style="height: 300px; width: 100%"></div>
    JAVASCRIPT
    const loadingColors = document.querySelector('#my-container');
const loader = new Nimbus.Loading(loadingColors, {
    color: 'success',
    text:  'Loading'
});

loader.show();

    Custom spinners

    Growing spinner

    Replace spinner-border with spinner-grow to switch to a pulsing grow animation. The grow variant is subtler than the rotating border and works well in contexts where a spinning element would be distracting.

    HTML
    <div id="my-container"
     style="height: 300px; width: 100%"
     data-cnds-init="loading"
     data-cnds-loading
     data-cnds-spinner="grow"
     data-cnds-text="Loading"></div>

    Delay

    Pass a delay value (in milliseconds) to postpone the overlay's appearance. This prevents a loading flash on fast connections — the spinner only becomes visible if the operation takes longer than the specified delay. Toggle the switch below to see an 8-second simulated load with a 5-second delay before the overlay appears.

    HTML
    <div id="test">
    <div class="test-counter" aria-live="polite" aria-atomic="true"></div>
    <div class="form-check form-switch my-3">
        <input class="form-check-input" type="checkbox"
               id="flexSwitchCheckDefault" role="switch" aria-checked="false" />
        <label class="form-check-label"
               for="flexSwitchCheckDefault">Switch Delay</label>
    </div>
</div>
    JAVASCRIPT
    const switchEl = document.querySelector('#flexSwitchCheckDefault');
let timeleft = 4;

switchEl.addEventListener('change', (e) => {
    const container = document.querySelector('#test');

    if (e.target.checked) {
        // Inject an empty container; Loading appends the overlay inside it
        container.insertAdjacentHTML('beforeend',
            '<div id="loading-test-6" style="height: 300px; width: 100%"></div>'
        );

        const delayContainer = document.querySelector('#loading-test-6');
        const counter        = document.querySelector('.test-counter');

        // Countdown ticker — updates the aria-live region each second
        const downloadTimer = setInterval(() => {
            counter.classList.add('h2', 'd-flex', 'justify-content-center', 'align-items-center');
            if (timeleft <= 0) { clearInterval(downloadTimer); timeleft = 4; }
            counter.textContent = timeleft;
            timeleft -= 1;
        }, 1000);

        // Show overlay after 5 s delay; auto-remove container after 8 s total
        const loadingDelay = new Nimbus.Loading(delayContainer, { text: 'Loading' });
        setTimeout(() => { loadingDelay.show(); }, 5000);
        setTimeout(() => { delayContainer?.remove(); }, 8000);

    } else {
        document.querySelector('#loading-test-6')?.remove();
        document.querySelector('.test-counter').textContent = '';
        timeleft = 4;
    }
});

    Full screen

    Use fullpage: true to cover the full viewport during longer operations such as initial page loads, file uploads, or multi-step form submissions. Set document.body.style.overflow = 'hidden' to lock page scroll while the overlay is active. The overlay is removed when loading completes. Click the button below for a 5-second demo.

    HTML
    <div id="test-full">
    <button class="btn btn-primary" id="btn-full-screen">Full screen</button>
</div>
    JAVASCRIPT
    document.querySelector('#btn-full-screen').addEventListener('click', () => {
    // fullpage: true adds .loading-fullpage (position: fixed, z-index: 9999)
    const loadingFull = new Nimbus.Loading(document.body, {
        fullpage: true,
        text:     'Loading…'
    });
    loadingFull.show();
    document.body.style.overflow = 'hidden'; // lock page scroll

    // Auto-dismiss after 5 s — replace with your async operation callback
    setTimeout(() => {
        loadingFull.hide();
        document.body.style.overflow = '';
    }, 5000);
});

    Product Loading curtains

    Product loading curtains are full-viewport branded overlays that appear before the application shell has finished rendering. Unlike the generic Nimbus.Loading overlay, each curtain uses the product's own SVG logo and color palette to deliver a cohesive first impression. The curtain sits at z-index: 9999 with position: fixed and is dismissed — with a brief fade — once the browser fires the window load event.

    Skeleton loading

    A skeleton stands in for content that is on its way, holding the shape the real thing will take. It is not a spinner: a spinner says “something is happening”, a skeleton says “a list of rows is happening, here is how many and how wide”. Reach for a skeleton wherever the shape is known in advance — lists, cards, tables, detail panels — and a spinner only where it is not.

    Never leave stale content behind a spinner. A queue showing yesterday’s rows while it fetches today’s is worse than one that says it is loading — the operator cannot tell which they are looking at, and the stale rows are indistinguishable from fresh ones until the swap happens under them.
    Primitives
    Media — circle beside a stack of lines
    List — rows, divided the way a real list is

    HTML

    
<!-- The CONTAINER carries the message; the skeleton is decoration -->
<div class="cf-list" aria-busy="true">
  <div class="skeleton-list" aria-hidden="true">

    <div class="skeleton-row">
      <div class="skeleton-group">
        <div class="skeleton skeleton-text skeleton-w-50"></div>
        <div class="skeleton skeleton-text skeleton-w-75"></div>
      </div>
      <div class="skeleton skeleton-rect skeleton-action"
           style="width: 90px; height: 38px"></div>
    </div>

  </div>
</div>

<!-- Media: circle beside lines -->
<div class="skeleton-media" aria-hidden="true">
  <div class="skeleton skeleton-circle" style="width: 40px"></div>
  <div class="skeleton-group">
    <div class="skeleton skeleton-text skeleton-w-33"></div>
    <div class="skeleton skeleton-text skeleton-w-66"></div>
  </div>
</div>
    Match the shape, and vary the widths

    A skeleton is only worth more than a spinner if it is the shape of what is coming. Give it the same row count as a full page, the same trailing action, the same column structure — if the real list has ten rows and a button on each, so should the placeholder, or the layout jumps when the content lands.

    Vary the line widths with .skeleton-w-25 … .skeleton-w-100. Text does not come in one length, and without them every line runs full width and the block reads as a solid slab rather than as writing.

    Accessibility

    The skeleton is decoration; the container carries the message. Put aria-busy="true" on the container and aria-hidden="true" on the skeleton itself, so assistive tech is told “busy” once instead of reading out a dozen empty blocks. Remove aria-busy when the content lands.

    Reduced motion: the skeleton stops, the spinners slow down. A spinner has to keep turning to mean anything, so at prefers-reduced-motion: reduce it is slowed. A skeleton’s shimmer carries nothing the static block does not, so it is switched off outright and the placeholder rests at its base colour.
    Theming

    Built entirely from existing primitives — no one-off colours. Light uses --cnds-surface-light-200/100, dark uses --cnds-secondary-gray-800 and --cnds-primary-gray-800. All four are raw values that neither theme overrides, so what is written is what renders.

    The sweep travels toward the page ground, in both themes. That is what makes them read alike, and it is not a mirror of the lightness. In light the base sits 7 L* below white and the sweep lifts it back toward white; in dark the base sits 13.3 L* above #252525 and the sweep drops it back down. Either way the brightest moment of the shimmer is the least contrasty one, and each sweep lands halfway back to its own ground — it is the proportion that carries across, not the absolute distance. Mirroring the lightness instead — a lighter highlight in dark — inverts it: the peak becomes the most contrasty moment and the bar flashes.

    Do not re-point these at --cnds-gray-* — dark.css inverts those (gray-200 becomes #787878 there), so building on them silently flips the ramp. That is what previously put the dark skeleton 5.1× too prominent with a sweep 9.6× too wide: a near-white bar strobing on #252525. Measure in CIELAB L* rather than luminance — the same luminance delta is a whisper near white and a shout near black.

    CSS custom properties
    Variable Default Description
    --cnds-skeleton-bg surface-light-200 / secondary-gray-800 Base colour of the placeholder block.
    --cnds-skeleton-highlight surface-light-100 / primary-gray-800 Colour of the sweep that travels across it.
    --cnds-skeleton-speed 1.5s One pass of the sweep. Slower reads as calmer; faster reads as an error state.
    --cnds-skeleton-radius var(--cnds-border-radius) Corner radius on blocks and text lines.
    --cnds-skeleton-text-height 1em Height of one .skeleton-text line. Relative, so it tracks the surrounding font size.
    --cnds-skeleton-gap 8px Space between lines in a group, and the base for the wider gaps in .skeleton-media and .skeleton-row.
    Classes
    Class Description
    .skeleton The shimmer itself. Required on every placeholder block; the classes below give it a shape.
    .skeleton-text One line of text, 1em tall. A run of them ends short, the way real text does.
    .skeleton-circle Avatar or icon. Square by default (aspect-ratio: 1), so setting a width is enough.
    .skeleton-rect Block — a button, thumbnail or chart area.
    .skeleton-w-25 … -100 Line width: 25 / 33 / 50 / 66 / 75 / 100%.
    .skeleton-group Vertical stack of lines — a paragraph, a field group, a table cell.
    .skeleton-media Leading circle beside a stack of lines — an avatar row, a person card.
    .skeleton-row One list row: a body that grows and an optional trailing action that does not. Deliberately not a fixed column layout — add columns inside the body when the list has them. Every .skeleton-group in a row grows equally; to pin one to a fixed width, override with at least the specificity of .skeleton-row > .skeleton-group (0,2,0).
    .skeleton-action Trailing block inside a row; does not shrink.
    .skeleton-list A run of rows with a divider between them, so the placeholder reads as separate records rather than one striped panel.

    API Documentation

    Introduction

    Nimbus.Loading is a vanilla-JavaScript component that wraps a container element with a configurable backdrop and spinner overlay. It can be activated declaratively (via data-cnds-init="loading" + data-cnds-loading on the container) or programmatically (via new Nimbus.Loading(element, options).show()). The component automatically sets position: relative on the container, appends a centered .loading-overlay inside it, locks scroll when in full-screen mode, and exposes static methods to retrieve or destroy instances. No jQuery or third-party dependencies are required.

    Usage

    Via data attributes

    Add data-cnds-init="loading" and data-cnds-loading directly to the container element. Use additional data-cnds-* attributes to pass options without writing any JavaScript.

    HTML
    <div id="my-container"
     style="height: 300px; width: 100%"
     data-cnds-init="loading"
     data-cnds-loading
     data-cnds-spinner="border"
     data-cnds-text="Loading"
     data-cnds-color="primary"></div>

    Via JavaScript

    Pass the container element and an options object to the constructor, then call .show(). Store the instance reference to call .hide() or .dispose() later.

    JAVASCRIPT
    const container = document.getElementById('my-container');
const loader    = new Nimbus.Loading(container, { text: 'Loading' });

loader.show();

// When the async operation completes:
loader.hide();

    Options

    Options can be passed via data attributes or the JavaScript constructor. For data attributes, prefix the option name with data-cnds- — e.g. data-cnds-backdrop="false".

    Name Type Default Description
    spinner string "border" Spinner variant. Accepts "border" (rotating ring), "grow" (pulsing dot), or "dots" (three-dot bounce).
    text string "" Optional label rendered beneath the spinner inside the overlay. An empty string hides the text element.
    color string "primary" Bootstrap color name applied as text-{color} to the spinner element. Accepts any Bootstrap contextual color ("primary", "success", "danger", etc.).
    backdrop boolean true Enable (true) or disable (false) the semi-transparent background rendered inside the .loading-overlay.
    fullpage boolean false When true, adds .loading-fullpage to the overlay so it covers the entire viewport (position: fixed). Lock page scroll separately via document.body.style.overflow = 'hidden' while the overlay is visible.

    Methods

    Instance methods

    Name Description Example
    show() Appends the overlay to the container and transitions it visible. Fires show.cnds.loading before showing; call event.preventDefault() to cancel. No-op if the overlay is already shown. loader.show()
    hide() Removes the show class and detaches the overlay from the DOM after a 200 ms CSS transition. Fires hide.cnds.loading before hiding; call event.preventDefault() to cancel. No-op if the overlay is not shown. loader.hide()
    toggle() Calls show() if the overlay is currently hidden, or hide() if it is currently visible. loader.toggle()
    dispose() Hides the overlay, nulls the internal reference, and removes the instance from the component data store. Call when the host element is removed from the DOM to prevent memory leaks. loader.dispose()

    Static methods

    Name Description Example
    getInstance(el) Returns the Nimbus.Loading instance associated with the given element, or null if none exists. Nimbus.Loading.getInstance(el)
    getOrCreateInstance(el, config) Returns the existing instance for the element, or creates and returns a new one (using config) if the element has not been initialized. Nimbus.Loading.getOrCreateInstance(el)
    show(el, config) Convenience wrapper. Calls getOrCreateInstance(el, config) and immediately invokes .show(). Returns the instance. Nimbus.Loading.show(el, { text: 'Loading' })
    hide(el) Convenience wrapper. Retrieves the existing instance for el and calls .hide(). No-op if no instance exists. Nimbus.Loading.hide(el)
    JAVASCRIPT
    const el = document.getElementById('my-loader');

// Instance usage
const loader = new Nimbus.Loading(el, { text: 'Saving…' });
loader.show();
loader.hide();    // hides after async work completes
loader.toggle();  // or toggle visibility
loader.dispose(); // clean up when host element is removed

// Static convenience
Nimbus.Loading.show(el, { spinner: 'grow', text: 'Loading' });
Nimbus.Loading.hide(el);

// Retrieve an existing instance
const existing = Nimbus.Loading.getInstance(el);
if (existing) existing.dispose();

    Events

    Both events are dispatched on the container element. Call event.preventDefault() inside the handler to cancel the corresponding action.

    Event Trigger Cancelable
    show.cnds.loading Fired on the container immediately before the overlay is appended and made visible. Yes
    hide.cnds.loading Fired on the container immediately before the overlay begins its hide transition. Yes
    JAVASCRIPT
    const el = document.getElementById('my-loader');

el.addEventListener('show.cnds.loading', (event) => {
    // Cancel the show if a condition is not met
    if (!isReady) event.preventDefault();
});

el.addEventListener('hide.cnds.loading', () => {
    console.log('Loading overlay hidden');
});
