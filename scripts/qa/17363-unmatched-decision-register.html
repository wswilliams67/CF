U-1 Blocking whole section

How does anyone reach unmatched source records?

Nothing in the file links to this surface. It was built as a top-level destination with no back control, and that was an assumption rather than a decision.

Three candidates, from the docs. a Legacy Data Import completion — EXPERIENCE.md already names this "the entry point" for remediation, and it is the recommendation. b The crosswalk, which keeps unmatched records visible as (unmatched) rows. c A nav entry under Administration › Identity — argued against, because the nav is nine flat entries and this cohort may be empty for another tenant.

Answer it with #17384, not after it. The crosswalk has no route in either, and option b on its register proposes reaching the crosswalk through this screen. Whichever way it goes, the page title gains a back control naming its origin — ‹ Legacy data import or ‹ Crosswalk — and this stops being top-level.

U-2 Drawn · needs a number Small cohort

Below what size do the shares stop being shown?

The Outlook and Cohort profile cards are built on percentages. Below some cohort size those stop being measurements: a share of twelve records moves in steps of 8.3, so 41.7% reads as precision when it is one record either way.

Drawn at twelve records. The small-cohort screen suppresses every share to an em dash and keeps the counts, which stay exact and actionable at that size. The note above the cards carries the reason, so the dashes do not read as missing data.

What is needed is the cut-off itself — the point where a percentage stops being a measurement. It cannot be inferred from the design.

U-3 High · PM and DM Export · Export in progress · Export ready

Do unmatched exports need a log of their own?

EXPORT on the Overview and EXPORT SEGMENT on Browse both produce a file, and the progress dialog says it is ready to download. The crosswalk's equivalent dialog instead says the job appears under Exports — because the crosswalk has an Exports list. This feature does not.

If these runs have to be auditable — who exported the cohort, when, and with which filter — they belong in the crosswalk's existing Exports list rather than a second list built here. That makes this a routing decision rather than a new screen, and it is the same shape as C-9 on the crosswalk register, which added the export detail panel for exactly that reason.

U-4 Drawn · confirm or drop Re-measure confirm

Should Re-measure be confirmed before it runs?

It is drawn behind a confirmation. Re-measure is the only action on the Overview that changes system state, and it recalculates every count on the screen across 58,287 source records. The dialog says what moves and what does not, because the word re-measure does not make that obvious on its own.

Drop it if the measurement is cheap. If a re-measure is seconds rather than minutes, the dialog is friction on a safe, repeatable action and Re-measure should fire straight into the progress state. That depends on U-6, which is why the two travel together.

U-5 High Overview

Is the measurement scheduled, or only run on demand?

The Overview now carries a last-measured stamp reading 08-05-2026 — a week before the screen's own date — beside a manual RE-MEASURE control. That combination only makes sense if measurement is on demand.

If it runs on a schedule, the stamp is still right but the button changes meaning: it becomes "run it early", not "run it at all", and the copy on both the button and the confirmation needs to say so.

U-6 Open Re-measure in progress

How long does a re-measure take, and can it be interrupted?

The progress dialog is drawn with CANCEL and RUN IN BACKGROUND, and deliberately without the PAUSE that the export dialog it was built from carries — an export writes a file that can be resumed part-written, and half a measurement is not a thing to return to.

Two things follow from the real duration. It settles U-4, and it decides whether CANCEL can actually stop work already in flight or is only a way to close the dialog.

U-7 Drawn every action-bar screen

The last-measured stamp — the stated reason Re-measure exists

Every count on the Overview comes from a measurement run, not a live query, so the screen has to say when it ran. Without it there is no telling a stale 25,444 from a current one, and the control beside it means nothing.

It carries the delta against the previous run — up 312 — because the direction is the finding. A cohort growing after an ingestion is a different situation from one shrinking, and the figure alone says neither.

U-8 Drawn Zero unmatched

What the Overview shows when nothing is unmatched

The Outlook and Cohort profile cards are hidden rather than filled with zeros — they profile a population, and with none they state nothing while implying there is something to read.

EXPORT and BROWSE are removed rather than disabled: there is nothing to browse and an empty file is not a useful artefact. RE-MEASURE stays and is the point of the screen — a zero is a claim someone will ask you to evidence later, and the stamp is what evidences it.

U-9 Drawn Re-measure confirm → in progress → Re-measured · Export → in progress → ready

Both flows now have confirmation and end states

Re-measure runs confirm → in progress → re-measured, and Export runs modal → in progress → ready. Each end state carries both toasts, drawn together for developer reference — they are alternatives and never appear at once.

The re-measured screen is the after state, not a copy of the Overview: it shows 24,912 against the 25,444 every earlier screen carries, every share still resolves, and the two partition segments still sum to the cohort. The toast confirms the change; the screen is the change.
